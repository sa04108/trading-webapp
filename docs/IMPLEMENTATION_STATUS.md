## 알려진 제약

- 키움 REST 어댑터는 사용하지 않으며 KRX 일별매매와 DART가 데이터 경로다 (D-041)
- 토스증권 동기화 파이프라인 구현·와이어링 완료 (D-018·D-020·D-021) — 웹 데이터셋 페이지에서 생성·동기화·심볼 편집·삭제 가능. TOSS_CLIENT_ID/SECRET 설정과 허용 IP 등록만 남음. 1h 봉 미제공(1분봉 집계로 생성), 증분 자동 스케줄러는 미구현(수동 sync 트리거)
- KR 공휴일 캘린더 미반영 — coverage 가 공휴일을 누락으로 표시할 수 있음, UI 에 명시 (D-006)
- 개발 머신 Node 22 / 운영 Node 24 (D-001), TypeScript 5.9 고정 (D-007), better-sqlite3 v12 (D-008)
- 손절·익절은 **종가**로만 판정한다 — 장중에 손절선을 뚫었다가 종가가 회복한 봉은 청산되지 않아 실제 스톱 주문보다 낙관적이다. `execution.fillTiming` 이 `NEXT_BAR_OPEN` 고정이라 장중 체결을 표현할 수 없다. 파라미터 설명에 고지 (`docs/reviews/BACKTEST_BIAS_REVIEW.md` B-008, D-028)
- 과거 `hourly-breakout` 실행은 전략 이름·파라미터 라벨 없이 원본 id/키로 표시되고 「재설정 및 복제」 시 전략을 다시 골라야 한다 — `range-breakout` 으로 대체하며 별칭을 두지 않았다 (D-028)
- **종목이 1급 객체다 (D-034)** — 봉·재무·수집 상태가 종목에 매달리고 데이터셋은 참조만 갖는다. 데이터 탭이 데이터셋/종목으로 나뉜다. 데이터셋 카드의 「종목 편집」이 추가·제거를 한 번의 PATCH 로 적용한다. 소비 봉 주기를 생략한 옛 잡은 `defaultTimeframe` 이 없어져 화면이 「기록 없음」으로 표시한다 — 없는 근거로 추측하지 않는다
- **종목 목록이 200종목에서 동작한다 (D-035)** — 이름·코드 한 입력으로 검색하고, 쉼표·줄바꿈으로 구분한 코드를 한 번에 등록하며(`POST /symbols` 가 `{codes: []}` 를 받아 `{added, skipped}` 로 답한다 — 부분 성공을 인정하고 하나도 못 넣으면 409), 페이지당 표시 수를 조절한다. 선택은 페이지·검색과 무관하게 전체 목록 기준으로 유지된다. 데이터셋 카드는 종목 배지를 20개까지 나열하고 나머지를 「외 N개」로 접는다. 검색은 **클라이언트 필터**이고 정렬은 가나다순 고정이다 — 서버 검색·정렬 옵션·초성 검색은 아직 없다
- **데이터셋 편집 화면이 종목 목록과 같은 구성을 공유한다 (D-036)** — 「종목 편집」·「데이터셋 만들기」가 종목 탭과 같은 행·검색·페이징(기본 10개)을 쓰고 왼쪽 체크박스와 「전체 선택」·「페이지내 전체 선택」(범위가 다르다)이 더해진다. 이 화면은 **포함 여부만** 정한다 — 동기화·수집 봉·재무 수집 컨트롤은 없고 수집은 종목 탭 소관이다. 1,000종목 실측으로 다이얼로그 열기가 1,443ms → 160ms(long task 0)로 줄었다
- **1,000종목 서버 비용을 종목 수에서 떼어냈다 (D-037)** — `FactRepository.symbolsWithFacts()` 가 재무 보유를 디렉터리 한 번으로 읽어 `GET /symbols` 가 40ms → 5.7ms (종목마다 `fs.existsSync` 하던 것을 없앴다. 단건 `hasFacts` 는 제출 검증용으로 남고, 두 경로가 같은 답을 내는지 테스트가 확인한다). `SymbolService.getSymbol` 이 목록 전체를 만들지 않아 999종목 일괄 등록이 1.0초 → 0.48초
- **백테스트 설명은 데이터셋을 가리키고 거래 내역은 서버가 정렬한다 (D-039)** — 목록 카드·상세 화면의 설명 줄이 종목을 나열하지 않고 「데이터셋 이름 · N종목」을 적는다(종목 수는 실행된 요청 기준, 이름은 현재 카탈로그 조회 — 데이터셋을 지우면 id 를 적는다). 거래 내역의 수량·진입·청산·순손익·수익률·보유 열이 머리글 버튼으로 두 방향 정렬되고, 정렬은 서버가 한다(서버 페이징이라 화면 정렬은 한 페이지만 뒤집는다). 정렬 상태는 URL 에 남지 않아 새로고침하면 기본(청산 오름차순)으로 돌아간다. 미청산 행은 첫 페이지 위에 고정되고 같은 축으로 정렬되지만 청산 거래와 한 줄로 섞이지는 않는다
- 전략 카드는 「재무 필요」·「봉 데이터만」(D-032)을 표시한다. 재무 전략은 최종 유니버스 전 종목의 전략 lookback 필수 연도 coverage가 완전해야 실행되며(D-069), 완료 뒤 coverage drift도 preview·복제·난수 승격·worker에서 다시 막는다. 종목·연도별 versioned fact count/content-hash manifest가 구버전 coverage와 사후 행 추가·삭제·변경을 재수집 대상으로 되돌리고, `corp_code`·파서·금액·분기 차분 blocking gap은 실행을 차단한다. coverage 기록은 있지만 실제 공시가 없는 일부 종목은 랭킹에서 제외하고 이름을 경고한다. preview의 재무 보유 표시는 고정 schedule 편입 구간·최초 상장폐지 이전의 종목별 마지막 실행 봉까지 공개된 실제 비자본변동 fact만 센다. 정상 무공시와 전략별 필수 계정 누락을 더 엄격히 구분하는 required-fields readiness 정책은 아직 없다
- **상장폐지 청산과 거래불가일을 반영한다 (D-046·D-070·D-071)** — 폐지 종목은 마지막 거래 가능 봉 종가로 전량 청산되고 거래 내역에 사유 `DELISTED` 가 남는다(수수료·매도세·슬리피지는 정상 매도와 같다). 거래정지·무거래 종목은 유니버스 후보와 매수에서 빠진다. 시장 거래일에 확정 유니버스 종목 봉이 없고 이 두 근거도 없으면 전략 후보에서 조용히 빼거나 마지막 가격으로 정상 완료하지 않고 종목·날짜를 밝히며 실행을 실패시킨다. 선택 종목 봉이 모두 일찍 끊겨도 KRX 거래일력으로 발견하며, 편출 뒤 남은 보유분도 검사한다. KRX 는 거래정지와 무거래를 구분해 주지 않아 하나로 다룬다 — 사유가 필요하면 KIND 수집이 따로 있어야 한다. 거래불가일은 `krx_non_trading_days` 에 쌓이고 과거분은 `pnpm cli krx:backfill-non-trading --from <날짜> --to <날짜>` 로 채운다. 백필 전 구간은 결과 경고가 "거래불가일 정보가 없습니다" 로 밝힌다. **배당·유상증자 권리락은 여전히 미보정이다.** "생존 편향" 이라는 단일 라벨은 더 이상 쓰지 않는다 — 부분 보정이라 예/아니오로 답할 수 없다
- **액면분할은 분할 이력이 수집된 데이터셋에서 보정된다 (D-043)** — 엔진이 보유 포지션의 수량·평균단가와 대기 주문 수량을 조정한다. `ema-trend-switch`·`rsi-reversion`·`range-breakout` 이 봉 사이에 들고 다니는 지표 누적(EMA·ATR·RSI·전고점 창·상관 워밍업)과 스톱 레벨도 같은 비율로 내려간다. 횡단면 모멘텀은 여기에 더해 신호 계산에서 보정 종가를 쓴다. 체결가는 항상 실제 거래 가격이다. `value-quality-rank` 는 가격 상태를 들고 다니지 않아 조정할 것이 없다. 유니버스 종목의 자본변동은 제출 전 백테스트 준비(preparation)가 자동으로 동기화한다 — 같은 조건의 준비가 아직 끝나지 않은 제출은 409(PREPARATION_REQUIRED)로 준비를 먼저 완료하라고 안내한다. 준비를 마쳤는데 DART 가 답하지 못한 gap 종목은 막지 않고 경고만 한다. 거시 지표 수집(`FactScope.MACRO`)·시점별 지수 구성·업종 분류·US 재무제표(SEC EDGAR)는 이번 범위가 아니다. 재무·자본변동 수집은 CLI·수동 동기화 버튼이 아니라 백테스트 준비(preparation)가 요청 기간과 최소 warm-up 만큼만 자동으로 한다(D-049) — 과거 연도 정정공시를 다시 받는 별도 경로는 없다. 수집은 연결(CFS) 고정이다 — 별도(OFS)를 자동으로 수집하는 경로는 없다. **재무 수집은 국내(KR) 종목 전용이다** — DART 는 국내 공시 기관이다

- **요청 시작부 가격 공백도 차단한다 (D-072)** — worker는 기간에서 첫 번째로 발견한 봉이 아니라 요청 시작일을 거래 경계로 쓴다. 선정 종목 봉이 시작부터 함께 누락돼도 KRX 거래일력 기준 검사가 결측 첫날에서 실행을 중단한다. 시작일이 휴일이면 시장 거래일력에 없어 전략 호출을 만들지 않는다
- **legacy 주말을 거래일로 사용하지 않는다 (D-073)** — 종목 마스터 이행 중 이벤트 경계로 유입된 토·일요일은 리밸런스 적용일·상장폐지 관측 경계·worker warm-up N일에서 제외한다. 기간 전 warm-up은 필요한 **실제 KRX 거래일** 수만큼 로드된다
- **단주 정산 뒤 비용 원가를 중복 귀속하지 않는다 (D-074)** — 역분할·비정수 비율에서 현금으로 빠진 단주 몫의 매수수수료를 남은 포지션 원가에서도 제거해 미청산·후속 매도 손익의 과소계상을 막는다
- **돌파 전략의 유니버스 밖 거부 주문이 다음 진입을 막지 않는다 (D-075)** — `range-breakout`은 실제 매수 가능 종목만 진입 상태를 만들고, 편입·거래 재개 뒤 첫 유효 돌파를 한 봉 늦게 잡던 오류를 제거했다
- **밸류 전략은 분할에 흔들리지 않는 KRX 시가총액을 쓴다 (D-076)** — `value-quality-rank`의 기업가치는 리밸런스 시점에 고정된 KRX 시가총액으로 계산한다. 분할 후 종가와 아직 갱신되지 않은 공시 주식수를 곱해 종목을 가짜 저평가 상태로 만들지 않으며, 일정의 시가총액 결측·오류는 전체 실행을 차단한다
- **저PER·고ROE 전략은 KRX 시가총액 결측을 부분 제외하지 않는다 (D-077)** — 거래 가능한 활성 후보의 리밸런스 시점 시가총액이 빠졌거나 유효하지 않으면 차순위를 자동 편입하지 않고 실행 전체를 차단한다
