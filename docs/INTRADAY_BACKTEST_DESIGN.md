# 지정 종목 분봉 백테스트와 데이터 화면 설계

작성일: 2026-11-14

상태: 설계안 — 제품 동작과 스키마에는 아직 반영하지 않음

기존 일봉 백테스트는 현재 목적과 동작을 유지한다. 분봉 백테스트는 사용자가 미리 지정한 종목을 대상으로 진입·청산 시점과 수량을 검증하는 별도 흐름으로 제공한다. 데이터 화면에는 종목별 가격 차트를 중심으로 탐색하는 분봉 데이터 탭을 추가한다.

## 1. 합의된 범위와 설계 제안

### 합의된 방향

- 일봉 전략과 분봉 전략을 분리한다. 기존 일봉 전략을 분봉으로 자동 변환하지 않는다.
- 분봉 매매의 대상 종목은 사용자가 사전에 정한다. 분봉 전략은 종목을 발굴하거나 순위를 매겨 교체하지 않는다.
- 분봉 전략은 기술적 가격·거래량 정보를 사용한다. 재무 기반 전략과 PER·ROE 등의 종목 선정 단계는 포함하지 않는다.
- 백테스트 화면에서 일봉과 분봉 전략의 진입 경로를 구분한다.
- 데이터 화면에 분봉 전용 탭을 둔다. 날짜별 수집 현황보다 종목 검색·선택과 해당 종목의 가격 그래프를 중심에 둔다.
- 별도 진행 중인 실매매 시스템의 주문 실행 기능은 이 설계의 구현 범위에 포함하지 않는다.

### 초기 구현 제안

아래는 합의된 방향을 구체화한 제안이며, 세부 지원 범위는 구현 착수 때 확정한다.

| 항목 | 초기 제안 |
| --- | --- |
| 대상 시장 | 국내 주식, 공급자와 거래시장·세션을 명시한 한 가지 시세 범위부터 시작 |
| 지정 종목 | 첫 단계는 단일 종목. 여러 종목과 공유 자금 운용은 후속 확장 |
| 기준 데이터 | 확정된 1분봉을 보관하고 5분·15분봉을 같은 규칙으로 집계 |
| 초기 전략 | 분봉 전용 돌파 또는 EMA 전략 한 개로 전체 흐름 검증 후 확대 |
| 매매 방향 | 현금 범위 내 매수와 보유 수량 내 매도 |
| 청산 | 전략 청산과 공통 종료 규칙을 명시적으로 설정 |
| 초기 체결 | 봉 확정 후 신호, 다음 거래 가능 시점의 체결을 비용·지연과 함께 모델링 |

단타와 당일 청산은 같은 의미로 고정하지 않는다. 익일 보유 허용 여부는 실행 설정으로 명시하고, 당일 청산 모드에서는 신규 진입 마감·청산 시각·청산 실패 처리를 함께 정의한다.

## 2. 사용자 흐름

### 백테스트

백테스트 목록과 신규 실행의 시작점에서 `일봉`과 `분봉`을 선택한다. 기존 실행은 일봉으로 식별하며, 과거 파라미터·결과·복제·기간 검증 동작을 유지한다.

분봉 신규 실행의 순서는 다음과 같다.

1. 종목 검색 후 대상을 지정한다.
2. 거래시장·세션, 테스트 기간, 신호 봉 주기를 선택한다.
3. 보유 데이터 범위와 누락 구간, 추가 수집 필요 여부를 확인한다.
4. 분봉 전략과 진입·청산 파라미터를 선택한다.
5. 초기 자금, 주문 수량 규칙, 비용, 보유·청산 정책을 설정한다.
6. 준비 결과를 확인하고 실행한다.

분봉 흐름에는 재무 수집과 유니버스 선정 단계를 노출하지 않는다. 준비 중 지정 종목의 데이터가 부족해도 다른 종목으로 자동 대체하지 않는다. 수집 가능하면 보완하고, 실행 불가능하면 해당 범위와 사유를 보여준다.

결과는 자산 곡선·거래 내역과 함께 해당 종목의 가격 차트에 신호 시점과 실제 모의 체결 시점을 구분해 표시한다. 순손익, 거래당 순손익, 거래비용, 거래 횟수, 보유시간, 최대낙폭, 미체결·잔여 포지션을 확인할 수 있어야 한다.

### 분봉 데이터 탭

기존 데이터 화면에 `분봉 데이터` 탭을 추가한다. 날짜는 종목 선택 이후 차트 범위를 좁히는 필터로 사용한다.

| 영역 | 표시 및 동작 |
| --- | --- |
| 종목 탐색 | 종목명·코드 검색, 수집 중이거나 보관 이력이 있는 종목 목록 |
| 종목 요약 | 종목 식별 정보, 거래시장·세션, 최초·최종 보유 시각, 최근 갱신 시각 |
| 가격 차트 | 기간·봉 주기 선택, OHLC 캔들, 거래량, 확대·이동 |
| 데이터 상태 | 요청 구간의 수집 완료·결측·무거래·수집 중·실패 상태 |
| 작업 | 선택 종목·기간 수집 또는 보완, 해당 조건으로 분봉 백테스트 시작 |

오래된 마지막 봉을 현재 시세처럼 표시하지 않는다. 실시간 미확정 봉을 표시한다면 확정 봉과 구분하고 백테스트 입력에서 제외한다. 보유 데이터가 없으면 빈 차트와 수집 안내를 표시한다. 부분 실패나 누락 구간은 가격선을 연결해 숨기지 않는다.

긴 기간을 탐색할 때는 화면 범위에 필요한 데이터만 조회한다. 시각화용 축약 데이터와 전략 계산용 원본 봉은 구분하며, 표시된 집계 주기를 사용자에게 알린다.

## 3. 전략과 실행 계약

분봉 전략의 입력은 확정된 봉 이력, 현재 포지션·가용 자금, 사용자 파라미터와 거래 세션 상태다. 출력은 지정 종목에 대한 주문 의도다. 주문 체결과 자금·수량 제한은 실행 계층이 최종 검증한다.

| 책임 | 계약 |
| --- | --- |
| 종목 지정 | 실행 요청에 대상 식별자를 고정하고 결과에 보존 |
| 진입 신호 | 봉 확정 이후 판단. 조건에 쓰는 기간은 봉 수인지 실제 시간인지 명시 |
| 수량 | 고정 금액·자금 비율 등의 명시된 방식 사용. 현금·호가·주문 단위 제한 적용 |
| 청산 | 손절·익절·신호 반전·시간 만료 중 지원 조건과 충돌 우선순위 고정 |
| 재진입 | 중복 신호, 대기 주문, 청산 직후 재진입 여부를 명시 |
| 워밍업 | 필요한 이전 봉을 준비하되 평가 구간 전 주문은 실행하지 않음 |
| 재무 제외 | 분봉 전략과 준비 경로에서 재무 조회와 재무 선정 규칙을 허용하지 않음 |

가격과 보유 수량의 정합성을 위한 분할·병합, 거래정지·상장폐지 정보는 재무 전략 제외와 별개로 유지한다. 수정주가와 원주가의 혼용을 막고, 기업행동 적용 시점과 전략 내부 가격 상태의 보정 규칙을 고정한다.

후속 다종목 지원은 공통 자금과 종목별 독립 자금 중 하나를 명시해야 한다. 공통 자금을 쓰면 동시 주문의 자금 배분·순서와 전체 투자 한도를 재현 가능하게 정의한다. 단일 종목 실행 결과를 단순 합산해 공유 자금 포트폴리오 성과로 표시하지 않는다.

## 4. 분봉 데이터 계약

### 보관과 집계

분봉은 일봉과 논리적으로 분리해 영속 보관한다. 일봉에서 장중 경로를 복원할 수 없으므로 일봉을 분봉으로 변환하는 경로는 제공하지 않는다. 기존 일봉 저장소와 데이터의 의미는 유지한다.

초기에는 별도 테이블 또는 파일로 시작할 수 있다. 물리 저장 형식은 대상 종목 수·보관 기간·스냅샷 전송량을 측정한 뒤 결정한다. 대규모 이력을 매번 전체 계산 DB와 함께 복제하는 구조는 피할 수 있도록 데이터 조회 계약과 배포 단위를 분리한다.

개념상 다음 정보를 보존한다. 필드명과 실제 SQL 스키마는 후속 구현에서 정한다.

| 구분 | 정보 |
| --- | --- |
| 식별 | 공급자, 종목의 유효기간을 구분할 식별자, 거래시장 또는 통합 시세 범위, 세션, 봉 주기, 시작 시각 |
| 가격 | 시가·고가·저가·종가, 구간 거래량, 제공되는 경우 거래대금 |
| 시각 | 봉 시작·종료 시각, 사용 가능 시각의 규칙, 수신·수집 시각 |
| 품질 | 확정 여부, 원천 또는 집계 구분, 수정주가 정책, 데이터 revision |
| 수집 범위 | 완료 범위, 누락·무거래·거래정지 구분, 재시도 상태 |

종목 코드가 같아도 과거 발행사가 다른 경우를 구분한다. KOSPI·KOSDAQ의 상장시장 구분과 KRX·NXT 등의 거래시장 구분은 별개의 축으로 다룬다. 공급자별 데이터는 임의로 덮어쓰거나 혼합하지 않는다.

1분봉에서 상위 봉을 만들 때는 거래소 시간대와 세션 시작을 기준으로 경계를 정한다. 시가는 첫 관측값, 고가는 최댓값, 저가는 최솟값, 종가는 마지막 관측값, 거래량·거래대금은 구간 합계다. 누적 거래량 응답은 구간 거래량으로 정규화한 뒤 합산한다. 세션 끝의 짧은 봉, 무거래 구간, 단일가 매매의 포함 규칙을 집계 버전에 고정한다. 세션 사이의 공백을 넘어 봉을 합치지 않는다.

### 시점과 재현성

절대 시각은 UTC로 저장하고 화면과 거래일 판정에는 명시된 거래소 시간대를 사용한다. 봉의 시작 시각만으로 정보 사용 가능 여부를 판단하지 않는다. 예를 들어 09:00부터 09:05까지의 봉은 종료와 공급 지연 이후에만 전략 입력이 된다.

과거 API 조회에는 당시의 실제 도착 시각이 없을 수 있다. 이때는 정한 지연 가정을 기록하고, 실제 도착 이력을 재현한 것처럼 표시하지 않는다. 실시간 수집의 수신 시각과 과거 보완 수집 시각도 같은 의미로 취급하지 않는다.

중복 수집은 같은 봉을 중복 생성하지 않아야 한다. 정정으로 현재 데이터가 바뀌더라도 완료된 실행이 참조하는 데이터 버전과 집계 규칙은 보존한다. 실행에는 대상·기간·세션·주기·원천 데이터 revision·집계 버전·전략 버전·체결 설정을 고정한다.

공급자의 과거 조회 범위, 호출 제한, 시장별 제공 범위, 저장·이용 조건은 공급자 확정 시 확인한다. 공급자가 조회할 수 없는 과거 구간은 수집 대기로 무한 재시도하지 않고 이용 불가로 구분한다.

## 5. 체결과 평가의 경계

다음 봉 시가 체결은 실제 체결의 보장이 아니라 시뮬레이션 가정이다. 신호 봉의 종가를 확인한 뒤 같은 종가에 주문을 체결시키지 않으며, 계산·전송 지연과 스프레드·수수료·세금·슬리피지를 실행 설정으로 보존한다.

- 체결 봉 전체 거래량을 그 봉 시가 시점에 이미 알았다고 가정해 주문 수량을 결정하지 않는다. 주문 결정 시 사용할 과거 유동성과 사후 체결 평가에 사용할 거래량의 역할을 구분한다.
- 부분체결·미체결·주문 만료를 명시한다. 결측이나 거래정지 뒤의 다음 봉까지 주문이 무기한 살아 있지 않게 한다.
- 초기 손절이 종가 신호 방식이면 그렇게 표시한다. 장중 스톱 주문은 별도의 체결 모형으로 다룬다.
- 한 봉에서 손절가·익절가를 모두 통과했을 때 OHLC만으로 선후를 확정하지 않는다. 지원하려면 더 세밀한 데이터 또는 명시된 보수적 처리 규칙이 필요하다.
- 당일 청산은 실행 가능한 시점에 주문을 발생시킨다. 미체결 포지션을 임의의 종가로 체결 처리하지 않고 청산 실패·잔여 보유를 결과에 남긴다.

Sharpe 등 일간 지표는 거래일 기준 자산으로 계산한다. 분봉 수를 독립된 거래일 수로 간주해 연율화하지 않는다. 봉 단위 최대낙폭과 일말 최대낙폭은 구분하며, 봉 사이 위험은 입력 해상도에 따라 관측하지 못할 수 있다.

고정 종목의 성과는 그 종목을 선택했다는 조건부 결과다. 현재의 성공 종목을 사후 선택한 결과를 전체 종목 선정 능력으로 해석하지 않는다. 평가 구간을 시간순으로 분리하고 비용·지연 민감도와 실시간 모의운용을 통해 실행 가능성을 검증한다.

## 6. 기존 구조와의 연결

| 현재 코드 또는 문서 | 분봉 도입 시 검토할 경계 |
| --- | --- |

일봉·분봉을 분리하는 것은 화면과 전략·입력 계약의 분리를 뜻한다. 모든 계산 코드를 복제한다는 뜻은 아니다. 비용·수량·포지션 계산처럼 의미와 검증이 같은 부분만 공유하고, 분봉 세션과 주문 생명주기는 별도의 실행 정책으로 구성한다.

과거 요청에 모드가 없다면 기존 일봉으로 해석하는 호환 경계를 둔다. 분봉 요청이 일봉 경로에 들어가거나 기존 결과가 분봉으로 재해석되는 것을 차단한다. 실제 모드 구분자 이름, 저장 스키마와 버전 변경은 구현 시 함께 확정한다.

실매매 시스템과는 종목 식별, 거래시장·세션, 봉 확정·지연 규칙, 신호 주기, 주문 수량 단위, 주문 만료, 청산 정책, 전략·데이터 버전을 맞춘다. 백테스트의 모의 체결과 증권사의 주문·체결 이벤트는 별도 어댑터로 유지하며, 신호와 주문 의도의 비교가 가능하도록 식별 정보를 연결한다.

## 7. 구현 순서와 수용 기준

| 순서 | 작업 | 수용 기준 |
| --- | --- | --- |
| 1 | 공급자·시장·세션·초기 종목 수·청산 정책 확정 | 실제 수집 가능 구간과 주문 측 계약을 확인하고 아래 미결정 항목 해소 |
| 2 | 분봉 수집·저장·집계·coverage | 중복 수집 안전, 결측과 무거래 구분, 세션 경계 집계 일치, 정정 버전 재현 |
| 3 | 분봉 데이터 탭 | 종목 검색부터 차트·수집·보완까지 연결, 빈 데이터·누락·실패 표시, 조회 범위 제한 |
| 4 | 분봉 요청·전략·실행 경로 | 고정 종목만 거래, 재무 수집 없음, 확정 전 봉 접근 차단, 수량·비용·만료 검증 |
| 5 | 결과와 실매매 연동 계약 검증 | 신호·체결 시각 구분, 잔여 포지션 표시, 같은 입력의 신호 재현 |
| 6 | 일봉 회귀와 런타임 호환성 확인 | 기존 요청·결과·복제·기간 검증 보존, 호환되지 않는 에이전트 배정 차단 |

구현 검증은 기존 테스트를 우선 재사용한다. 새로운 영구 테스트는 확정 전 봉 유출, 세션 경계 오집계, 중복 수집, 주문 만료 누락 등 기존 테스트가 보호하지 못하는 구체적 실패에 한정한다. 단위 검증 이후 요청→준비→실행→결과의 통합 흐름과 데이터 탭의 사용자 흐름을 검증한다.

최종 변경 범위에 맞춰 `pnpm lint`, `pnpm typecheck`, 관련 단위·통합 테스트를 필수 검사로 정한다. UI 흐름은 관련 E2E, 런타임 배포 계약 변경은 해당 빌드·패키지 검사를 추가한다. 공유 출력 디렉터리를 쓰는 빌드는 직렬 실행한다. 데이터 규모 검증은 먼저 임시 실험으로 수행해 저장량·조회시간·메모리·스냅샷 비용을 측정하며 기본 테스트에 대용량 데이터를 넣지 않는다.

## 8. 구현 전 확정할 사항

- 실제 분봉 공급자와 과거 조회·보관 가능 범위, KRX·NXT·통합 시세 중 초기 지원 범위.
- 단일 종목부터 시작할지, 처음부터 여러 지정 종목을 지원할지. 여러 종목이면 자금 공유 방식.
- 최초 지원 봉 주기와 첫 전략, 주문 수량 방식.
- 당일 청산 강제 여부와 세션 종료·청산 실패 정책.
- 분봉 보관 기간·대상 수·자동 수집 주기 및 측정에 따른 물리 저장·배포 방식.
- 별도 매매 시스템의 봉 확정·주문 만료·전략 호출 계약과 연결 위치.

이 설계의 문서 커밋은 위 기능의 구현·배포나 기존 일봉 동작 변경을 포함하지 않는다.
