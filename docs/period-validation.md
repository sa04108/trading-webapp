# 구간별 독립 검증

백테스트 결과 화면의 **기간 검증**에서 원본 요청을 기반으로 실험을 생성한다. 모든 IS/OOS는 동일 초기자금, 무포지션, 원본 비용 설정과 난수 시드로 새 백테스트를 실행한다. 원본 자산곡선을 잘라 구간의 독립 실행 결과로 사용하지 않는다.

## 지원 방식

- 홀드아웃: OOS 시작일을 지정하고 IS와 OOS를 각각 한 번 실행한다.
- 최적화 홀드아웃: IS의 모든 매개변수 후보를 실행하고 선택한 후보의 OOS와 원본 매개변수의 OOS를 실행한다.
- 워크포워드: 고정 길이 학습 구간을 평가 기간만큼 이동한다. 완전한 OOS가 최소 두 개 필요하다. OOS끼리는 겹치지 않으며 마지막 불완전 구간은 실행 전에 표시하고 제외한다.

숫자 매개변수 최대 두 개, 조합 최대 50개, 총 백테스트 최대 300회, 진행 중 실험 최대 5개를 허용한다. 최적화 실행량은 `구간 수 × (후보 수 + 선택 전략 OOS 1회 + 고정 전략 OOS 1회)`다. 같은 후보가 원본 매개변수와 같더라도 두 용도의 실행과 기록을 구분한다.

## 선택 및 성과 해석

선택 기준은 실험 생성 시 고정한다. 최소 매도 체결 수와 허용 MDD 크기를 만족하는 후보 중 IS Sharpe 또는 CAGR이 가장 높은 후보를 고른다. 매도 체결 수는 기존 엔진 정의대로 부분청산도 포함하므로 독립 거래 표본 수를 뜻하지 않는다. 계산 불가 지표는 선택 대상에서 제외하고 동률은 후보 입력 순서로 결정한다. 모든 IS 후보가 정상 완료되기 전에는 OOS 매개변수를 정하지 않는다.

후보 실행 실패, 중단 또는 조건을 만족하는 후보가 없는 회차를 건너뛰지 않는다. 실험을 실패 처리하고 남은 실행을 중단한다. 실패·취소 실험의 완료된 OOS 통계는 부분 결과로 표시한다.

각 실행은 기간 전 데이터를 지표 준비에만 사용한다. 워커와 같은 거래일 수 기준으로 준비 데이터 부족을 검사한다. 구간 말 보유분은 기존 엔진처럼 마지막 가격으로 평가하며 가상 청산 주문과 청산 비용을 추가하지 않는다. 따라서 결과는 청산 후 현금 수익률이 아니다. 현금·포지션·미체결 주문·전략 상태는 다음 독립 구간으로 승계하지 않는다.

OOS 수익률을 합산하거나 구간별 Sharpe·MDD를 평균해 연속 운용 성과로 제공하지 않는다. 표에는 회차별 IS/OOS 성과, 선택 매개변수, 원본 매개변수의 동일 OOS 성과와 벤치마크를 제공한다. 상세 백테스트 링크에서 자산곡선, 거래와 실행 경고를 확인할 수 있다.

원본 전체 결과를 이미 확인한 상태에서 시작하는 실험이므로, 과거에 사용하지 않은 데이터라는 사실을 보장하지 않는다. OOS를 보며 분할·탐색 범위·전략을 바꾼 결과는 새 실험으로 기록되지만 엄격한 미사용 평가로 해석할 수 없다.

## 실행과 재현성

`backtest_validations`는 원본 요청, 계획, 선택 기준, 실행 버전과 현재 단계를 보관한다. `backtest_validation_trials`는 회차별 IS 후보, 선택 OOS, 고정 전략 OOS를 기존 작업 큐와 연결한다. 서버가 진행하므로 브라우저를 닫아도 실행을 계속한다. 작업 생성과 연결은 같은 SQLite 트랜잭션에서 처리하고 재시작 시 저장된 단계를 복구한다.

한 회차의 IS 후보 준비를 모두 끝낸 뒤 데이터 revision을 고정하고 후보를 비교한다. 후보 선택 후 OOS와 고정 전략의 준비를 끝내고 평가 그룹의 revision을 별도로 고정한다. 다음 회차는 다시 준비한다. 전체 실험이 하나의 물리적인 데이터 스냅샷을 사용하는 구조는 아니며, 각 실행에는 기존 데이터·유니버스 버전 기록이 남는다.

같은 비교 그룹의 실행 중 시장·재무 데이터 revision이 변하거나 전략·엔진·배포 버전이 바뀌면 실험을 중단한다. revision은 저장소 전체 기준이므로 실험에 직접 관련 없는 데이터 변경도 중단을 일으킬 수 있다. 이를 피하려면 대규모 동기화를 마친 뒤 검증 실험을 실행한다.

실험의 준비 참조는 위저드의 사용자별 참조와 분리한다. 취소는 실험 소유 백테스트와 단독 사용 중인 준비 작업에 적용한다. 다른 실험이나 위저드가 사용하는 준비 작업은 유지한다. 검증 결과가 참조하는 백테스트와 원본은 실험을 먼저 삭제해야 삭제할 수 있다. 실험 삭제는 하위 결과도 삭제하며, 그 하위 결과에서 파생한 실험이 있다면 먼저 정리해야 한다.

일반 백테스트 목록과 알림에는 후보 실행을 개별 나열하지 않는다. 원본 결과의 검증 영역에서 조회하며 실험 종료 시 요약 알림을 제공한다. 재시작된 실행 버전이 달라지면 이전 실험을 다른 버전으로 이어 실행하지 않고 실패 처리한다.

## API

| 요청 | 용도 |
| --- | --- |
| `POST /api/v1/backtests/:id/validations/preview` | 전략 스키마와 실행 계획 검증 |
| `POST /api/v1/backtests/:id/validations` | 실험 생성 |
| `GET /api/v1/backtests/:id/validations` | 원본의 실험 목록과 결과 |
| `GET /api/v1/backtest-validations/:id` | 실험 상세 |
| `POST /api/v1/backtest-validations/:id/cancel` | 실험 취소 |
| `DELETE /api/v1/backtest-validations/:id` | 종료된 실험과 하위 결과 삭제 |

모든 경로에 기존 로그인 인증을 적용한다. 분할·후보·선택 기준을 수정하는 API는 없으며 변경하려면 새 실험을 생성한다.
