# 스윙 전략 최소 중복 정리

날짜: 2026-08-13

## 목적

`ema-trend-switch`와 `rsi-reversion`의 동적 상관그룹 수정에 포함된 명백한 중복과
불필요 상태를 정리한다. 이번 작업은 동작 변경이나 대규모 테스트 재편이 아니라,
기존 PR을 읽고 유지하기 쉽게 만드는 최소 리팩터링이다.

## 범위

### 1. 상관그룹 상태와 수명주기만 공용화한다

두 전략에 중복된 다음 책임을 `shared/pair-groups.ts`의 작은 공용 API로 옮긴다.

- 초기 그룹 상태 생성
- 활성 멤버십 심볼 선택
- 종가 기록과 크기 제한
- 멤버십 변경·리밸런스·새 종목 준비 완료 시 그룹 재계산
- 마지막 활성 멤버십의 워밍업 부족 경고 생성
- 자본변동 시 누적 종가 조정

전략별 EMA·RSI 지표 갱신, 청산 조건, 진입 신호와 주문 생성은 각 전략 파일에 그대로
둔다. 공용 부품이 전략별 매매 의미를 알지 않게 한다.

### 2. 중복 상태를 최소화한다

현재 `groupedSymbolsKey`와 `lastActiveSymbols`는 같은 활성 심볼 집합을 문자열과 배열로
중복 저장한다. 공용 상태에는 마지막 그룹 계산 대상과 종료 진단 대상을 함께 표현하는
정렬된 심볼 배열 하나만 둔다. 멤버십 변경 비교는 배열을 직접 비교한다.

`groupReadyCount`는 새 종목이 `correlationBars`를 채운 순간 재계산하기 위해 필요하므로
유지한다. `warmup`의 `null` 상태도 정적 실행에서 메모리를 해제했다는 의미가 있어 유지한다.

### 3. 공개 구조와 행동 테스트는 유지한다

`TradingStrategy`, `StrategyBarContext`, `activeUniverseSymbols`, `completionWarnings` 계약은
바꾸지 않는다. 기존 전략 버전 `1.0.2`도 유지한다. 리팩터링만으로 실행 결과나 재현성 pin을
다시 바꾸지 않는다.

다음 행동 회귀 테스트는 서로 다른 실패 모드를 검증하므로 삭제하지 않는다.

- 짧은 이력·무봉 종목이 전체 준비를 막지 않음
- pair별 시각 정렬과 결정적 그룹 id
- 비활성 미래 종목이 활성 종목 신호를 선점하지 않음
- 멤버십 변경과 동일 멤버십 리밸런스에서 그룹 갱신
- 새 멤버십 미준비 시 이전 그룹 폐기
- 거래정지된 보유 종목도 그룹 선점을 유지
- EMA·RSI 워밍업 부족 경고

테스트 fixture의 전역 공용화나 파일 재배치는 하지 않는다. 테스트끼리 과도하게 결합하는
정리 비용이 현재 중복보다 크기 때문이다.

### 4. 사용되지 않는 함수는 보수적으로 판단한다

`buildCorrelationGroups()`는 운영 코드가 직접 호출하지 않지만 상관 계산과 결정적 union의
독립 단위 테스트 진입점이다. 최소 수정안에서는 삭제하지 않는다. 대신 새 공용 수명주기
API가 해당 계산을 재사용할 수 있는지 확인하고, 그렇지 않더라도 테스트 전용이라는 이유만으로
공개 함수를 제거하지 않는다.

## 구현 원칙

- 먼저 현재 관련 테스트를 기준선으로 실행한다.
- 공용 API 자체의 상태 전이 테스트를 추가한 뒤 EMA·RSI가 이를 사용하도록 바꾼다.
- 전략별 실제 체결 결과가 리팩터링 전과 같은지 기존 테스트로 확인한다.
- 새 추상화가 매개변수 객체 전체나 전략별 상태를 받지 않도록 한다.
- 중복 제거량보다 API 복잡도가 커지는 추상화는 만들지 않는다.

## 완료 조건

- EMA·RSI의 그룹 준비·재계산·경고 구현이 한 곳에만 존재한다.
- 중복 저장하던 활성 멤버십 표현이 하나로 줄어든다.
- 기존 행동 회귀 테스트를 삭제하지 않고 모두 통과한다.
- lint, typecheck, 전체 테스트, 서버·웹 빌드가 통과한다.
- 독립 코드 리뷰에서 Critical/Important 지적이 없다.
- 기존 원격 브랜치와 Draft PR을 갱신한다.
