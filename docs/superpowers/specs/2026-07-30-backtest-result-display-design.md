# 백테스트 결과 표시 개선 설계

날짜: 2026-07-30
상태: 승인됨 (구현 전)

## 배경

백테스트 엔진은 수수료·세금·슬리피지를 체결 시점에 차감하고 합계를
`BacktestMetrics.totalCommission / totalTax / totalSlippage` 로 집계한다
(`src/server/modules/backtest/domain/metrics.ts:203-205`). 값은 웹 타입
(`src/web/features/backtests/types.ts:66-68`)까지 내려오지만 화면에 그리지 않는다.

그 외 사용자가 지적한 표시 문제:

- 백테스트 목록이 전략 구분 없이 평면 나열이고, 전략이 케밥케이스 id
  (`rsi-reversion`)로 표시된다. 전략에는 한국어 이름(`'RSI 되돌림'`)이 있고
  `/strategies` 가 이미 반환한다.
- 백테스트가 어떤 봉 주기(1분봉/1시간봉/일봉)를 소비했는지 목록·상세 어디에도 없다.
- 데이터셋 봉 주기 라벨 `'1시간봉 (1분봉 수집)'` 이 혼란스럽다. 증권사 수집은
  1분봉 또는 일봉뿐이며, `1h` 종류 데이터셋의 실체는 "1분봉 데이터 + 시간봉 집계
  캐시"다.

## 범위

전부 프론트엔드 변경. 서버·엔진·DB·API 무변경. 기존 완료된 백테스트에도 즉시 적용된다.

## 설계

### 1. 총 비용 카드 (결과 상세)

`backtest-detail-page.tsx` 의 `MetricCards` 에 7번째 카드 "총 비용" 추가.

- 메인 값: `totalCommission + totalTax + totalSlippage` 합계 (원화, `formatKrw`)
- 서브 라인: `수수료 152,300 · 세금 121,800 · 슬리피지 113,320 (초기자본의 1.13%)`
- 슬리피지 퍼센트 = `totalSlippage / initialCash × 100`, 소수 둘째 자리
- 분모를 초기자본으로 잡은 이유: `totalReturnPct` 와 같은 분모라 "수익률에서
  슬리피지가 몇 %p 깎아먹었나"를 직접 비교할 수 있다. 총 거래대금 기준(bp)이
  업계 표준이지만 turnover 가 메트릭에 없어 엔진 변경이 필요하므로 제외했다.
- 기존 카드 구조 `{label, value, className}` 에 선택적 `detail` 필드 추가.
  다른 카드는 영향 없다.
- `zero-cost` 프로파일이면 0원 · 0.00% 그대로 표시한다. 숨기지 않는다 —
  "비용 없이 돌린 결과"라는 사실 자체가 정보다.

### 2. 전략별 그룹화 + 한국어 이름 (목록·상세)

`backtests-page.tsx`:

- `/strategies` 를 조회해 `strategyId → name` 맵을 만든다 (react-query,
  위저드와 같은 캐시 키 관례).
- 잡을 `strategyId` 로 그룹핑한다. 그룹 헤더 = 전략 한국어 이름, 레지스트리에
  없는 전략(삭제·개명)은 id 로 폴백한다.
- 그룹 헤더 이름 옆에 ⓘ 툴팁 버튼을 붙여 전략 설명(`/strategies` 의
  `description`)을 보여준다. 클릭(터치 탭)으로 여는 방식 — `ParamHint`
  (`param-hint.tsx`)와 같은 이유(모바일 hover 부재). 열고 닫는 로직을 공용
  컴포넌트 `InfoHint` 로 추출해 `ParamHint` 와 그룹 헤더가 공유한다.
  설명이 없거나 전략을 못 찾으면 툴팁 버튼을 그리지 않는다.
- 그룹 정렬: 그룹 내 최신 잡 `createdAtMs` 내림차순. 그룹 내부는 지금처럼 최신순.
- 카드 안의 `job.strategyId` 텍스트는 그룹 헤더와 중복이므로 제거한다.

`backtest-detail-page.tsx`:

- 페이지 제목과 재현성 카드의 전략 표기를 `이름 (id vX.Y)` 형태로 바꾼다.
  재현성 정보이므로 id 를 병기한다.

### 3. 소비 봉 주기 표시 (목록·상세)

- 목록 카드: 종목 요약 라인에 `· 1시간봉` 형태로 추가.
- 상세 재현성 카드: `봉 주기` 행 추가.
- 값 결정: `request.timeframe` 우선. 없으면(이 필드가 없던 시절의 잡) 데이터셋
  목록에서 `datasetId` 로 timeframe 을 찾아 쓴다 — "미지정 = 데이터셋 timeframe"
  이 엔진 규칙이므로 이 폴백이 실제 소비 봉이다. 데이터셋도 삭제됐으면 `-`.
- 표기는 `timeframeLabel` (1분봉/1시간봉/일봉). 소비 봉 주기이므로
  `datasetTimeframeLabel` 을 쓰지 않는다.

### 4. 데이터셋 봉 주기 라벨 수정

`src/web/lib/format.ts` 의 `datasetTimeframeLabel('1h')` 반환을
`'1시간봉 (1분봉 수집)'` 에서 `'1분봉'` 으로 바꾼다. 사용처 3곳(데이터셋 목록
배지, 위저드 데이터셋 선택, 캔들 조회)이 자동 반영된다.

의도된 트레이드오프: CSV 로 만든 `1m` 종류와 브로커 `1h` 종류가 화면상 같은
'1분봉' 으로 보인다. 실제 차이는 시간봉 집계 보관 여부뿐이고, 그 차이는 백테스트
위저드의 봉 주기 선택지(1h 종류에만 노출)에서 자연히 드러난다.

## 테스트

- 비용 요약 문자열·슬리피지 퍼센트 계산을 순수 헬퍼로 분리해 단위 테스트
  (0원 케이스, 반올림 포함).
- 그룹핑·정렬과 봉 주기 결정(요청 → 데이터셋 폴백 → `-`)도 순수 함수로 분리해
  단위 테스트.
- 카드·헤더 렌더링은 기존 패턴을 따르고 수동 확인한다.

## 하지 않는 것

- 총 거래대금(turnover) 메트릭 추가 — 슬리피지 bp 표기가 필요해지면 그때 엔진에
  추가한다.
- 해외주식 양도소득세 모델링 — US 시장 미지원 상태라 무의미. 지원 시 연 단위
  정산 레이어로 별도 설계.
- 데이터셋 종류(`1m`/`1h`) 통합 마이그레이션 — 라벨 수정으로 충분.
