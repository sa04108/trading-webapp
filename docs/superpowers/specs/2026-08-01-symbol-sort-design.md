# 종목 정렬 — 시가총액·거래대금·거래량, 그리고 유니버스 상한 처리

## 왜

D-035 가 종목 목록에 검색·페이징을 넣으면서 정렬은 "가나다순 고정, 정렬 UI 는 나중" 으로
남겼다. 그 나중이 지금이다. 1,000종목 목록에서 사용자가 실제로 묻는 것은 「ㄱ 으로
시작하는 종목」이 아니라 **「큰 종목」**이다.

백테스트 쪽은 다른 문제였다. 데이터셋은 1,000종목까지 담고 백테스트 유니버스 상한은
200종목인데, 위저드는 참조 종목 전부를 체크박스로 깔아 놓고 사용자가 손으로 800개를
끄기를 기다렸다. 1,000개 체크박스를 그리는 것 자체가 D-036 이 데이터셋 편집에서 없앤
바로 그 성능 문제이기도 하다. 그리고 애초에 **백테스트를 만들면서 종목을 골라내는 것이
잘못된 프로세스다** — 아래 「위저드는 데이터셋만 고른다」에서 다룬다.

## 소스가 주는 것과 주지 않는 것

토스증권 Open API 기준.

| 지표 | 경로 | 덮는 범위 |
|---|---|---|
| 발행주식수 | `GET /api/v1/stocks` (`sharesOutstanding`) | 묻는 종목 전부 (200건씩) |
| 현재가 | `GET /api/v1/prices` (`lastPrice`) | 묻는 종목 전부 (200건씩) |
| 거래대금·거래량 | `GET /api/v1/rankings` (`tradingAmount`·`tradingVolume`) | **시장 상위 100위까지** |

**시가총액을 주는 엔드포인트가 없다.** 발행주식수 × 현재가로 만든다. 둘 다 종목을
지정해 물을 수 있으므로 등록 종목 전부를 덮는다.

**거래대금·거래량은 사정이 다르다.** "이 200종목의 거래대금" 을 묻는 API 가 없고 시장
전체 랭킹만 있다. 랭킹 밖 종목의 값은 **모른다** — 0 이 아니다. 0 으로 채우면 거래가
없던 종목과 순위에 못 든 종목이 같은 칸에 놓이고, 정렬은 그 900종목을 근거 없이 한
덩어리로 만든다. null 로 남기고 화면이 「N종목은 집계 없어 뒤에 가나다순으로 놓인다」고
적는다.

랭킹은 **두 축을 모두 받아 합친다**. `MARKET_TRADING_AMOUNT` 상위 100 과
`MARKET_TRADING_VOLUME` 상위 100 은 서로 다른 종목 집합이고, 두 응답 모두 두 값을 함께
싣는다. 한쪽만 받으면 거래량 상위에만 든 종목의 거래대금이 비어 정렬이 그 종목을 근거
없이 뒤로 민다.

`duration` 은 `realtime` 이 아니라 `1d` 다. 실시간 누적은 장 초반에 거의 0 이라 그
시간대의 「거래대금순」이 사실상 무작위가 되고, 장 마감 후와 장중의 순서가 달라진다.

## 모델

```
GET /symbols/metrics
  → { metrics: [{ code, marketCap, tradingValue, tradingVolume }], rankingLimit }
```

- **등록 종목 전체**를 답한다. 코드를 받지 않는 이유: 정렬은 페이지가 아니라 목록
  전체를 대상으로 하고, 화면이 페이지마다 다시 물으면 스크롤 도중 순서가 바뀐다.
- **실패는 200 + null 이다.** 자격 증명 미설정·조회 실패로 종목 화면이 막히면 안 된다 —
  가나다순으로는 멀쩡히 쓸 수 있다. `SymbolInfoService` 가 이름에 대해 하는 것과 같다.
- `rankingLimit` 을 함께 싣는다. 「상위 100위까지만 제공된다」를 화면이 말하려면 그
  숫자가 응답에 있어야 한다.

캐시는 셋 다 다르다. 발행주식수는 이름과 같은 응답에서 오므로 `SymbolInfoService` 의
24시간 캐시를 그대로 나눠 쓴다(따로 받으면 `/stocks` 를 두 벌 부른다). 현재가와 랭킹은
60초 — 시세는 움직이지만 목록을 보는 도중 순서가 뒤집히면 읽을 수 없다.

**세 소스는 독립적으로 받는다.** 랭킹이 죽어도 시가총액은 나와야 하고 그 반대도 같다.
다만 랭킹을 한 축도 못 받으면 캐시하지 않는다 — 빈 결과를 60초 붙잡으면 일시 장애가 그
시간 내내 「집계 없음」으로 보인다.

## 정렬

`sortSymbols(symbols, key, metrics)` 하나가 두 화면(종목 탭·데이터셋 종목 편집)을 덮는다.
규칙:

1. 규모 지표는 **내림차순**. 「시가총액순」을 고르는 사람이 보려는 것은 큰 종목이다.
2. 값이 없으면 **뒤로**. 값이 아무리 작은 종목보다도 뒤다.
3. 값이 같거나 둘 다 없으면 **가나다순으로 떨어진다**. 랭킹 밖 900종목이 매 렌더 다른
   순서로 보이면 목록이 아니라 셔플이다.
4. `NaN`·`Infinity` 는 "모름" 으로 접는다. 비교에서 순서를 무너뜨린다.

정렬 축은 행에도 적는다 — **정렬한 축만**. 세 지표를 늘 나열하면 행이 두 배로 길어지는데
사용자가 확인하려는 것은 "왜 이 종목이 위에 있나" 하나다.

## 위저드는 데이터셋만 고른다 — 유니버스는 데이터셋이 정한다

2단계는 데이터셋 **자체만** 보여 준다. 종목 체크박스는 없고, 고른 데이터셋을 해제할
수도 없다(다른 데이터셋으로 바꾸는 것만 된다). 「편집」은 데이터 화면의 그 데이터셋 편집
다이얼로그로 보낸다(`/datasets?tab=datasets&edit=<id>`).

**백테스트를 만들면서 종목을 골라내는 것 자체가 잘못된 프로세스다.** 같은 데이터셋으로
돌린 두 결과가 서로 다른 유니버스를 갖게 되고, 무엇이 달랐는지는 저장된 요청을 펼쳐
봐야만 안다. 유니버스를 바꾸고 싶으면 데이터셋을 바꾼다 — 그러면 그 사실이 데이터
화면에 남고 다음 실행도 같은 것을 쓴다. 참조를 바꾸는 화면이 둘이면 무엇이 최신인지
알 수 없다는 문제도 같이 없어진다.

딥링크는 한 번 쓰고 쿼리에서 지운다. 남겨 두면 새로고침이 닫은 다이얼로그를 되연다.

## 상한 초과 데이터셋은 자르지 않고 막는다

```
데이터셋 1,000종목 ─→ 2단계 게이트가 막는다 (검토로 갈 수 없다)
```

- **알아서 상위 200종목만 담지 않는다.** 그건 위저드가 종목을 골라내는 것과 같은 일이고,
  기준(시가총액순/거래대금순)에 따라 담기는 종목이 달라지므로 "이 데이터셋으로 돌렸다"
  가 더는 실행을 특정하지 못한다. 앞에서 200개를 자르는 것은 더 나쁘다 — 그 200개는
  가나다순 앞자리일 뿐이다.
- 막는 자리는 `stepBlocker(1, …)` 이다. 데이터셋을 고르는 그 자리에서 이유가 뜨고,
  검토까지 네 단계를 지나 "요청을 못 만든다" 를 듣는 왕복이 없다. 상한 초과는 카드에도
  적어 **고르기 전에** 보이게 한다.
- 상한 상수는 `src/shared/schemas/universe-limit.ts` 하나다. 화면이 자기 숫자를 들면
  상한을 올릴 때 한쪽만 고쳐지고 그 어긋남은 제출 400 으로만 드러난다. 요청 스키마도 이
  상수를 쓰고, 단위 테스트가 게이트 경계와 스키마 경계가 같은지 직접 확인한다.
  (zod 를 웹 번들에 끌고 오지 않으려고 스키마 파일에서 떼어냈다.)
- 복제(clone)만 예외다. 저장된 요청의 종목 목록을 그대로 되살린다 — 예전 화면에서 부분
  선택으로 만든 잡을 복제하면서 데이터셋 전체로 넓히면 「재실행」이 재실행이 아니게 된다.
  데이터셋을 다시 고르면 그때 그 데이터셋의 종목 전체를 쓴다.

## 하지 않은 것

- **로컬 봉에서 거래대금 채우기.** 저장된 일봉의 `close × volume` 이면 랭킹 밖 종목도
  덮을 수 있지만, 랭킹(오늘)과 마지막 저장 봉(몇 주 전일 수 있다)을 한 열에 섞으면
  정렬 순서가 뜻을 잃는다. 둘을 나란히 두려면 "언제 기준" 을 종목마다 표시해야 하고,
  그건 정렬 컨트롤 하나가 감당할 정보량이 아니다.
- **서버 정렬.** 검색과 마찬가지로 클라이언트에서 한다 (D-035 와 같은 한계). 지표를 한
  번에 받아 두므로 1,000종목 정렬은 렌더 한 번 안에서 끝난다.
- **지표를 저장하지 않는다.** 시가총액·거래대금은 "지금" 값이라 과거 시점 재현이 안 되고,
  백테스트 입력이 되면 look-ahead bias 다. 봉·재무와 달리 parquet 에 남기지 않고 프로세스
  메모리에만 캐시한다 — 종목 동기화도 이 API 를 부르지 않는다(화면을 열 때만 나간다).
- **오름차순 토글.** 「시가총액 작은 순」을 실제로 찾는 화면이 아직 없다.
