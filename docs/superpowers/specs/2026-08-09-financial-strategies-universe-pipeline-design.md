# 재무전략·단계형 유니버스·자동 재무 동기화 설계

- 작성일: 2026-08-09
- 상태: 사용자 설계 승인 완료
- 대상 시장: KOSPI·KOSDAQ 중 단일 시장

## 1. 목표

이 변경은 백테스트의 종목 선정과 재무 데이터 준비를 한 흐름으로 묶는다.

1. PIT 재무정보를 쓰는 전략 2개를 추가한다.
2. 시가총액 하나뿐인 유니버스 규칙을 순서가 있는 단계형 후보 축소 파이프라인으로 바꾼다.
3. 시가총액·거래량·거래대금·PER·급하락 기준을 지원한다.
4. 사용자가 리밸런싱 주기를 1일에서 1년 사이로 정한다.
5. 백테스트 준비에 필요한 재무·자본변동을 온디맨드로 자동 동기화한다.
6. `facts:sync` CLI와 수동 자본변동 수집 경로를 제거한다.
7. 동시 보유 종목 하드 상한을 20개에서 200개로 높이고 기본값을 40개로 바꾼다.

## 2. 범위 밖

- 애널리스트 추정치와 forward PER은 수집하지 않는다.
- 여러 기준을 가중치로 합치는 합성점수 편집기는 만들지 않는다.
- 업종 중립 순위와 업종별 쿼터는 지원하지 않는다.
- 한 파이프라인에서 같은 기준을 두 번 쓰지 않는다.
- 실거래 동작은 바꾸지 않는다.
- 향후 1년 수익률을 보장하거나 예측값으로 표시하지 않는다.

## 3. 전략 선정 근거와 한계

최근 KOSPI는 2025년 큰 폭으로 상승했고 2026년에는 반도체 실적을 중심으로 상승과 큰 조정을 함께 겪었다. 이 환경에서는 이익 개선과 가치·수익성을 서로 다른 전략으로 검증할 가치가 있다.

다만 최근 1년 장세는 전략 선정의 가설일 뿐이다. 가치·수익성 팩터 연구는 장기간 평균수익의 차이를 다루며 다음 1년 성과를 보장하지 않는다. 이익발표 후 드리프트 연구도 단순 전년 대비 이익 증가율이 아니라 시장 기대를 웃돈 서프라이즈를 주로 다룬다. 일부 연구는 효과 감소와 거래비용 영향을 보고한다.

참고 자료:

- [KRX Data Marketplace](https://data.krx.co.kr/)
- [Fama·French, A five-factor asset pricing model](https://www.aea.ru/data/pdf/fama2015.pdf)
- [Asness·Frazzini·Pedersen, Quality Minus Junk](https://research-api.cbs.dk/ws/files/60211462/lasse_heje_pedersen_et_al_quality_minus_junk_publishersversion.pdf)
- [Johnson·Schwartz, Earnings Surprises and the Persistence of Post-Announcement Drift](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=255603)
- [Chordia 외, Liquidity and the Post-Earnings-Announcement Drift](https://business.columbia.edu/faculty/research/liquidity-and-post-earnings-announcement-drift)

두 전략은 연구 후보로 제공한다. 채택 판단은 여러 시장 국면을 포함한 walk-forward 결과에서 사용자가 내린다.

## 4. 핵심 용어

- **후보군**: 현재 파이프라인 단계에 들어오는 종목 집합이다.
- **단계**: 후보군을 한 기준으로 정렬하고 상위 N개만 다음 단계로 넘기는 연산이다.
- **최종 유니버스**: 마지막 단계를 통과한 종목 집합이다.
- **기준일**: 사용자가 정한 달력상 리밸런스 날짜다.
- **적용 거래일**: 기준일 이전 또는 당일 중 자료가 있는 가장 늦은 거래일이다.
- **PIT 재무**: 리밸런스 판단 시각까지 공시된 사실만 포함한 재무 스냅샷이다.
- **warm-up**: 첫 백테스트 날짜의 지표를 계산하려고 기간 시작 전 자료를 읽는 최소 구간이다.

## 5. 유니버스 규칙

### 5.1 요청 모델

새 규칙은 다음 형태다.

```ts
type UniverseCriterion =
  | 'MARKET_CAP'
  | 'VOLUME'
  | 'TRADING_VALUE'
  | 'PER'
  | 'DECLINE';

type UniverseStage =
  | {
      criterion: Exclude<UniverseCriterion, 'DECLINE'>;
      limit: number;
    }
  | {
      criterion: 'DECLINE';
      limit: number;
      lookbackTradingDays: number;
    };

type RebalanceUnit = 'DAY' | 'WEEK' | 'MONTH' | 'YEAR';

interface UniverseRule {
  markets: ['KOSPI' | 'KOSDAQ'];
  stages: UniverseStage[];
  rebalanceInterval: {
    value: number;
    unit: RebalanceUnit;
  };
}
```

예시:

```json
{
  "markets": ["KOSPI"],
  "stages": [
    { "criterion": "MARKET_CAP", "limit": 200 },
    { "criterion": "PER", "limit": 100 },
    { "criterion": "DECLINE", "limit": 30, "lookbackTradingDays": 20 }
  ],
  "rebalanceInterval": { "value": 1, "unit": "MONTH" }
}
```

### 5.2 스키마 불변식

- 시장은 하나만 선택한다.
- 단계는 1개 이상 5개 이하이다.
- 같은 `criterion`은 한 번만 쓴다.
- 첫 단계 `limit`은 1~200이다.
- 다음 단계 `limit`은 1~직전 단계 `limit`이다.
- `DECLINE.lookbackTradingDays`는 1~252이다.
- `DECLINE` 이외의 단계는 `lookbackTradingDays`를 받지 않는다.
- 모르는 필드는 버린다. 필수 필드가 없거나 범위를 벗어나면 요청을 거부한다.

### 5.3 단계 계산

각 리밸런스 날짜에 상장 보통주와 선택 시장 조건으로 최초 후보군을 만든다. 거래불가 종목은 최초 후보군에서 제외한다.

각 단계는 다음 절차를 따른다.

1. 직전 단계가 넘긴 후보만 평가한다.
2. 기준값을 계산할 수 없는 종목을 제외한다.
3. 정해진 방향으로 정렬한다.
4. 동점이면 단축 종목코드 오름차순으로 정한다.
5. 앞에서 `limit`개만 다음 단계로 넘긴다.

정렬 방향은 사용자가 바꾸지 않는다.

| 기준 | 방향 | 값 |
|---|---|---|
| 시가총액 | 큰 순 | 적용 거래일 KRX 시가총액 |
| 거래량 | 많은 순 | 적용 거래일 `ACC_TRDVOL` |
| 거래대금 | 많은 순 | 적용 거래일 `ACC_TRDVAL` |
| PER | 낮은 순 | 적용 거래일 시가총액 / PIT TTM 순이익 |
| 급하락 | 낮은 수익률 순 | 적용 거래일까지 직전 N거래일 분할보정 수익률 |

PER은 TTM 순이익과 시가총액이 모두 양수일 때만 계산한다. 0 이하 PER과 재무가 없는 종목은 제외한다.

급하락 수익률은 시작 종가와 종료 종가를 자본변동 팩트로 분할보정한 뒤 `종료가 / 시작가 - 1`로 계산한다. 정확히 N거래일 전 종가가 없으면 제외한다. 액면분할을 급락으로 오인하지 않는다.

### 5.4 단계 진단

미리보기는 날짜·단계마다 다음 값을 반환한다.

```ts
interface UniverseStageDiagnostic {
  criterion: UniverseCriterion;
  inputCount: number;
  eligibleCount: number;
  selectedCount: number;
  excludedMissingMetricCount: number;
}
```

화면은 다음처럼 표시한다.

```text
시가총액  824 → 200
PER       187 → 100  (13개는 PER 계산 불가)
급하락    100 → 30
```

최종 종목이 0개이면 미리보기는 원인과 단계 진단을 돌려주고 제출을 막는다.

## 6. 리밸런싱 주기

### 6.1 입력 범위

| 단위 | 허용 값 |
|---|---|
| 일 | 1~365 |
| 주 | 1~52 |
| 개월 | 1~12 |
| 년 | 1 |

주기 하나가 1년을 넘으면 거부한다. 주기 범위의 마지막 날이 백테스트 종료일을 넘으면 거부한다. 시작일과 종료일은 모두 기간에 포함한다.

예를 들어 2026-01-01~2026-01-31에는 1개월 주기를 허용한다. 첫 선정은 시작일에 수행하고 다음 기준일은 기간 밖이므로 일정에는 첫 항목 하나만 남는다.

### 6.2 날짜 계산

- 첫 기준일은 `period.from`이다.
- 이후 날짜는 첫 기준일을 원점으로 `k × interval`을 더한다.
- 월·년 단위에서 대상 월에 같은 일자가 없으면 월말로 줄인다.
- 중간 계산값을 다음 날짜의 원점으로 쓰지 않는다. 2월을 지난 뒤 28일에 고착되지 않는다.
- 기준일이 휴장일이면 직전 거래일 자료로 선정한다.
- 새 멤버십은 기준일 이후 첫 거래 가능 봉부터 적용한다.

리밸런스 주기는 전략 파라미터가 아니라 `UniverseRule`이 소유한다. `cross-sectional-momentum`과 `value-quality-rank`의 `rebalanceMonths`를 제거하고 전략 버전을 올린다.

## 7. 동시 보유 상한

20개는 투자 관례에 따른 값이 아니었다. 최초 기준 전략의 임의 상한을 요청 스키마가 이어받았고, 후속 전략이 그 상한에 맞춰 축소됐다.

새 정책은 다음과 같다.

- `risk.maxPositions` 허용 범위: 1~200
- 새 백테스트 기본값: 40
- 새 재무전략의 `topN` 기본값: 40
- 모든 순위 전략의 `topN` 허용 범위: 1~200
- `strategy.topN > risk.maxPositions`이면 제출을 거부한다.
- `strategy.topN > 마지막 stage.limit`이면 제출을 거부한다.
- `risk.maxPositions`가 마지막 단계 N보다 큰 것만으로는 거부하지 않는다. 실제 후보보다 큰 안전 상한은 결과를 바꾸지 않기 때문이다.

화면은 동일가중 전략에서 `100 / topN`으로 계산한 종목당 예상 비중을 함께 보여준다. 기본 40개는 종목당 2.5%이다.

분산형 펀드 규칙도 보유 종목 수 하나보다 종목당 비중과 집중도를 주로 제한한다. 40은 안전을 보장하는 값이 아니라 편의 기본값이다.

## 8. 재무전략

### 8.1 공통 규칙

- 두 전략 모두 `requiresFundamentals: true`이다.
- PIT 스냅샷만 읽는다.
- 공시 접수 시각 전 봉에서는 그 공시를 볼 수 없다.
- 사용자가 정한 유니버스 리밸런스 시점에만 순위를 다시 계산한다.
- 매도와 매수는 두 단계로 나눈다. 탈락 종목 매도가 체결된 뒤 새 종목을 산다.
- 목표 종목은 동일가중한다.
- 계산할 수 없는 종목은 순위에서 제외한다.
- `staleQuarters` 기본값은 2이고 허용 범위는 0~8이다.

### 8.2 이익 가속·가격 확인 순위

- id: `earnings-acceleration-rank`
- 표시명: `이익 가속·가격 확인 순위`

파라미터:

```ts
{
  topN: 40,                 // 1~200
  priceMomentumDays: 126,  // 60~252
  staleQuarters: 2         // 0~8
}
```

최근 공개 분기를 `q0`이라고 한다.

1. `q0`부터 `q-3`까지의 TTM 영업이익을 계산한다.
2. `q-4`부터 `q-7`까지의 전년 TTM 영업이익을 계산한다.
3. 두 TTM 값이 모두 양수여야 한다.
4. `ttmGrowth = currentTtm / priorTtm - 1`이 양수여야 한다.
5. `q0`과 `q-4`, `q-1`과 `q-5`의 분기 영업이익 YoY를 계산한다. 두 비교의 과거 기준값은 양수여야 한다.
6. `latestQuarterYoy > previousQuarterYoy`여야 한다.
7. 최근 `priceMomentumDays` 거래일 분할보정 수익률이 양수여야 한다.
8. TTM 성장률 내림차순 순위와 가격 모멘텀 내림차순 순위를 더한다.
9. 순위 합이 작은 `topN` 종목을 산다. 동점은 종목코드 오름차순이다.

음수에서 양수로 전환한 기업은 작은 분모로 성장률이 폭발하므로 제외한다. 이 전략은 턴어라운드 전략이 아니다.

첫 거래일부터 신호를 계산하려면 최대 8개 비교 분기와 가격 모멘텀 봉을 warm-up으로 읽는다. 백테스트 손익과 거래 기록은 `period.from` 이전에 만들지 않는다.

### 8.3 저PER·고ROE 순위

- id: `low-per-high-roe-rank`
- 표시명: `저PER·고ROE 순위`

파라미터:

```ts
{
  topN: 40,          // 1~200
  staleQuarters: 2   // 0~8
}
```

리밸런스 날짜마다 다음 값을 계산한다.

```text
PER = 적용 거래일 시가총액 / PIT TTM 순이익
ROE = PIT TTM 순이익 / PIT 최근 자본총계
```

TTM 순이익·자본총계·시가총액이 모두 양수여야 한다. PER 오름차순 순위와 ROE 내림차순 순위를 더하고, 합이 작은 `topN` 종목을 동일가중한다. 동점은 종목코드 오름차순이다.

이 전략은 기존 `value-quality-rank`와 다르다. 기존 전략은 EBIT/EV와 EBIT/투하자본을 쓰고, 새 전략은 순이익 기반 PER과 자기자본수익률을 쓴다.

### 8.4 재무 팩트 확장

`FundamentalField`에 다음 계정을 추가한다.

```ts
| 'NET_INCOME'
| 'TOTAL_EQUITY'
```

`NET_INCOME`은 분기 단독값이며 TTM 합산 대상이다. `TOTAL_EQUITY`는 시점값이므로 TTM 합산 대상이 아니다.

DART 파서는 연결재무제표를 우선하며 기존 `consolidated: true` 정책을 유지한다. 표준 계정명과 프로젝트가 승인한 별칭 목록만 매핑한다. 계정을 추정하거나 0으로 채우지 않는다.

`FundamentalSnapshot`은 최근 값뿐 아니라 분기 오프셋을 명시해 읽는 API를 제공한다. API는 공시된 PIT 뷰 안에서만 조회하며 미래 분기를 가져오는 경로를 만들지 않는다.

## 9. 시장 선정 자료

KRX 일별 계약에 `ACC_TRDVAL`을 추가한다. 거래대금은 `종가 × 거래량`으로 근사하지 않는다.

새 선정 자료 저장소는 날짜·표준 종목코드를 키로 다음 값을 보관한다.

```ts
interface DailySelectionMetric {
  date: string;
  standardCode: string;
  marketCapKrw: string | null;
  volume: number | null;
  tradingValueKrw: string | null;
}
```

기존 시가총액과 일봉 행에서 시가총액·거래량을 이관한다. 과거 `ACC_TRDVAL`은 로컬 자료만으로 복원할 수 없으므로 null로 둔다. 거래대금 단계가 해당 날짜를 요구하면 KRX 일별 응답으로 그 날짜만 자동 보강한다.

급하락과 가격 확인 전략은 필요한 거래일 warm-up을 계산한다. 기간 시작 전에 봉이 부족하면 KRX 백필을 자동 시작한다. 필요한 거래일 수를 채울 때까지만 과거로 확장하며, 백테스트 기간 밖 warm-up 봉에서는 주문·손익·결과 스냅샷을 만들지 않는다.

## 10. 온디맨드 재무 준비

### 10.1 원칙

재무 수집은 백테스트 미리보기에서만 시작한다. 서버가 사용하지 않을 전체 시장 재무를 매일 미리 받지 않는다.

미리보기 준비 과정은 다음 종목을 동기화한다.

1. PER 단계에 들어가는 후보 전체
2. 분할보정 급하락 단계에 들어가는 후보의 자본변동
3. 최종 유니버스 전체의 재무·자본변동

따라서 PER이 첫 단계면 해당 시점 시장 전체 후보의 재무가 필요할 수 있다. 앞에서 시가총액 200개로 줄인 뒤 PER을 적용하면 200개만 동기화한다. 사용자가 정한 단계 순서가 데이터 준비 비용에도 영향을 준다. 화면은 예상 종목 수·연도·호출 수를 보여준다.

최종 유니버스는 전략 종류와 관계없이 재무·자본변동을 자동 증분 동기화한다. 이 정책이 `facts:sync`를 항상 자동으로 만든다.

### 10.2 수집 범위

기본 수집 연도는 백테스트 시작 연도부터 종료 연도까지다. 계산에 선행 분기가 필요하면 다음 최소 warm-up을 더한다.

- PER·저PER/고ROE: 첫 시점 TTM을 만들 수 있는 최대 4개 공시 분기
- 이익 가속: 현재·전년 TTM과 분기 가속을 만들 수 있는 최대 8개 공시 분기
- 자본변동: 대상 연도와 각 불연속 구간 직전 주식수 앵커 연도

동기화 계획은 전략 메타데이터의 `fundamentalLookbackQuarters`와 유니버스 단계 요구량 중 큰 값을 쓴다. DART가 연도 단위로 조회되므로 필요한 가장 이른 분기가 속한 사업연도부터 요청한다. 최근 보고서 공시 지연을 고려해 시작 시점에 실제로 알려질 수 있는 가장 최근 분기를 기준으로 보수적으로 계산한다.

### 10.3 준비 잡

수동 자본변동 잡을 일반 `BacktestPreparationJob`으로 대체한다.

상태:

```ts
type PreparationJobStatus =
  | 'QUEUED'
  | 'RUNNING'
  | 'WAITING_DAILY_QUOTA'
  | 'COMPLETED'
  | 'FAILED'
  | 'CANCELLED';

type PreparationPhase =
  | 'MARKET_DATA'
  | 'RESOLVING_STAGES'
  | 'SYNCING_FACTS'
  | 'FINALIZING';
```

잡은 정규화된 미리보기 요청 해시를 가진다. 같은 해시의 활성 잡이 있으면 새 잡을 만들지 않고 기존 잡을 반환한다. 다른 요청도 팩트 저장은 종목 단위 증분 커버리지를 공유한다.

진행률은 다음 정보를 포함한다.

- 현재 phase
- 완료 종목 수 / 전체 종목 수
- 수집 연도
- 저장 팩트 수
- 누락 수
- 다음 자동 재개 시각
- 현재까지 확정된 단계 진단

UI는 SSE를 우선하고 연결이 끊기면 폴링한다. 잡이 완료되면 같은 요청의 미리보기를 자동으로 표시한다. 사용자가 미리보기 버튼을 다시 누를 필요가 없다.

### 10.4 일일 호출 한도

한 프로세스에서 DART 준비 잡은 하나만 실행한다. 잡은 프로젝트가 발생시킨 그날 호출 수를 추적한다. 다음 종목·연도 작업 단위가 남은 예산을 넘으면 외부 호출 전에 `WAITING_DAILY_QUOTA`로 전환한다.

KST 날짜가 바뀌면 서버 스케줄러가 잡을 자동 재개한다. 서버 재시작 뒤에도 DB 상태와 종목별 커버리지로 이어간다. 사용자가 기다릴 수 없으면 잡을 취소하고 기간이나 앞 단계 N을 줄일 수 있다.

### 10.5 부분 실패

- DART 인증키 없음: 503 설정 오류로 실패한다.
- 특정 기업·연도 응답 없음: gap을 기록하고 나머지를 계속한다.
- 네트워크·서버 오류: 완료 종목까지 저장하고 잡을 실패 처리한다. 다음 요청은 남은 범위만 재개한다.
- 취소: 현재 종목 경계에서 멈춘다. 저장 완료분은 지우지 않는다.
- 계산 불가 재무: 해당 단계 또는 전략 순위에서 제외한다.
- 최종 후보 0개: 단계 진단과 함께 제출을 막는다.

gap이 있는 종목을 자동으로 0원·0배로 채우지 않는다. 같은 gap을 무한히 다시 요청하지 않도록 커버리지와 gap 연도를 함께 본다.

## 11. 미리보기와 제출 데이터 흐름

1. 사용자가 전략·기간·파이프라인·리밸런스 주기를 입력한다.
2. 서버가 요청 스키마와 기간 제약을 검증한다.
3. 준비 잡이 필요한 KRX warm-up과 선정 자료를 채운다.
4. 재무 없이 계산 가능한 앞 단계를 실행한다.
5. PER·급하락 단계 후보에 필요한 팩트를 증분 동기화한다.
6. 모든 날짜의 단계 파이프라인을 해소한다.
7. 최종 유니버스 전체의 재무·자본변동을 증분 동기화한다.
8. 재무 버전과 유니버스 멤버십 일정을 확정한다.
9. 미리보기 응답에 일정·단계 진단·해시·누락 경고를 담는다.
10. 제출 시 현재 입력과 미리보기 요청 해시가 같은지 확인한다.
11. 잡에는 확정된 규칙·일정·팩트/봉 버전 pin을 저장한다.

준비 완료 뒤 종목 마스터나 재무가 바뀌어도 이미 제출한 백테스트 일정을 다시 계산하지 않는다.

## 12. 리밸런스 실행 의미

멤버십 일정이 바뀐 첫 거래 가능 봉에서 엔진은 `isRebalanceBar`를 전략 컨텍스트에 전달한다.

기존 보유 종목이 새 유니버스에서 빠지면 엔진이 `REBALANCE_EXIT` 매도 의도를 만든다. 그 주문은 다음 거래 가능 봉 시가에 체결한다. 사용자의 전략이 별도 매도 신호를 내지 않아도 탈락 종목을 유지하지 않는다.

같은 시점의 매수는 청산 체결 다음 봉으로 미룬다. 다음 순서를 보장한다.

```text
멤버십 변경 감지
→ 탈락 종목 매도 의도
→ 다음 거래 가능 봉 시가 청산
→ 현금·포지션 상한 갱신
→ 신규 편입 종목 매수 의도
→ 그 다음 거래 가능 봉 시가 매수
```

전략이 낸 중복 매도와 엔진의 `REBALANCE_EXIT`가 겹치면 한 주문으로 접는다. 청산 수량은 보유 수량을 넘지 않는다.

## 13. UI/UX

### 13.1 선정 파이프라인 편집기

각 단계 행은 다음 요소를 가진다.

- 순서 번호
- 드래그 핸들 및 키보드 이동 버튼
- 기준 선택
- 상위 N 입력
- 기준 설명
- 삭제 버튼
- 급하락 전용 관찰 기간 입력

새 단계를 추가하면 직전 단계 N을 기본값으로 복사한다. 사용자는 그 값 이하만 입력할 수 있다.

드래그로 순서를 바꾼 뒤 N 제약이 깨지면 뒤 단계부터 다음 규칙으로 줄인다.

```text
stage[i].limit = min(기존 stage[i].limit, stage[i - 1].limit)
```

자동으로 바뀐 행을 잠시 강조하고 “단계 순서에 맞춰 후속 N을 조정했습니다”라고 알린다. 입력을 조용히 바꾸지 않는다.

### 13.2 리밸런싱 주기

숫자 입력과 `일·주·개월·년` 선택을 한 줄에 둔다. 현재 백테스트 기간으로 계산한 최대 허용값을 도움말에 표시한다. 범위를 넘으면 필드 아래 오류와 다음 단계 차단을 함께 적용한다.

### 13.3 자동 준비 진행률

별도 수집 버튼은 두지 않는다. 미리보기 버튼을 누르면 준비 잡을 시작하고 같은 카드에서 진행률을 보여준다.

```text
재무정보 준비 중 · 63 / 200종목
2023~2026년 · 증분 동기화
[취소]
```

일일 한도 대기 중이면 다음 자동 재개 시각과 기간·N을 줄이는 대안을 안내한다. 완료되면 리밸런스 일정과 단계 진단 카드로 자동 전환한다.

### 13.4 보유 상한

기본값은 40이다. 입력 범위는 1~200이다. 동일가중 전략을 고르면 예상 종목당 비중을 표시한다. 유니버스 단계 N과 전략 `topN`, 동시 보유 상한이 맞지 않으면 어느 값을 바꿔야 하는지 구체적으로 말한다.

## 14. 기존 데이터 호환성

과거 실행 기록과 `universeScheduleJson`은 수정하지 않는다.

복제 초안에서 옛 요청을 다음처럼 재기준한다.

```text
{ sortKey: 'MKTCAP', topN: N }
→ stages: [{ criterion: 'MARKET_CAP', limit: N }]
```

- 전략 파라미터에 `rebalanceMonths`가 있으면 `{ value, unit: 'MONTH' }`로 옮기고 파라미터에서 제거한다.
- `rebalanceMonths`가 없으면 1개월을 넣고 결과가 원본과 달라질 수 있다고 경고한다.
- 옛 `risk.maxPositions` 값은 그대로 유지한다. 새 기본값 40은 새 백테스트에만 적용한다.
- 사라진 전략과 현재 전략 버전 차이는 기존 재기준 경고 규칙을 유지한다.

원본 요청 JSON과 실행 당시 pin은 감사·재현성 자료이므로 마이그레이션으로 덮어쓰지 않는다.

## 15. 제거·대체 대상

- `cli.ts`의 `facts:sync` 명령·인자 파서·리포트 출력 제거
- README·ONBOARDING의 수동 `facts:sync` 안내 제거
- 수동 자본변동 수집 버튼과 전용 게이트 제거
- 전용 `CorporateActionSyncOrchestrator`를 일반 준비 잡으로 대체
- 자본변동 전용 라우트를 준비 잡 상태·SSE 라우트로 대체
- 전략별 `rebalanceMonths` 파라미터 제거
- 시가총액 전용 provenance 문구를 단계형 파이프라인 요약으로 교체

기존 팩트 수집 서비스와 종목 단위 저장·커버리지·gap 기록은 재사용한다.

## 16. 테스트

### 16.1 스키마·도메인

- 단계 없음·중복 기준·200 초과·N 증가를 거부한다.
- 새 단계는 직전 N을 복사한다.
- 재정렬 뒤 후속 N만 필요한 만큼 줄인다.
- PER은 양수 TTM 순이익만 쓴다.
- 거래대금은 KRX 원자료를 쓰며 종가×거래량으로 계산하지 않는다.
- 급하락은 N거래일과 분할보정 수익률을 쓴다.
- 동점 결과가 입력 순서와 무관하다.
- 단계 순서가 바뀌면 최종 결과도 달라지는 fixture를 둔다.

### 16.2 주기

- 1일·365일·52주·12개월·1년 경계를 검증한다.
- 1년 초과와 백테스트 기간 초과를 거부한다.
- 월말·윤년·휴장일을 검증한다.
- 원점을 유지해 2월 이후 날짜가 28일에 고착되지 않는지 검증한다.

### 16.3 팩트·PIT

- `NET_INCOME`·`TOTAL_EQUITY` 매핑과 흐름/시점 계정 구분을 검증한다.
- 4분기·8분기 warm-up을 검증한다.
- 공시 전 봉에서 미래 값이 보이지 않는다.
- 정정공시는 접수 시각 이후에만 기존 값을 바꾼다.
- gap을 0으로 채우지 않는다.

### 16.4 준비 잡

- 같은 요청은 single-flight로 합친다.
- 종목 단위 저장 뒤 실패하면 남은 범위만 재개한다.
- 취소는 종목 경계에서 멈춘다.
- 일일 호출 한도 전에 대기하고 KST 날짜 변경 뒤 재개한다.
- 서버 재시작 뒤 활성 잡을 복구한다.
- SSE 단절 뒤 폴링으로 진행률을 이어간다.
- 완료 뒤 미리보기를 자동 표시한다.

### 16.5 전략

- 이익 가속 조건과 8개 분기 구멍을 검증한다.
- 이익 증가율·가격 모멘텀 순위 합과 동점을 검증한다.
- 저PER·고ROE 순위 합과 음수 분모 제외를 검증한다.
- stale 공시를 제외한다.
- 기본 40개·최대 200개와 동일가중을 검증한다.
- 리밸런스 봉이 아닐 때 순위를 다시 계산하지 않는다.

### 16.6 엔진·통합·E2E

- 탈락 종목을 `REBALANCE_EXIT`로 청산한다.
- 청산 체결 후에만 신규 편입 매수를 낸다.
- 중복 매도를 접고 보유 수량 이상 팔지 않는다.
- warm-up 기간에 주문·손익·결과 스냅샷을 만들지 않는다.
- 최종 규칙·일정·팩트/봉 버전을 pin한다.
- 복제 시 옛 규칙과 `rebalanceMonths`를 재기준하고 경고한다.
- 드래그 재정렬·N 자동 조정·주기 차단·진행률·오류를 데스크톱과 390px 화면에서 검증한다.

## 17. 완료 기준

- 사용자가 다섯 기준을 원하는 순서로 조합하고 단계별 N을 줄일 수 있다.
- 단계 순서와 N이 미리보기·제출·실행에서 같은 결과를 만든다.
- 1일~1년 주기를 고를 수 있고 백테스트 기간보다 긴 주기는 제출되지 않는다.
