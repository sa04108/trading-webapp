# 편출 종목의 stale pendingEntry 정리

날짜: 2026-08-13

## 문제

EMA 추세 스위치와 RSI 되돌림은 매수 주문을 발행하면 전략 상태의
`holding.pendingEntry`를 `true`로 둔다. 이 표시는 다음 거래 가능 봉에서 주문이
체결되기 전까지 같은 종목의 중복 주문을 막고, 역상관 그룹의 다른 종목이 동시에
진입하지 못하게 그룹을 예약한다.

리밸런스에서 종목이 편출되면 엔진은 이전 멤버십에서 발행한 대기 BUY를 취소한다.
그러나 전략에는 주문 취소 알림이 없고, 현재 구현은 이번 시점에 봉이 있는 종목만
`pendingEntry`를 정리한다. 편출 종목이 거래정지 등으로 봉도 없다면 플래그가 남는다.
그 종목이 나중에 봉 없이 재편입되면 stale 플래그가 역상관 그룹을 계속 선점해,
실제로 거래 가능한 다른 종목의 진입을 막을 수 있다.

## 범위

- `ema-trend-switch`와 `rsi-reversion`에서 같은 결함을 수정한다.
- 활성 유니버스 밖으로 편출된 종목의 `pendingEntry`만 봉 유무와 관계없이 해제한다.
- 활성 유니버스에 속하지만 당일 거래정지·무거래인 종목의 정상적인 진입 예약은
  유지한다.
- 엔진의 주문 큐, `TradingStrategy` 공개 계약, 상관 그룹 계산과 전략 버전은 바꾸지
  않는다.

## 설계

두 전략은 `updateCorrelationGrouping()`으로 현재 활성 멤버십을 확정한 직후,
`context.activeUniverseSymbols`가 `null`이 아닐 때 이미 생성된 심볼 상태를 순회한다.
활성 집합에 없는 심볼의 `holding.pendingEntry`를 `false`로 만든다.

이 정리는 `state.groupOf`의 준비 여부와 무관하게 실행한다. 그룹이 아직 미확정인
동안 편출되더라도 stale 상태가 남았다가 이후 그룹 확정 시 다시 선점하지 않아야 하기
때문이다. 상태가 생성되지 않은 심볼은 `pendingEntry`도 없으므로 새 상태를 만들지 않는다.

두 전략에 짧고 명시적인 루프를 각각 둔다. 유니버스와 보유 상태를 함께 아는 별도 공용
추상화를 추가하면 작은 중복보다 API 결합 비용이 커지고, 상관 그룹 모듈이 주문 상태까지
알게 되므로 이번 수정에서는 공용화하지 않는다.

## 상태 전이

정상 경로는 유지한다.

```text
BUY 발행 → pendingEntry=true → 다음 거래 가능 봉에서 체결
→ 포지션 확인 → pendingEntry=false
```

편출 취소 경로는 다음과 같이 바뀐다.

```text
BUY 발행 → pendingEntry=true → 리밸런스 편출로 엔진 BUY 취소
→ 전략이 활성 유니버스 밖 상태를 확인 → pendingEntry=false
→ 이후 재편입 시 stale 그룹 선점 없음
```

`tradableSymbols`에만 없는 종목은 편출로 간주하지 않는다. 이 집합은 거래정지·무거래
필터를 포함하므로, 이를 기준으로 일괄 정리하면 아직 유효한 대기 주문과 그룹 예약을
잘못 지울 수 있다.

## 테스트

TDD로 실제 결함을 먼저 재현한다.

- EMA: 편출로 대기 BUY가 취소된 종목이 봉 없이 재편입돼도 거래 가능한 역상관 종목의
  진입을 막지 않는지 검증한다.
- RSI: 같은 상태 전이가 RSI 전략에서도 해제되는지 검증한다.
- 기존 거래정지 보유 종목의 그룹 선점 테스트를 유지해, 활성 멤버의 예약을 잘못
  지우지 않았음을 확인한다.

회귀 테스트는 수정 전 구현에서 거래 가능 종목의 BUY가 누락되어 실패하고, 수정 후
해당 BUY가 발생해 통과해야 한다.

## 완료 조건

- 봉이 없는 편출 종목의 `pendingEntry`가 두 전략 모두에서 해제된다.
- 활성 멤버이지만 거래 불가능한 종목의 상태는 유지된다.
- 관련 회귀 테스트, lint, typecheck, 전체 테스트와 빌드가 통과한다.
- 독립 코드 리뷰에서 Critical 또는 Important 지적이 없다.
- 기존 기능 브랜치와 Draft PR #7을 갱신한다.
