# 데이터셋 종목 그룹화 (봉 슬라이스 통합) 설계

날짜: 2026-07-30
상태: 승인됨 (구현 전)

## 배경

지금은 데이터셋 종류가 봉 주기로 갈린다 — `1h`(1분봉 수집 + 시간봉 집계),
`1d`(일봉 수집), CSV 전용 `1m`. 같은 종목 묶음의 일봉과 분봉이 서로 다른
데이터셋이 되고, 사용자는 "왜 같은 종목인데 데이터셋이 두 개냐"를 이해해야 한다.

분봉과 일봉은 데이터·차트 관점에서 양립이 불가능하므로 **보관은 계속 나눈다**.
대신 데이터셋의 단위를 **종목 그룹**으로 바꾸고, 봉 주기는 그 안의 두 슬라이스로
만든다.

## 설계

### 1. 데이터 모델

- 데이터셋 = 종목 그룹: 이름, 시장, 종목 구성. `datasets.timeframe` 컬럼은
  `defaultTimeframe`(기본 봉: `1d` | `1m`) 로 대체한다.
- **종목 구성(정렬·중복 제거한 집합)이 유일키다.** 생성·종목 편집에서 같은
  구성의 데이터셋이 이미 있으면 거부한다. 이름은 표시용이며 지금처럼 유니크.
- 봉 슬라이스 2개:
  - **일봉 슬라이스**: 1d 캔들.
  - **분봉 슬라이스**: 1m 캔들 수집 + 1h 집계 보관 (기존 `1h` 종류의 실체와 같다).
- 캔들 저장소는 이미 (symbol, market, timeframe, ts) 키 — 변경 없음.
- `data_coverage` 와 `broker_sync_state` 에 슬라이스 구분(`slice`: `1d` | `1m`)
  컬럼을 추가해 봉별 워터마크·커버리지를 따로 둔다.
- 데이터셋 버전은 지금처럼 데이터셋 단위 — 어느 슬라이스든 변경되면 증가한다.

### 2. 마이그레이션

- 종목 구성이 같은 기존 `1h`·`1d` 데이터셋은 **하나로 병합**한다: 먼저 만든 쪽의
  이름·id 를 유지하고, 캔들·커버리지·동기화 상태를 각자 슬라이스로 이관한다.
  데이터 손실 없음.
- 구성이 다른 데이터셋은 슬라이스 하나만 찬 종목 그룹 데이터셋으로 전환한다.
- 기본 봉 = 기존 종류 (`1d` → 일봉, `1h`/`1m` → 분봉). 병합된 경우 먼저 만든
  쪽 종류.
- 백테스트 기록의 `datasetId` 참조: 병합으로 사라지는 id 는 남는 id 로
  재매핑한다. 재현성 메타데이터(`datasetVersion`·`datasetHash`)는 그대로 둔다 —
  과거 실행이 가리키는 데이터 내용은 변하지 않는다.
- 병합된 데이터셋의 버전 = 두 데이터셋 버전의 최댓값 + 1 (슬라이스 이관도
  변경이다). 단독 전환은 버전을 올리지 않는다 — 내용이 그대로다.

### 3. 데이터셋 카드 UI

- 카드에 **일봉/분봉 스위치**. 표시(커버리지·기간·봉 수·검증 차트)와 **동기화
  대상**이 스위치를 따른다. 스위치 기본값 = 데이터셋의 기본 봉.
- 선택한 봉의 데이터가 없으면 카드 본문에 **큰 자물쇠 아이콘 + "동기화가
  필요합니다"** 를 띄운다. 그 상태에서 동기화를 누르면 그 봉을 수집한다.
- 생성 드로어: **수집 봉 선택(일봉/분봉)을 유지한다** (기본 일봉). 선택한 봉이
  `defaultTimeframe` 으로 저장되고 첫 동기화 대상이 된다. 생성 직후 두 슬라이스
  모두 비어 있다.
- '재무' 체크는 그대로. 별도 '분봉' 체크박스는 두지 않는다 — 스위치가 동기화
  대상을 결정한다.
- CSV 가져오기: 봉 주기 선택지를 **1분봉/일봉**으로 바꾼다 (1h 업로드 제거 —
  시간봉은 1m 집계로만 생긴다). 업로드가 해당 슬라이스를 채운다.

### 4. 백테스트 위저드

- 데이터셋 선택 후 봉 주기 선택지 = **데이터가 있는 슬라이스**에서 도출:
  일봉 슬라이스 → 일봉, 분봉 슬라이스 → 1시간봉·1분봉.
- 제출 검증(커버리지·봉 수 상한)은 선택한 봉의 슬라이스 커버리지로 한다.
- 저장된 요청(`datasetId` + `timeframe`)의 형태는 그대로 — 복제·재실행 호환.

### 5. 하지 않는 것

- 분봉↔일봉 상호 집계·보정 (양립 불가 원칙).
- 슬라이스별 데이터셋 버전 분리.
- 동기화 화면의 별도 '분봉' 체크박스 (스위치로 대체).

## 테스트

- 종목 구성 유일키: 같은 구성 생성·편집 거부, 순서·중복 무관 동등성.
- 마이그레이션: 병합(이름·id 유지, 슬라이스 이관), 단독 전환, 백테스트 참조
  재매핑 — 통합 테스트.
- 동기화 대상 결정: 스위치(요청 파라미터)별 수집 timeframe — 단위 테스트.
- 자물쇠 노출 조건: 슬라이스 커버리지 유무 판정 — 단위 테스트.
- 위저드 봉 주기 선택지 도출 — 단위 테스트.
- 기존 E2E(mvp-flow)가 새 카드 구조에서 통과하도록 갱신.

## 구현 분할

계획은 두 단계로 나눈다 — 각각 독립적으로 동작·테스트 가능해야 한다:

1. **서버**: 스키마 변경 + 마이그레이션 + 슬라이스별 동기화·커버리지 + API
   (datasets 응답에 슬라이스 상태 포함).
2. **웹**: 카드 스위치·자물쇠, 생성 드로어, CSV 선택지, 위저드 봉 주기 도출.
