# 백테스트 종목 리밸런싱 요약 설계

- 작성일: 2026-08-13
- 상태: 사용자 설계 승인 완료

## 1. 목표

백테스트 위저드의 단계별 종목 수(N) 입력을 리밸런스 주기 입력과 같은 방식으로
보정한다. 사용자는 값을 지우거나 범위를 벗어난 수를 입력할 수 있고, 포커스를 벗어날
때 입력값을 복구하거나 허용 범위로 clamp한다.

백테스트 결과에서는 종목별 성과를 제거한다. 기존 「유니버스 단계 진단」은
「종목 리밸런싱」으로 바꾸고, 단계별 통과 정보 대신 리밸런스 사이에 편입·편출된 종목
수를 보여준다.

## 2. 단계별 N 입력

`UniverseStage.limit`에는 계속 유효한 정수만 저장한다. 각 N 입력은 별도의 문자열
초안을 두어 편집 중인 값과 도메인 상태를 분리한다.

- 입력 중에는 빈 문자열과 범위 밖 정수를 그대로 표시한다.
- 현재 단계의 허용 범위 안에 있는 정수는 즉시 `UniverseStage.limit`에 반영한다.
- 빈 문자열, 정수가 아닌 값, 범위 밖 정수는 편집 중에는 도메인 상태를 바꾸지 않는다.
- 포커스를 벗어날 때 빈 문자열이나 정수가 아닌 값은 그 단계의 직전 유효값으로
  복구한다.
- 포커스를 벗어날 때 `1`보다 작은 정수는 `1`로, 상한보다 큰 정수는 상한으로
  clamp한다.
- 첫 단계 상한은 기존 정책인 `200`이다. 이후 단계 상한은 직전 단계의 확정된 N이다.
- 확정된 값이 앞 단계 N을 줄이면 기존 cascade 규칙으로 뒤 단계 N도 함께 줄인다.
- cascade, 단계 이동, 초안 복원 등 외부 원인으로 단계 값이 바뀌면 입력 문자열도 새
  값에 맞춘다.

리밸런스 주기 입력은 이미 같은 정책을 구현하고 있으므로 동작을 바꾸지 않는다. 단계
입력만 작은 내부 컴포넌트로 분리해 문자열 초안의 생명주기를 단계별로 격리한다.

## 3. 리밸런싱 요약 데이터

서버는 `backtest_jobs.universeScheduleJson`에 제출 시점의 멤버십 일정을 이미 고정해
둔다. 결과 상세 조회 시 이 일정에서 화면에 필요한 요약만 계산한다. 전체 멤버 목록은
브라우저에 보내지 않는다.

요약 응답은 첫 구성과 이후 변경을 구분하는 union으로 표현한다.

```typescript
type UniverseRebalancingEntryDto =
  | {
      kind: 'INITIAL';
      rebalanceDate: string;
      effectiveDate: string;
      memberCount: number;
    }
  | {
      kind: 'CHANGE';
      rebalanceDate: string;
      effectiveDate: string;
      addedCount: number;
      removedCount: number;
      changedCount: number;
    };
```

첫 일정은 비교 대상이 없으므로 `INITIAL`이며 현재 멤버 수만 센다. 이후 일정은 직전
일정과 현재 일정의 종목 code 집합을 비교한다.

- `addedCount`: 현재 집합에만 있는 종목 수
- `removedCount`: 직전 집합에만 있는 종목 수
- `changedCount`: `addedCount + removedCount`

이 정의에서는 최종 유니버스 크기가 변하면 편입 수와 편출 수가 달라질 수 있다. 상장·
거래 가능 여부, 선정 지표 결측, 단계별 적격 종목 부족이 유니버스 크기를 바꿀 수 있다.

요약 계산은 저장된 일정 순서를 그대로 따른다. 멤버 수는 배열 길이가 아니라 code
집합 크기로 계산해 손상된 중복 항목이 수를 부풀리지 않게 한다. 일정 JSON을 파싱할 수
없으면 상세 조회 전체를 실패시키지 않고 요약을 빈 배열로 내리며 서버 로그에 경고를
남긴다. 일정이 비어 있으면 결과 화면에서 섹션을 숨긴다.

별도 DB migration이나 provenance pin 변경은 하지 않는다. 따라서 현재 저장 형식을 쓰는
기존 백테스트 결과도 같은 요약을 볼 수 있다.

## 4. 결과 화면

`SymbolPerformanceSection`과 그 렌더링을 제거한다. `series.symbols`는 거래 종목 이름과
거래 내역 필터에 계속 필요하므로 API 응답에서는 제거하지 않는다.

기존 진단 카드의 이름과 페이지 이동 접근성 문구를 모두 「종목 리밸런싱」으로 바꾼다.
표는 다음 세 열만 둔다.

1. 리밸런스일
2. 기준일
3. 변동 종목 수

첫 행은 `최초 구성 N종목`으로 표시한다. 이후 행은
`합계 N종목 (편입 A · 편출 B)` 형태로 표시한다.

- 합계와 일반 문구는 기본 글자색을 쓴다.
- 편입 숫자는 한국 주식 화면의 상승 색인 `text-gain` 빨간색을 쓴다.
- 편출 숫자는 하락 색인 `text-loss` 파란색을 쓴다.
- `편입`과 `편출` 문구를 항상 함께 표시해 색상만으로 의미를 전달하지 않는다.
- 기준일이 리밸런스일과 다르면 기존처럼 `(휴장 조정)`을 붙인다.
- 단계별 통과 수와 기준별 이름은 화면에서 완전히 제거한다. provenance pin에는 재현
  정보로 계속 보존한다.

## 5. 테스트

테스트는 다음 회귀를 검증한다.

- 단계 N을 지운 동안 빈 문자열을 유지하고 새 값을 이어서 입력할 수 있다.
- 범위보다 큰 N과 `0`은 편집 중 그대로 보이고 blur에서 각각 상한과 `1`로 clamp된다.
- 유효값을 입력한 뒤 지우고 blur하면 직전 유효값을 복원한다.
- 앞 단계의 clamp 결과가 뒤 단계 상한보다 작으면 기존 cascade가 적용된다.
- 첫 일정은 최초 구성 수를 반환한다.
- 같은 크기의 교체, 유니버스 증가·감소, 변경 없음에서 편입·편출·합계가 정확하다.
- 결과 상세 API는 멤버 원문 대신 리밸런싱 요약을 반환한다.
- 결과 화면에 「종목 리밸런싱」과 색상·문구가 표시되고 단계별 통과 정보와
  「종목별 성과」는 보이지 않는다.
- 기존 기간 정합성, 미리보기, 거래 내역, provenance 표시가 계속 동작한다.
