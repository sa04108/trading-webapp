# 유니버스 단계 방향 선택과 ROE 설계

## 1. 목표

백테스트 위저드의 유니버스 단계마다 정렬 방향을 명시적으로 고르게 한다. 현재 서버가
기준별 방향을 고정해서 정하는 동작을 없애고, 사용자가 고른 방향을 요청과 결과 요약에
남긴다. ROE 기준도 추가한다.

방향 문구는 숫자 정렬 용어가 아니라 기준에 맞는 말로 표시한다. 드롭다운에서는 일반적으로
유리하다고 여기는 방향을 먼저 보여주고 새 단계의 기본값으로 쓴다.

| 기준 | 첫 번째 방향 | 두 번째 방향 |
|---|---|---|
| 시가총액 | 상위 | 하위 |
| 거래량 | 상위 | 하위 |
| 거래대금 | 상위 | 하위 |
| PER | 낮음 | 높음 |
| ROE | 높음 | 낮음 |
| 가격 변동 | 급상승 | 급하락 |

## 2. 선택한 구조

기준과 방향을 별도 값으로 저장한다. 각 `UniverseStage`는 `criterion`, `direction`,
`limit`을 가진다. `direction`은 수치가 큰 종목부터 고르는 `HIGH`와 작은 종목부터
고르는 `LOW` 두 값만 쓴다. 화면이 기준에 따라 `HIGH`와 `LOW`를 위 표의 문구로 바꾼다.

이 구조는 같은 랭킹 코드를 모든 기준에 쓸 수 있고 요청만 보아도 선택 방향을 알 수 있다.
`시가총액 상위`, `시가총액 하위`처럼 조합마다 criterion을 만드는 방식은 기준 목록과 서버
분기를 늘리므로 쓰지 않는다. `오름차순`, `내림차순` 같은 공통 문구도 사용자에게 선택
결과를 바로 설명하지 못하므로 쓰지 않는다.

가격 기준의 내부 criterion 식별자 `DECLINE`은 저장 요청과 실행 기록 호환성을 위해
유지한다. 화면에서만 기준 이름을 `가격 변동`으로 바꾼다. `HIGH`는 급상승,
`LOW`는 급하락을 뜻한다.

기준이 여섯 개로 늘어나므로 단계 상한도 5개에서 6개로 올린다. 같은 criterion을 두 번
쓸 수 없고 다음 단계의 N은 직전 단계의 N 이하여야 한다는 기존 불변식은 유지한다.

## 3. 위저드 동작

각 단계 행을 `기준 → 방향 → N → 기준별 추가 입력` 순서로 배치한다. 가격 변동 단계에는
기존 조회기간 입력을 그대로 표시한다.

- 새 단계는 표의 첫 번째 방향으로 만든다.
- 기준을 바꾸면 방향도 새 기준의 첫 번째 방향으로 초기화한다.
- 방향만 바꾸면 criterion, N, 조회기간과 단계 순서는 바꾸지 않는다.
- 기준별 방향 드롭다운은 항상 두 옵션을 모두 보여준다.
- `급하락 단계 추가` 문구는 `가격 변동 단계 추가`로 바꾼다.
- 신규 위저드 기본 규칙은 `시가총액 / 상위 / 200`이다.

검토 화면, 백테스트 목록, 상세 화면의 규칙 요약에도 방향을 포함한다. 예시는
`KOSPI · 시가총액 상위 200 → PER 낮음 80 → ROE 높음 40 · 매월`이다.

## 4. 요청 계약과 과거 데이터 호환성

공유 스키마에 `ROE` criterion과 `HIGH | LOW` 방향을 추가한다. 신규 위저드가 만드는 모든
단계는 방향을 명시한다.

방향 필드가 없던 기존 요청은 파싱 경계에서 다음처럼 보정한다. 이 기본값은 기존 서버의
고정 정렬과 같으므로 저장된 규칙의 의미가 바뀌지 않는다.

| 기존 criterion | 보정 방향 |
|---|---|
| `MARKET_CAP` | `HIGH` |
| `VOLUME` | `HIGH` |
| `TRADING_VALUE` | `HIGH` |
| `PER` | `LOW` |
| `DECLINE` | `LOW` |

복제 초안과 워커는 스키마 파싱 결과를 받아 명시적인 방향으로 실행한다. 목록과 상세처럼
기존 JSON을 바로 표시하는 경로의 요약 함수도 같은 보정 규칙을 사용한다. 기존 완료 결과를
마이그레이션하거나 다시 계산하지 않는다.

## 5. 서버 랭킹과 데이터 흐름

랭킹은 criterion에 방향을 하드코딩하지 않는다. 결측을 제외한 뒤 `HIGH`면 큰 값부터,
`LOW`면 작은 값부터 정렬하고 N개를 남긴다. 값이 같으면 지금처럼 단축코드 오름차순으로
결정해 실행 환경과 무관한 결과를 만든다.

- 시가총액, 거래량, 거래대금은 기존 선정 지표를 쓴다.
- PER는 PIT 시점의 시가총액을 TTM 순이익으로 나눈다. 시가총액과 순이익이 모두 양수인
  종목만 적격이다.
- ROE는 PIT 시점의 TTM 순이익을 자본총계로 나눈다. 순이익과 자본총계가 모두 양수인
  종목만 적격이다. `ROE 낮음`도 이 양수 집합 안에서 작은 값부터 고른다.
- 가격 변동은 기존처럼 조회기간의 split-adjusted 수익률을 쓴다. `HIGH`는 수익률이 큰
  급상승 종목, `LOW`는 수익률이 작은 급하락 종목을 고른다.

PER와 ROE는 같은 재무 coverage와 PIT fact 조회 경로를 사용한다. 유니버스 준비 계획은 둘
중 하나가 있으면 4분기 재무를 요구한다. ROE 계산에 필요한 `NET_INCOME`과
`TOTAL_EQUITY`가 준비 후에도 없거나 유효하지 않으면 해당 종목을 결측으로 제외한다.
가격 변동 방향은 조회기간과 필요한 가격·자본변동 준비 범위를 바꾸지 않는다.

단계 진단에는 criterion과 함께 direction을 남겨 저장된 규칙과 실제 랭킹을 대조할 수 있게
한다. 결측 제외 수, 입력 수, 적격 수, 선정 수의 뜻은 바꾸지 않는다.

## 6. 오류 처리와 경계 조건

- 알 수 없는 criterion이나 direction은 요청 스키마에서 거부한다.
- 같은 기준을 두 번 쓰거나 7개 이상 단계를 만들면 거부한다.
- 방향을 바꿔도 단계별 N cascade는 실행하지 않는다.
- PER와 ROE의 0, 음수, 비유한 값, 재무 결측은 적격 집합에서 제외한다.
- 가격 이력이 조회기간보다 짧거나 조정 근거가 부족한 종목은 기존 정책대로 제외한다.
- 적격 종목이 N보다 적으면 가능한 종목만 남기고 진단의 실제 선정 수를 기록한다.

## 7. 검증

구현은 테스트를 먼저 실패시킨 뒤 최소 변경으로 통과시킨다.

1. 공유 스키마가 여섯 기준, 명시적 양방향, 최대 여섯 단계와 legacy 방향 보정을 검증한다.
2. 순수 랭킹 테스트가 모든 기준의 `HIGH`와 `LOW`, 동률, 결측을 검증한다.
3. resolver 테스트가 ROE의 PIT TTM 순이익·자본총계 계산, 양수 필터, 양방향 선정을 검증한다.
4. 준비 계획 테스트가 ROE 단계에 4분기 재무를 요구하는지 검증한다.
5. 편집기 테스트가 기준별 옵션 순서, 기준 변경 시 기본 방향, 여섯 번째 단계 추가를
   검증한다.
6. 요약 테스트가 방향 문구와 방향 없는 기존 규칙의 문구를 검증한다.
7. 통합 미리보기 테스트가 ROE 단계의 데이터 준비와 최종 종목을 검증한다.
8. Playwright 시나리오가 방향 선택, 가격 변동 문구, 복제 시 방향 복원을 검증한다.

## 8. 범위 밖

ROE의 산식이나 공시 신선도 임계값을 사용자가 바꾸는 기능은 넣지 않는다. 방향별로 별도
N을 저장하거나 한 단계에서 여러 기준을 합산하는 기능도 넣지 않는다. 기존 완료 백테스트의
유니버스와 결과는 다시 계산하지 않는다.
