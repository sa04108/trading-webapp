# KRX 과거 유니버스 정렬 기준·선택 버튼·데이터셋 기록 설계

- 날짜: 2026-08-04
- 상태: 승인됨
- 범위: 백테스트 위저드 "데이터·종목" 단계의 과거 기준일 조회 흐름

## 배경

과거 기준일 조회는 현재 시가총액 내림차순 rank 하나로 고정돼 있다.
선택 UI도 「시가총액 상위 200종목 선택」 버튼 하나뿐이다.
스냅샷은 백테스트 위저드 안에서만 소비되고, 데이터 화면의 데이터셋으로는 남지 않는다.

## 요구사항

1. 과거 기준일 조회에 정렬 기준을 둔다: 시가총액 상위, 영업이익 상위, PER 상위, PBR 상위, EV/EBITDA 상위.
2. 조회 결과 화면에서 「시가총액 상위 200종목 선택」 버튼을 지우고 「페이지 선택」·「전체 선택」을 넣는다.
3. 스냅샷 생성 시 데이터셋으로도 기록한다. 기준 시점과 정렬 기준을 명시한다.
   현시점 기준 상장폐지 등으로 사라진 종목은 데이터셋 카드 하단에만 표시하고 종목 편집에서는 찾을 수 없게 한다.

## 확정된 결정

| 결정 | 내용 |
|---|---|
| 지표 범위 | 시가총액·영업이익만 실동작. PER·PBR·EV/EBITDA는 드롭다운에 비활성으로 노출하고 "데이터 준비 중" 표기. 지표 수집은 후속 작업 |
| 정렬 위치 | 서버 정렬. preview 요청에 `sortBy` 파라미터, 서버가 rank 부여 |
| 상장폐지 판정 | KRX 기본정보(현재 상장 목록)를 하루 1회 캐시 조회해 diff |
| 전체 선택 범위 | 검색 필터가 적용된 후보 전체 |
| 데이터셋 기록 | 스냅샷 확정 시 항상 자동 생성 |

## 설계

### 1. 정렬 기준

**API**: `POST /universe/historical/preview` 요청 본문에 `sortBy` 필드를 추가한다.

- 값: `'MKTCAP' | 'OPERATING_INCOME'` (zod enum). 생략 시 `MKTCAP` — 기존 클라이언트와 호환된다.
- 비활성 3종(PER·PBR·EV/EBITDA)은 서버 enum에 넣지 않는다. 데이터가 생길 때 확장한다.

**영업이익 rank 산출**:

- DuckDB로 `facts/scope=SYMBOL/symbol=*/data.parquet`를 일괄 스캔한다.
  조건: `field = 'OPERATING_INCOME'`, 공시 `as_of_ts_ms ≤ 기준일`.
- point-in-time 규칙과 TTM 4분기 합산은 `value-quality-rank` 전략과 동일하게 맞춘다.
  전략 쪽 계산 로직을 공용 모듈로 추출해 양쪽이 같은 코드를 쓴다.
- 영업이익을 산출할 수 없는 종목(미수집·분기 부족)은 rank null로 목록 뒤에 둔다.
- 요약 카드에 "영업이익 데이터 없는 종목 N개"를 표시한다.

**캐시·해시**: preview TTL 캐시 키와 canonicalPayload에 `sortBy`를 포함한다.
`candidateCanonicalHash`가 정렬 기준까지 재현성 범위에 넣는다.

**프론트** (`krx-snapshot-step.tsx`):

- 조회 카드에 정렬 Select를 추가한다. 항목 5종, 뒤 3종은 disabled + "데이터 준비 중".
- 후보 행의 보조 정보는 선택한 정렬 기준의 값을 보여준다
  (시가총액 정렬이면 시가총액, 영업이익 정렬이면 영업이익).

### 2. 선택 버튼 개편

- 「시가총액 상위 200종목 선택」 버튼과 `selectTopN()` 경로를 제거한다.
  `topNCodes()`는 서버 검증·방식 판정에 남는다.
- 추가 버튼:
  - 「페이지 선택」: 현재 페이지 후보를 토글한다. 페이지 전체가 이미 선택돼 있으면 해제한다.
  - 「전체 선택」: 검색 필터가 적용된 후보 전체를 선택한다.
  - 「전체 해제」: 선택을 비운다.
- 200종목 초과 경고는 유지한다. 스냅샷 확정은 허용하고 백테스트 제출은 서버가 차단한다(기존 동작).
- `selectionMethodOf`: sortKey가 `MKTCAP`일 때만 상위 N 일치 판정(`TOP_MARKET_CAP_N`)을 한다.
  다른 정렬 기준에서는 항상 `MANUAL_FROM_KRX_SNAPSHOT`이다 — 영업이익은 미수집 종목이 많아
  "상위 N"이라는 주장 자체가 데이터 보유 종목 안에서만 참이고, 상위 N 버튼도 없어졌으므로
  새 방식 값(`TOP_SORT_N`)을 만들지 않는다. 서버도 `TOP_MARKET_CAP_N` 요청이
  MKTCAP 정렬이 아닌 preview를 가리키면 400으로 거부한다.
- 상위 N 방식은 MKTCAP 정렬에서만 성립하므로 provenance 라벨("시가총액 상위 N종목" / "수동 선택")은
  기존 그대로다. 위저드의 「기존 스냅샷 다시 쓰기」 목록에는 sortKey 라벨("영업이익순" 등)을 함께 표기한다.

### 3. 스냅샷 → 데이터셋 자동 기록

- `universe_snapshots.sortKey` 값을 `'MKTCAP' | 'OPERATING_INCOME'`으로 확장한다.
  기존 행은 `MKTCAP` 그대로다.
- `datasets`에 `universe_snapshot_id`(nullable, FK → universe_snapshots) 컬럼을 추가한다.
  마이그레이션 1건.
- `createFromPreview()` 트랜잭션 안에서 데이터셋과 dataset_symbols를 함께 생성한다.
  스냅샷 생성과 데이터셋 기록은 원자적이다.
- 기준 시점·정렬 기준은 데이터셋에 중복 저장하지 않고 스냅샷 join으로 읽는다.
- 데이터셋 이름은 자동 생성한다: `KRX {적용거래일} {정렬 라벨}순 {N}종목`
  (예: `KRX 2020-06-15 영업이익순 150종목`). "상위"라고 쓰지 않는다 — 수동 선택 스냅샷은
  상위 N이 아니다. 이름이 겹치면 ` (2)`, ` (3)` 접미를 붙인다.
- 데이터셋 카드에 배지 2개를 단다: 기준 시점(적용거래일), 정렬 기준.
  스냅샷 연결이 없는 일반 데이터셋은 기존 표시 그대로다.

### 4. 현시점 조회 불가(상장폐지 등) 종목

- 신규 서비스를 만들지 않는다 — `HistoricalUniverseService.currentStandardCodeMap()`이
  이미 KRX 기본정보(`stk_isu_base_info` + `ksq_isu_base_info`)로 현재 상장 목록을 만들어
  TTL 6시간으로 캐시한다. 여기에 `currentShortCodes()`(키 집합 반환)를 추가해 재사용한다.
  호출량 상한 의도(하루 몇 회 이내)는 6시간 캐시로도 지켜진다.
- 스냅샷 연결 데이터셋을 조회할 때 종목별 `listed: boolean`을 부여한다.
- 데이터셋 카드 하단에 "현재 상장 목록에 없는 종목 N개"를 접이식으로 표시한다.
  폐지 사유는 알 수 없으므로 "상장폐지"로 단정하지 않는다.
- `EditSymbolsDialog`(종목 편집)에서는 해당 종목을 목록에서 제외한다. 선택·해제 대상이 아니다.
  종목 패널 등 다른 화면은 건드리지 않는다.
- KRX 조회가 실패하면 diff를 생략하고 전 종목을 정상 표시한다. 서버 로그만 남기고
  카드 렌더는 차단하지 않는다.

## 오류 처리

- preview `sortBy` 검증 실패: 400 (zod).
- 영업이익 facts 스캔 실패: 502로 실패시키고 사유를 알린다. MKTCAP으로 조용히 폴백하지 않는다.
  사용자가 요청한 것과 다른 정렬 기준으로 스냅샷을 만들 위험이 있기 때문이다.
- listing-status 조회 실패: 위 4절의 폴백(전 종목 정상 표시 + 로그).
