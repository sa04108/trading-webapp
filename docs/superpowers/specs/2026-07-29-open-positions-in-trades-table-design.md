# 거래 내역 테이블에 미청산 포지션 통합 — 설계

날짜: 2026-07-29
브랜치: feat/uiux
선행 작업: c514e58 (미청산 포지션을 별도 카드로 노출)

## 문제

백테스트 결과의 "거래 내역"에는 청산(완결)된 거래만 나온다. 미청산 포지션도
매수가 실제로 일어난 것이므로, 사용자는 거래 내역에서 모든 진입을 한눈에
보기를 기대한다. c514e58 로 별도 "미청산 포지션" 카드를 추가했지만, 사용자
피드백은 분리된 카드가 아니라 거래 내역 테이블 안에서 함께 보는 것.

## 결정

- 미청산 포지션 행을 **거래 내역 테이블에 통합**하고, 별도 "미청산 포지션"
  카드(`OpenPositionsSection`)는 **제거**한다.
- **프론트 전용 변경.** 서버·DB·엔진·export 무변경 (ENGINE_VERSION 유지).
  상세 페이지가 이미 가진 `run.openPositionsJson` 을 `TradesSection` 에
  전달해 클라이언트에서 병합 렌더링한다.

## 렌더링 규칙

- 미청산 행은 **첫 페이지(page 0)에서만**, 청산 거래 위에 고정 표시한다.
  미청산은 많아야 종목 수(수십 건 이하)라 페이지네이션에 끼워 넣지 않는다.
  페이지네이션 계산(limit/offset, 다음 버튼 활성화)에는 영향을 주지 않는다.
- 종목 필터 선택 시 미청산 행에도 동일 필터를 적용한다.
- 청산 거래 0건이어도 미청산이 있으면 "거래가 없습니다" 대신 미청산 행을
  표시한다. 둘 다 없을 때만 빈 상태 문구.

### 컬럼 매핑 (기존 8컬럼 유지)

| 컬럼 | 미청산 행 |
|---|---|
| 종목 | symbol |
| 수량 | quantity |
| 진입 | entryTsMs + avgEntryPrice (청산 거래와 동일 포맷) |
| 청산 | **"미청산" 배지** + 기말 종가(lastPrice). 시각은 표기하지 않음 |
| 순손익 | unrealizedPnl (기말 종가 기준 평가손익, 매도 비용 미반영) |
| 수익률 | returnPct |
| 보유 | `job.request.period.to` − entryTsMs (기간 종료 기준 경과 시간) |
| 사유 | "미청산" |

- 미청산 행은 배지 + 톤 차이(예: muted 배경)로 청산 거래와 시각적으로
  구분한다. 목적: "테이블엔 N+k건인데 거래 수 카드는 N건" 역혼란 방지.

### 설명 문구

기존 카드의 각주를 거래 내역 하단으로 이동:

> 미청산 행의 손익은 기간 종료 시점 종가 기준 평가치입니다 (매도 비용
> 미반영). 누적 수익률·자산 곡선에는 포함되지만 승률·profit factor·거래
> 수에는 포함되지 않습니다.

지표 카드의 "청산 기준" 표기는 유지한다.

  행이 첫 페이지 상단에 표시되는지, 별도 카드가 없는지 확인.
