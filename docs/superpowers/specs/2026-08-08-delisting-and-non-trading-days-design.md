# 상장폐지 청산과 거래불가일 설계

**작성일:** 2026-08-08
**상태:** 승인됨 — 구현 계획 대기

## 배경

유니버스는 시점별로 뽑는데 폐지 처리가 없다. 생존편향 제거가 반쪽에서 멈춰 있다.

종목 마스터가 KRX 스냅샷 diff 로 `DELISTED` 이벤트를 만든다(`symbol-master.ts:64`). 유니버스 규칙은 리밸런스 시점 기준으로 후보를 뽑으므로 나중에 폐지될 종목도 들어간다. 그런데 엔진은 그 종목이 사라진 뒤에도 마지막 종가로 계속 평가한다(`engine.ts:414`, `lastCloseBySymbol.get(symbol) ?? avgEntryPrice`).

폐지 종목을 유니버스에 넣어 놓고 손실은 잡지 않는 상태다. 넣기 전보다 더 낙관적일 수 있다.

`engine.ts:391` 의 경고는 이 동작을 말하지 않는다. 그 문구는 "생존 편향, 공휴일 캘린더, 배당, 권리락은 이 백테스트에서 보정하지 않습니다" 로 시작하는데, 시점별 유니버스 선정이 이미 동작하는 지금은 사실과 어긋난다. 정작 위험한 "폐지 종목을 마지막 종가로 남긴다" 는 한 글자도 없다.

## KRX 실응답 실측 (2026-08-08)

거래정지 종목을 KRX 응답만으로 가려낼 수 있는지 확인했다. `scripts/krx-halt-probe.ts` 로 2021-06-15·2022-02-15 두 날짜를 조회했다.

거래불가 종목의 시그니처가 일정하다.

```
TDD_OPNPRC = TDD_HGPRC = TDD_LWPRC = "0"
TDD_CLSPRC = 직전 종가 (유지)
ACC_TRDVOL = ACC_TRDVAL = "0"
CMPPREVDD_PRC = "0", FLUC_RT = "0.00"
```

신라젠(215600) 종가가 두 날짜 모두 `12100` 이다. 정지 직전 가격이 그대로 박혀 있다. 오스템임플란트(048260)는 2021-06-15 정상(`98000/99500/97400/99400`), 2022-02-15 거래불가로 갈린다. 실제 정지 시점과 맞는다.

예상과 달랐던 것이 둘이다.

**`null` 이 아니라 `"0"` 이다.** 봉 필드가 빈 행은 0행이었다. `writeDailyBars` 의 null 분기(`symbol-master-service.ts:594`)는 타지 않는다. 대신 `isValidCandle` 의 `value <= 0`(`candle.ts:27`)에 걸려 `invalidCount` 로 버려진다. 그 주석이 "가격 4개나 거래량 중 하나라도 null 인 행(거래정지 등)" 이라고 적은 것은 실측과 어긋난다. `high < low` 같은 파싱 버그를 담으려던 통에 정상적인 거래불가일이 대량으로 들어가고 있다.

**거래정지와 무거래를 구분할 수 없다.** 성안(011300)·세기상사(002420) 같은 저유동성 종목이 신라젠과 완전히 같은 모양으로 나온다. KRX 는 무거래일에도 시·고·저를 0 으로 준다. `SECT_TP_NM` 은 정지 표시가 아니다 — 오스템임플란트는 정지 중에도 "우량기업부" 다.

규모는 무시할 수 없다.

| 시장 | 전체 | 거래불가일 | 비율 |
|---|---|---|---|
| KOSPI 2021-06-15 | 927 | 15 | 1.6% |
| KOSDAQ 2021-06-15 | 1505 | 94 | 6.2% |
| KOSPI 2022-02-15 | 941 | 9 | 1.0% |
| KOSDAQ 2022-02-15 | 1542 | 76 | 4.9% |

덤으로 하나 더 나왔다. `LIST_SHRS`·`MKTCAP` 는 정지 중에도 갱신된다. 신라젠 발행주식수가 71,617,125 에서 102,867,125 로 늘고 시총이 8,666억에서 1조 2,447억이 됐다. 종가는 12,100 으로 고정인데 시총만 뛴다. 시가총액 상위 N 유니버스가 이런 종목을 뽑고 있고, 뽑히면 봉이 없어 매수가 체결되지 않는다.

## 범위

이 스펙은 셋을 다룬다.

1. 상장폐지 종목 청산
2. 거래불가일 기록과 반영
3. 실행 경고 문구 정정

셋을 묶는 이유는 하나다. 전부 "봉이 없는 날을 어떻게 볼 것인가" 라는 같은 질문이다. 따로 하면 엔진의 같은 자리를 두 번 고치고 경고 문구를 두 번 쓴다.

후속 작업으로 분리한 것:

| 작업 | 내용 | 이 스펙과의 관계 |
|---|---|---|
| 배당 | DART 배당결정 공시 수집, 현금 반영 | **새 데이터 소스**가 필요해 성격이 다르다 |
| 유상증자 권리락 | DART 파서 확장, 권리락 조정계수 | 독립. 현재 파서는 유상증자·유상감자를 의도적으로 제외한다(`dart-report-parser.ts:461`) |
| 정지 사유·재개 예정일 | KIND 매매거래정지 공시 | 독립. 이 스펙은 사유 없이 "거래 불가" 사실만 다룬다 |
| 과거 지수 구성원 복원 | KOSPI200 편입·편출 이력 | 독립. 시총 상위 N 규칙에는 필요 없다 |
| 장중 손절(B-008) | `fillTiming` 확장 | 독립 |

## 원칙

1. **없는 가격을 만들지 않는다.** KRX 가 준 값만 저장하고 계산한다.
2. **실제 사건을 먼저 반영하고, 모르는 것만 보수적으로 남긴다.** 폐지는 실거래가로 청산하고, 원인 불명은 stale 로 표시한다.
3. **가정을 결과에 남긴다.** 청산·제외·stale 이 몇 건이었는지 화면에 적는다.

## 1. 데이터 계층

### 1.1 `krx_non_trading_days` 테이블

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | integer PK | |
| `date` | text | ISO 날짜 |
| `short_code` | text | 단축코드 |
| `market` | text | KOSPI \| KOSDAQ |
| `last_close` | integer | `TDD_CLSPRC` 원값 |

`(date, short_code)` 에 UNIQUE 인덱스를 건다. 재수집이 UNIQUE 위반으로 죽지 않게 `onConflictDoNothing` 으로 넣는다 — 봉 저장과 같은 규칙이다.

`last_close` 는 **평가용이지 체결 가능 가격이 아니다.** 이 구분이 이 설계의 핵심이고, 테이블을 나눈 이유다. 봉 테이블에 섞으면 청산 코드가 실수로 이 값을 체결가로 쓸 수 있다.

봉 테이블에 flat 봉(`O=H=L=C`)을 채우는 방식은 택하지 않았다. KRX 가 주지 않은 시·고·저를 우리가 지어내게 되고, "없는 가격을 만들지 않는다" 는 원칙과 정면으로 부딪힌다.

### 1.2 판정 조건

```
open == 0 && high == 0 && low == 0 && close > 0 && volume == 0
```

거래정지와 무거래를 나누지 않는다. 실측상 응답이 동일하고, **체결 관점에서 둘은 같은 사건**이기 때문이다. 어느 쪽이든 그날 그 종목은 살 수도 팔 수도 없다.

이 결정을 이름에 담는다. 테이블도 필드도 `halted` 가 아니라 `non_trading` 이다. `HALTED` 라고 부르면 우리가 알지 못하는 것을 안다고 말하는 셈이다.

### 1.3 수집 경로

`writeDailyBars`(`symbol-master-service.ts:604`)가 이미 이 행들을 만나고 있다. 거기서 갈래를 나눈다.

- 거래불가 패턴에 맞으면 → `krx_non_trading_days` 에 기록
- 그 외 `isValidCandle` 실패(`high < low` 등) → 지금처럼 `invalidCount` 로 센다. 이쪽이 진짜 파싱 버그다

새 API 도 새 호출도 없다. 이미 매일 받아 오는 응답에서 버리던 것을 저장할 뿐이다.

같은 커밋에서 `symbol-master-service.ts:594-597` 주석을 고친다. "null 인 행(거래정지 등)" 은 실측과 어긋난다. 주석이 틀린 채로 남으면 다음 사람이 null 분기를 고치려다 헤맨다.

### 1.4 백필

`ingestDate` 는 `isCovered` 게이트가 재수집을 막는다. 그 게이트를 열지 않는다 — 이벤트 재생성 위험을 만들 이유가 없다.

대신 전용 CLI 를 둔다.

```
pnpm cli krx:backfill-non-trading --from 2015-01-01 --to 2026-08-08
```

`fetchDailyTrades` 만 부르고 `krx_non_trading_days` 만 채운다. 이벤트·coverage·봉은 건드리지 않는다. 거래일당 2호출이므로 10년치라도 약 5,000호출로, 엔드포인트당 일일 한도 10,000회 안에 든다.

처리한 날짜 범위를 `krx_non_trading_coverage` 에 남긴다. 행이 없는 날짜가 "거래불가 종목이 없었다" 인지 "아직 모른다" 인지는 이 기록으로만 갈린다. 구조는 `symbol_master_coverage`(`schema.ts:532`)와 같다 — 같은 문제를 이미 그렇게 풀었다.

백필이 끝나기 전에도 배포한다. 채워지지 않은 구간은 "거래불가 정보 없음" 으로 취급하고 결과 경고에 그 구간을 적는다(§4).

## 2. 유니버스 계층

`UniverseRuleResolver.resolve`(`universe-rule-resolver.ts:70`)가 `ranked` 를 만들 때 `effectiveTradingDate` 에 거래불가인 종목을 후보에서 뺀다. 시총이 아무리 커도 그날 살 수 없기 때문이다. 표준 유동성 필터와 같은 취지다.

look-ahead 는 없다. 기준일 종가 시점에 이미 확정된 사실이다.

백필되지 않은 구간에서는 제외가 일어나지 않는다. `krx_non_trading_days` 에 행이 없는 날짜는 "거래불가 종목이 없었다" 가 아니라 "모른다" 다. 둘을 구분하려면 어느 구간이 백필됐는지 알아야 하므로, 백필 CLI 가 처리한 날짜 범위를 기록하고 결과 경고가 그 범위를 읽는다(§4).

제외한 종목 수를 `ResolvedUniverse` 에 리밸런스 날짜별로 담아 결과 화면까지 흘린다. 조용히 빠지면 "왜 이 종목이 후보에 없지" 를 추적할 방법이 없다.

### 결과가 바뀐다

`scheduleHash` 가 달라진다. 같은 규칙·기간이라도 이전 실행과 다른 유니버스가 나온다. 의도된 변경이다.

엔진 버전을 올려 과거 실행과 구분한다. 재현성 요구(스펙 §9.5 "같은 입력·버전·seed는 같은 결과")는 버전이 갈리므로 깨지지 않는다. 과거 실행의 저장된 결과는 그대로 둔다.

## 3. 엔진 계층

워커가 조립해 넘기는 입력이 둘 는다.

- `delistings: ReadonlyMap<symbol, { lastTradableTsMs, lastTradableClose }>`
- `nonTradingDays: ReadonlySet<string>` — 키는 `${symbol}|${tsMs}`

### 3.1 거래 후보에서 빼기

`StrategyBarContext.tradableSymbols`(`strategy.ts:40`)가 이미 있다. 이름 그대로 그 시점에 거래 가능한 종목 집합이다. 매 시점 여기서 그날 거래불가 종목을 뺀다.

전략 코드는 고칠 것이 없고, 엔진의 리스크 검증도 같은 집합을 보므로 매수가 두 겹으로 막힌다. 새 개념이 늘지 않는다.

### 3.2 체결

거래불가일에는 봉이 없어 지금도 주문이 대기한다. 동작은 그대로다. 달라지는 것은 **이유를 안다**는 것뿐이다.

기간 종료 시 "체결되지 않은 주문 N건 폐기" 경고(`engine.ts:364`)에 거래불가로 막힌 건수를 따로 적는다.

### 3.3 평가

`lastCloseBySymbol` 을 거래불가일 `last_close` 로 갱신한다. KRX 가 직전 종가를 그대로 주므로 값은 대개 변하지 않는다.

갱신하는 이유는 값이 아니라 **언제까지 확인된 가격인지**를 기록하기 위해서다. stale 경과일 계산의 기준이 된다.

### 3.4 상장폐지 청산

`delistings` 에 있는 종목은 **마지막 거래 가능 봉 시각**에 그 봉의 종가로 전량 매도한다. 여기서 "마지막 거래 가능 봉" 은 엔진 타임라인에 실제로 들어온 그 종목의 마지막 봉이다 — 거래불가일에는 봉이 없으므로 자연히 제외된다.

청산가로 정리매매 종가를 따로 추정하지 않는다. KRX 일봉에 정리매매 기간 봉이 들어 있어 마지막 거래 가능 봉이 곧 정리매매 최종가다. 시장이 매긴 회수가치를 그대로 쓰는 것이 국내 퀀트 도구의 표준 처리이기도 하다.

- **비용을 정상 매도와 똑같이 적용한다.** 수수료·매도세·슬리피지를 면제하지 않는다. 실제 정리매매 체결이다.
- **거래 내역에 사유 `DELISTED` 를 남긴다.** 전략이 낸 주문이 아닌데 섞이면 승률·평균 보유기간 해석이 어긋난다.
- **청산가는 거래 가능 봉의 종가다.** `krx_non_trading_days.last_close` 는 절대 쓰지 않는다. 신라젠처럼 정지 상태로 폐지된 종목은 정지 **직전** 실거래가로 나간다. 테이블을 나눈 값이 여기서 나온다.
- 백테스트 기간이 폐지일 전에 끝나면 청산하지 않는다. 그 시점에는 아직 폐지가 아니다.

`0원 처리(-100%)` 는 쓰지 않는다. 현금합병·자발적 상장폐지에서 실제보다 훨씬 나쁘게 나온다. 사유별 추정치(CRSP 방식)도 쓰지 않는다 — 종목 마스터에 폐지 사유가 없고, 그것을 넣으려면 KIND 수집이 선행돼야 한다.

### 3.5 `onForcedExit` 훅

`TradingStrategy` 에 선택 훅을 더한다.

```ts
onForcedExit?(symbol: string, state: TState): void;
```

`onCorporateAction`(`strategy.ts:75`)과 같은 자리, 같은 이유다. 전략이 봉 사이에 들고 다니는 스톱 레벨·보유 플래그를 정리하지 않으면 없는 포지션에 매도 주문을 계속 낸다. 구현하지 않는 전략에는 영향이 없다.

### 3.6 look-ahead 방어

폐지 정보는 `StrategyBarContext` 에 넣지 않는다. 엔진만 본다. 전략이 "이 종목이 곧 폐지된다" 를 미리 알 경로가 구조적으로 없어야 한다.

청산 시점을 마지막 거래 가능 봉으로 잡는 것 자체는 "이 봉이 마지막" 이라는 미래 정보를 쓰는 셈이다. 그래도 유리해지는 방향이 아니다 — 정리매매 최종가는 그 구간에서 가장 낮은 축이고, 정리매매 종료일은 사전 공시되므로 현실에서도 알 수 있다.

## 4. 결과 표시와 경고

지금 경고는 네 항목을 한 문장에 뭉쳐 놨다(`engine.ts:391`). 상태가 갈렸으니 쪼갠다.

**"생존 편향" 이라는 단일 라벨을 버린다.** 부분 보정 상태라 예/아니오로 말할 수 없다. `universe-provenance.ts:19-21` 이 이미 같은 이유로 "생존자 편향 제거" 표현을 금지하고 있다. 같은 규칙을 실행 경고에도 적용해 구성 요소별로 적는다.

- **보정한다:** 시점별 유니버스 선정, 상장폐지 청산, 거래불가일 체결 금지, 액면분할(자본변동을 수집한 데이터셋에서)
- **보정하지 않는다:** 배당, 유상증자 권리락, 공휴일 캘린더, 과거 지수 구성원 복원
- **이번 실행의 사실:** 폐지 청산 건수와 손익, 유니버스 제외 건수, 미청산 stale 건수(자산 비중과 마지막 확인일로부터 경과일), 거래불가 정보가 백필되지 않은 구간

마지막 줄이 중요하다. 백필 전에는 "거래불가일을 반영한다" 고 적으면서 실제로는 데이터가 없는 구간이 생긴다. 그 구간을 밝히지 않으면 경고가 다시 거짓말을 한다.

`docs/IMPLEMENTATION_STATUS.md:41` 의 "배당·생존 편향 미보정" 줄도 같은 기준으로 고친다.

## 6. 테스트

**단위**
- 거래불가 판정 조건 — 실측 원문(신라젠·오스템임플란트·성안)을 fixture 로 쓴다
- 정상 봉과 `high < low` 파싱 버그가 거래불가로 잘못 분류되지 않는지
- 청산가와 비용 계산 — 수수료·매도세·슬리피지가 정상 매도와 같은지
- `tradableSymbols` 에서 거래불가 종목이 빠지는지
- `onForcedExit` 가 청산 시점에 불리는지

**통합**
- 폐지 종목이 든 백테스트에서 **실제 청산 체결이 나오는지**. `backtest-universe-rule-run.test.ts:403` 이 "생존편향 제거가 실제로 동작한다" 를 체결로 검증하는 것과 같은 방식이다
- 정지 상태로 폐지된 종목이 **정지 직전가**로 청산되는지. 거래불가일 종가를 쓰면 실패해야 한다
- 거래불가 종목이 시총 상위 N 에 있어도 유니버스에 들어오지 않는지

**e2e**
- 결과 화면에 청산·제외·stale 건수가 표시되는지

`BACKTEST_BIAS_REVIEW.md` 기준으로 남는 항목이다. 경고 문구가 이것들을 계속 밝혀야 한다.

- **B-004~B-006** OOS 분리, 시도 횟수 표시, 신뢰구간
- **B-008** 손절을 종가로만 판정한다
- **P-001 의 사유 구분** — `HALTED` 와 `NO_TRADE` 를 나누려면 KIND 공시가 필요하다
- **미체결 주문 경고의 거래불가 분해**(§3.2) — 기간 종료 시 폐기되는 주문 중 몇 건이
  거래불가일에 막힌 것인지는 따로 세지 않는다. 구현하려면 주문마다 대기 사유를
  들고 다녀야 하는데, 그 상태는 체결 로직 전체에 번진다. 지금은 폐기 건수만 적는다
- 배당, 유상증자 권리락
- 다음 봉 시가 체결 가정 — 시가가 상한가면 현실에서는 살 수 없다. 유동성·시장충격 제약도 없다
