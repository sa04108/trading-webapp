# 백테스트 리밸런스 주기 입력 보정 설계

- 작성일: 2026-08-12
- 상태: 사용자 설계 승인 완료

## 1. 목표

백테스트 유니버스 단계의 리밸런스 주기 입력에서 편집 중인 문자열과 실제 백테스트
설정값을 분리한다. 사용자는 기존 값을 지우고 새 값을 입력할 수 있으며, 허용 범위를
벗어난 정수는 포커스를 벗어날 때만 단위별 범위로 보정한다.

## 2. 원인

현재 입력은 `UniverseRule.rebalanceInterval.value`를 그대로 표시하는 제어 입력이다.
`onChange`는 빈 문자열을 `0`으로 변환한 뒤 범위 밖 값이라 버린다. 부모 상태에는 기존
값 `1`이 남으므로 다음 렌더에서 입력창도 즉시 `1`로 돌아가며, 사용자는 값을 지운 뒤
다른 숫자를 입력할 수 없다.

## 3. 선택한 접근

`UniverseRuleStep`에 리밸런스 주기 입력 전용 문자열 상태를 둔다. 백테스트 도메인
상태인 `UniverseRule`에는 계속 유효한 정수만 저장한다.

- 입력할 때는 문자열 상태를 항상 갱신해 빈 문자열과 범위 밖 정수를 그대로 보여준다.
- 입력값이 현재 단위의 범위 안에 있는 정수이면 부모의 `UniverseRule`에도 즉시 반영한다.
- 입력값이 범위 밖이거나 비어 있으면 편집 중에는 부모 상태를 바꾸지 않는다.
- 단위 변경이나 초안 복원처럼 외부에서 `rebalanceInterval`이 바뀌면 문자열 상태를
  해당 값과 동기화한다.

비제어 입력은 외부 값 동기화가 복잡해지므로 사용하지 않는다. 부모 상태에 문자열이나
범위 밖 값을 저장하는 방식도 요청 스키마와 미리보기 계산에 유효하지 않은 값이 섞이므로
사용하지 않는다.

## 4. 포커스 이탈 처리

포커스를 벗어날 때 다음 순서로 입력을 확정한다.

1. 빈 문자열 또는 정수로 해석할 수 없는 값이면 직전 유효한 부모 값을 복원한다.
2. 정수가 최솟값 `1`보다 작으면 `1`로 보정한다.
3. 정수가 현재 단위의 최댓값보다 크면 해당 최댓값으로 보정한다.
4. 범위 안 정수는 그대로 확정한다.

보정하거나 확정한 값은 입력 문자열과 부모 `UniverseRule`에 함께 반영한다. 단위별
최댓값은 기존 정책인 일 `365`, 주 `52`, 개월 `12`, 년 `1`을 유지한다. 년 입력은
기존처럼 비활성화하고 값 `1`을 유지한다.

## 5. 테스트

브라우저 테스트에서 실제 입력 동작을 검증한다.

- 기본값 `1`을 지운 동안 입력창이 빈 상태를 유지하고, 이어서 `3`을 입력할 수 있다.
- 개월 단위에서 `99`는 편집 중 그대로 보이며 포커스를 벗어나면 `12`가 된다.
- `0`은 편집 중 그대로 보이며 포커스를 벗어나면 `1`이 된다.
- 유효값을 입력한 뒤 다시 지우고 포커스를 벗어나면 직전 유효값이 복원된다.
- 기존 리밸런스 기간 정합성, 단위 변경, 미리보기 흐름 테스트가 계속 통과한다.

## 6. 범위 밖

- 유니버스 단계의 다른 숫자 입력 동작 변경
- 서버 요청 스키마와 단위별 허용 범위 변경
- 리밸런스 주기와 전체 백테스트 기간의 정합성 정책 변경
