# 공통 게시판형 페이지 이동 설계

날짜: 2026-08-01  
상태: 승인됨 (구현 전)

## 목표

기존 프론트엔드 페이징 UI를 게시판형 페이지 이동으로 바꾼다. 처음·이전·페이지
번호·다음·마지막 버튼을 한 줄에 놓는다. 화면 너비에 맞춰 페이지 번호를 5·7·9개
표시하고, 현재 페이지를 번호 창의 가운데에 둔다.

같은 UI와 계산 규칙을 공통 코드로 모은다. 서버 페이징과 클라이언트 페이징은 데이터
조회 방식만 유지하고 이동 UI는 공유한다.

## 범위

다음 사용자 노출 위치를 바꾼다.

- 데이터 화면의 종목 목록
- 데이터셋 만들기의 종목 선택 목록
- 데이터셋 편집의 종목 선택 목록
- 백테스트 상세의 거래 내역
- 백테스트 상세의 경고 목록

다음 항목은 바꾸지 않는다.

- 백테스트 전략·결과 목록
- 새 백테스트 위저드의 단계 이전·다음 버튼
- 대시보드 최근 결과, 데이터셋 카드 종목 요약, 종목명 요약처럼 일부 항목만 접는 UI
- 서버 API, DB 스키마, URL query parameter
- 각 화면의 기본 페이지당 표시 수와 검색·정렬·필터 동작

## 현재 구조

종목 목록 두 종류는 `features/datasets/symbol-list.tsx`의 `PageNav`와
`PageSizeInput`을 공유한다. 페이지 범위는 `features/datasets/symbol-paging.ts`의
`pageWindow`가 계산한다.

거래 내역과 경고 목록은 `backtest-detail-page.tsx` 안에 이전·다음 버튼을 각각
구현한다. 거래 내역은 서버의 `limit`·`offset`을 쓰고, 경고 목록과 종목 목록은 받은
배열을 클라이언트에서 자른다. 네 구현 모두 내부 페이지 상태는 0부터 시작하며 화면에는
1부터 표시한다.

## 선택한 방식

공통 controlled `Pagination` 컴포넌트와 순수 계산 함수를 만든다. 소비자는 현재 페이지,
전체 페이지 수, 변경 callback만 넘긴다. 이 구조는 서버·클라이언트 페이징을 같은 UI로
표현하면서 데이터 조회 책임을 각 화면에 남긴다.

화면별 UI를 유지하고 계산 함수만 공유하는 방식은 제외한다. 버튼 배치와 접근성 속성이
다시 갈라질 수 있다. CSS breakpoint마다 전체 버튼 묶음을 중복 렌더링하는 방식도
제외한다. 보이지 않는 내비게이션이 DOM에 함께 남고 같은 제어를 여러 번 만든다.

## 공통 계산

`src/web/lib/pagination.ts`가 다음 계산을 맡는다.

- `pageWindow(total, pageSize, page)`
  - 기존 동작을 옮긴다.
  - 전체 페이지 수를 최소 1로 유지한다.
  - 목록이 줄면 유효한 마지막 페이지로 `currentPage`를 제한한다.
  - `from`과 `to`를 계산한다.
- `visiblePageNumbers(currentPage, pageCount, maxVisible)`
  - 0-based `currentPage`를 받고 화면에 표시할 연속된 1-based 페이지 번호를 반환한다.
  - 전체 페이지 수가 `maxVisible` 이하면 모든 번호를 반환한다.
  - 중간 구간에서는 현재 페이지가 정확히 가운데에 온다.
  - 처음과 마지막 부근에서는 번호 창을 각각 1페이지와 마지막 페이지에 붙인다.
- `pageNumberLimitForWidth(width)`
  - 너비가 640px 미만이면 5를 반환한다.
  - 너비가 640px 이상 1024px 미만이면 7을 반환한다.
  - 너비가 1024px 이상이면 9를 반환한다.

홀수 개수만 쓰므로 중간 구간에서 현재 페이지를 한 칸으로 확정할 수 있다. 페이지가
100개이고 최대 9개를 표시한다면 현재 50페이지의 번호 창은 46~54이다. 현재 2페이지는
1~9, 현재 99페이지는 92~100을 표시한다. 생략 부호는 넣지 않는다.

## 공통 UI

`src/web/components/pagination.tsx`에 다음 컴포넌트를 둔다.

### `Pagination`

필수 입력은 `currentPage`, `pageCount`, `onPageChange`이다. 내부 값은 기존 호출부와 같은
0-based를 쓴다. 선택적 전체 항목 정보는 `{ count, unit }` 형태로 받아 `총 N종목`처럼
표시한다. `ariaLabel`로 각 목록의 내비게이션 이름을 구분한다.

컴포넌트는 브라우저 너비 변화를 구독하고 공통 계산 함수로 5·7·9개 번호를 만든다.
너비를 아직 읽지 못한 첫 렌더에서는 가장 좁은 기준인 5개를 사용한다. resize는 현재
페이지를 바꾸지 않고 보이는 번호 개수만 바꾼다.

버튼 순서는 다음과 같다.

```text
[<<] [<] 1 2 3 4 5 [>] [>>]
```

- `<<`, `<`, `>`, `>>`는 lucide의 이중·단일 꺾쇠 아이콘을 쓴다.
- 버튼의 접근성 이름은 `첫 페이지`, `이전 페이지`, `다음 페이지`, `마지막 페이지`이다.
- 번호 버튼의 접근성 이름은 `N페이지로 이동`이다. 현재 번호는 `현재 N페이지`이다.
- 현재 페이지는 굵게 표시하고 `aria-current="page"`를 붙인다.
- 첫 페이지에서는 처음·이전 버튼을 비활성화한다.
- 마지막 페이지에서는 다음·마지막 버튼을 비활성화한다.
- 변경 callback에 넘기기 전에 목표 페이지를 유효 범위로 제한한다.
- 전체가 한 페이지뿐이면 내비게이션을 그리지 않는다.
- 390px 지원 화면에서 한 줄을 유지하고 가로 overflow를 만들지 않는다.

### `PageSizeInput`

`value`, `onChange`, 접근성 `label`, `unit`을 받는다. `unit`은 `종목` 또는 `건`이다.
입력의 min·max는 기존과 같은 1·200을 유지한다. 문자열 파싱은 기존
`parsePageSize`가 계속 맡는다.

## 소비자별 데이터 흐름

### 종목 목록과 데이터셋 종목 선택

검색·정렬 결과를 공통 `pageWindow`로 자른다. 페이지당 표시 수나 검색·정렬 조건이
바뀌면 기존처럼 첫 페이지로 돌아간다. 검색으로 목록이 줄어 현재 페이지가 사라지면
`pageWindow`가 마지막 유효 페이지를 화면에 표시한다. 검색을 지우면 원래 페이지 상태를
복원하는 기존 규칙도 유지한다.

종목 목록은 선택적 전체 항목 정보로 필터 결과의 `총 N종목`을 표시한다. 데이터셋 생성과
편집은 같은 `SymbolCheckList`를 쓰므로 한 번의 변경으로 함께 적용된다. 페이지내 전체
선택은 현재 `from`·`to` 범위를 계속 사용한다.

### 경고 목록

묶기 적용 뒤 만들어진 행을 공통 `pageWindow`로 자른다. 묶기 또는 페이지당 표시 수가
바뀌면 기존처럼 첫 페이지로 돌아간다.

### 거래 내역

서버 요청의 `limit=pageSize`, `offset=page*pageSize`와 응답 `total` 계산을 유지한다.
공통화하는 것은 페이지당 입력과 이동 UI뿐이다. 첫 페이지에 덧붙이는 미청산 행은 서버
거래 건수와 페이지 크기에 포함하지 않는 기존 규칙을 유지한다.

## 경계 조건

- 빈 목록도 계산상 1페이지이지만 이동 UI는 숨긴다.
- 전체 페이지 수보다 큰 페이지 상태는 마지막 유효 페이지로 제한해 표시한다.
- 음수 페이지 상태는 첫 페이지로 제한한다.
- 전체 페이지 수가 5보다 작으면 존재하는 번호만 표시한다.
- 첫·마지막 이동은 각각 0과 `pageCount - 1`을 전달한다.
- 버튼을 빠르게 연속해서 눌러도 각 목표 페이지는 유효 범위를 벗어나지 않는다.

## 테스트

### Vitest

공통 계산을 `tests/unit/pagination.test.ts`에서 검증한다.

- 기존 `pageWindow`의 첫·마지막·빈 목록·목록 축소·잘못된 입력 사례
- 페이지 수가 최대 표시 수보다 적을 때 전체 번호
- 처음·중간·마지막 구간의 번호 창
- 현재 페이지가 중간 구간의 가운데에 놓이는지
- 639px·640px·1023px·1024px 경계에서 5·7·9를 선택하는지

기존 `symbol-paging.test.ts`의 사례는 공통 테스트로 옮긴다. 이번 기능만을 위해 jsdom이나
React Testing Library는 추가하지 않는다.

### Playwright

기존 데이터셋 편집 페이징 흐름을 새 접근성 이름에 맞춰 확장한다.

- 번호 버튼을 눌러 해당 페이지의 종목으로 이동한다.
- 현재 번호가 `aria-current="page"`와 굵은 표시를 가진다.
- 첫 페이지의 처음·이전 버튼과 마지막 페이지의 다음·마지막 버튼이 비활성화된다.
- mobile 390×844와 desktop 1440×900에서 페이지 이동이 동작한다.
- mobile에서 내비게이션이 가로 overflow를 만들지 않는다.

소비자 연결은 typecheck와 build로 함께 검증한다. 최종 검증은 lint, typecheck, 전체
Vitest, build, 두 Playwright 프로젝트 순서로 실행한다.
