# 백테스트 재설정 및 복제 진입 성능 개선 설계

- 작성일: 2026-08-11
- 상태: 사용자 설계 승인 완료

## 1. 목표

이미 생성된 백테스트에서 `재설정 및 복제`를 누르면 전략 선택 화면을 빠르게 연다.
첫 화면에 필요하지 않은 유니버스 계산과 종목·비용 프로필 조회는 각 단계로 미룬다.

## 2. 확인한 병목

`GET /backtests/:id/clone-draft`는 저장 요청을 재기준한 뒤 전체 기간의 유니버스를 다시
해소한다. 이어서 종목 등록 상태, 일봉 coverage, 재무 coverage를 검증한다. 단계형
유니버스는 모든 리밸런스 날짜마다 후보군을 다시 계산하므로 이 작업이 진입 지연의 주된
원인이다.

화면은 첫 렌더에서 다음 조회도 함께 시작한다.

- `GET /strategies`: 원본 전략을 현재 전략 목록과 대조하므로 첫 화면에 필요하다.
- `GET /strategies/:id/schema`: 원본 전략의 파라미터를 표시하므로 전략 프리필 뒤 필요하다.
- `GET /symbols`: 전체 종목 목록이라 위저드에는 필요하지 않다. 유니버스 미리보기가
  확정한 종목 중 실제 재무 행이 있는 종목만 preview 응답에 담으면 된다.
- `GET /backtests/profiles`: 비용 설정 단계에서만 필요하다.

## 3. 선택한 접근

기존 `clone-draft` 응답 계약을 유지하되 작업을 저장 요청 복원과 재기준으로 제한한다.
새 endpoint는 만들지 않는다. 새 endpoint를 만들면 같은 초안 계약과 캐시 키가 중복된다.
라우트 state만 전달하는 방식도 쓰지 않는다. 새로고침과 직접 링크에서 원본 요청을 복원할
수 없기 때문이다.

`clone-draft`는 다음 작업만 수행한다.

1. 원본 job을 찾는다.
2. 저장 요청을 현재 요청 스키마와 전략 버전에 맞게 재기준한다.
3. 재기준된 `request`와 `warnings`를 반환한다.
4. 응답 호환성을 위해 `blockers` 필드는 유지하되 유니버스·데이터 coverage 검사는 담지 않는다.

유니버스 해소와 제출 검증은 기존 책임 지점에 남긴다.

- 유니버스 단계는 preview에서 규칙, 종목 구성, 준비 상태를 확인한다.
- 최종 제출과 즉시 복제는 서버의 전체 제출 검증을 계속 거친다.

## 4. 화면 조회 시점

- 전략 목록은 위저드 진입 즉시 조회한다.
- 전략 schema는 전략 id가 정해진 뒤 조회한다.
- 종목 목록은 조회하지 않는다. 유니버스 preview가 `unionSymbols`와 함께
  `fundamentalSymbols`를 반환한다.
- 비용 프로필은 비용 설정 단계에 진입했을 때 조회한다.

구 서버가 `fundamentalSymbols`를 내리지 않으면 재무 보유 여부를 `없음`으로 판정하지
않는다. `모름`으로 유지해 잘못된 경고를 막는다. `fundamentalSymbols`는 fact 파일
존재나 수집 coverage가 아니라 실제 저장된 재무 행으로 판정한다. 자본변동 행만 있거나
DART에서 무자료 응답을 받아 coverage만 기록된 종목을 재무 보유로 오인하지 않는다.

## 5. 오류와 호환성

- 없는 job은 기존처럼 404를 반환한다.
- 현재 요청 스키마로 복원할 수 없는 저장 요청은 기존처럼 400을 반환한다.
- 구 전략 버전과 구 timeframe의 재기준 경고는 유지한다.
- 유니버스·일봉·재무 문제는 초안 진입을 막지 않는다. 유니버스 단계와 최종 제출에서
  사용자에게 알린다.
- `blockers` 필드는 빈 배열로 남겨 기존 클라이언트의 응답 파싱을 깨지 않는다.

## 6. 테스트

- 통합 테스트는 `clone-draft`가 유니버스 준비 오케스트레이터를 호출하지 않아도 200으로
  초안을 반환하는지 확인한다.
- 기존 초안 테스트는 재기준 요청과 경고를 확인하되 preparation을 선행하지 않는다.
- 유니버스·일봉 문제가 있는 원본도 빈 `blockers`와 함께 열리는지 확인한다.
- 브라우저 테스트는 전략 단계 진입에서 `/symbols`와 `/backtests/profiles`가 발생하지
  않는지 확인한다.
- 유니버스 preview 통합 테스트는 실제 재무 행이 있는 종목만 `fundamentalSymbols`에
  담고 자본변동 행과 무자료 coverage는 제외하는지 확인한다.
- 기존 전체 제출과 즉시 복제 검증 테스트는 그대로 통과해야 한다.

## 7. 범위 밖

- 유니버스 resolver와 coverage 쿼리 자체의 성능 개선
- 전략 목록 API의 응답 구조 변경
- 비용 프로필 캐시 정책 변경
- 최종 제출 검증 완화
