# 일봉·분봉 재검증 결과 수정 및 후속 검증 계획

작성일: 2026-11-17

## 범위와 결론

이 문서는 첨부된 「일봉·분봉 전략 업데이트 후 재검증 통합 요약」을 검토한 수정 보고서다. 첨부 요약의 수치는 작성자가 서버 결과로 제시한 값이며, 이 검토에서는 `quant/out/` 원자료를 확보하지 못해 수익률이나 체결을 재계산하지 않았다. 원문 수치를 실서버에서 독립 검증한 결과로 취급하지 않는다. 전략 기본값이나 진입 규칙을 이 보고서만으로 변경하지 않는다.

우선 달력과 재무자료 준비 상태를 확인해 재현 가능한 입력을 확보한 다음, 저PER·고ROE와 RSI 되돌림의 설정 차이를 분리해 검증한다. 새 기본값이 성과 차이에 기여했을 가능성은 있으나, 현재 비교는 여러 설정과 전략 동작이 함께 달라져 개별 원인을 확정하지 못한다. 분봉은 짧은 기간과 적은 체결로 별도 판단하며 일봉과 단일 순위로 합치지 않는다.

## 원 요약의 정정과 해석

- 원 요약 12행의 새 기본값 기준 양수 전략이 저PER·고ROE뿐이라는 설명은 표 64~67행과 다르다. 표에는 횡단면 모멘텀 KOSPI200 +6.7%, KOSDAQ150 +5.4%, 이익가속 KOSPI200 +7.0%도 양수다. 이 수치들은 모두 같은 표의 벤치마크 연평균 비교에서 열위다.
- 13행의 이익가속 연평균 +0.23%와 66행 CAGR 0.68%는 계산 기간과 정의가 달라졌는지 확인할 자료가 없다. 10년 누적 +7.0%와 CAGR 약 0.68%는 대체로 부합한다. +0.23%는 산식과 관측 기간을 확인하기 전까지 사용하지 않는다.
- 191행의 RSI 음수 평가구간은 5개가 아니라 표 181~187행 기준 7개 중 **6개**다.
- 원 요약 79~90행은 구 엔진의 과거 최고 설정, 새 엔진에 입력한 구 설정 계열, 새 엔진 기본값을 비교한다. 첫 비교는 엔진뿐 아니라 데이터·기간·유니버스·비용·설정이 일치했는지 원자료로 확인해야 한다. 두 번째 비교는 여러 파라미터를 동시에 바꾼 것이므로 특정 필터나 비중이 각각 얼마를 깎았는지 증명하지 못한다. 특히 RSI는 진입 규칙에도 코드 변경이 있어 새 엔진에 구 설정을 넣은 결과를 구 동작 재현이라고 부를 수 없다. 횡단면 모멘텀과 EMA는 해당 표에서 새 기본값이 새 엔진의 구 설정 계열보다 개선됐다.
- 330행의 비용 잠식과 338행의 서버 재기동 영향은 가능한 가설이다. 동일 거래의 비용 전후 비교와 준비 로그가 없으므로 원인으로 확정하지 않는다.
- 310행 RSI의 롤링 SD 11.02%p와 319행의 편차 12.1%p는 산식과 표본을 확인해야 한다. 서로 다른 지표라면 이름과 기간을 명시하고, 같은 지표라면 값을 정정한다. 샤프가 -179.23인 분봉 탐색 결과는 수익과 변동성이 거의 0인 사례이므로 무위험금리와 연율화, 작은 분모 처리를 확인하기 전까지 순위 지표로 사용하지 않는다.

## 일봉 평가

원 요약의 새 기본값 표는 일부 양수 전략도 지수에 뒤지고, 전고점 돌파와 EMA는 큰 손실 및 낙폭을 나타낸다. 이는 조사 우선순위를 정하는 관측치이지 향후 실거래 성과의 증거가 아니다. 이익가속의 낮은 달력연도 수익률 표준편차는 낮은 위험조정 성과나 현금 노출과 함께 평가해야 한다. 저PER·고ROE와 RSI의 구 설정 계열이 높은 수익을 보였다는 관측 역시 같은 기간에서 과거 최고 설정을 고른 선택 편향 가능성을 포함한다.

일봉 워크포워드 표는 전고점과 RSI 두 전략만 포함하며 나머지 전략의 롤링 변동성은 평가구간 외 검증의 대체물이 아니다. [명세](../SPEC.md)에 따르면 `optimization`을 생략한 기간 검증은 고정 설정으로 IS와 OOS를 독립 실행하며 IS 성과로 OOS 실행을 결정하지 않는다. 최적화 실행 여부와 각 폴드 설정은 원 결과에서 확인해야 한다. 이미 결과를 보고 선택한 기간은 다시 실행해도 진정한 미사용 검증 구간이 아니다.

## 분봉 평가

원 요약의 50회 중 양수 4회는 같은 1년 창에서 여러 종목·설정을 비교한 결과다. 상위 네 실행의 거래 수는 각각 4, 12, 7, 8회로 적고, 10회 기준 통과나 높은 샤프만으로 안정성을 입증할 수 없다. 2개 평가 폴드와 12개월 월별 수익으로는 기간과 종목에 대한 일반화가 어렵다. 추가 데이터가 확보되면 종목과 설정을 사전에 고정하고 거래별 체결, 비용, 노출, 데이터 범위를 확인한 뒤 독립 기간과 다른 종목에서 평가한다.

원 요약의 통합 안정성 순위는 일봉의 중첩 12개월 롤링 수익률 SD와 분봉 월수익 SD에 √12를 곱한 값을 서로 다른 기간과 표본에서 비교한다. 연율화는 수익률 자기상관 등 조건에 영향을 받으므로 단위가 같아져도 추정량이 같아지지는 않는다. 해당 순위를 공동 안정성 서열이나 운용 추천으로 사용하지 않는다. 일봉과 분봉을 각자의 기간, 표본 수, 수익, 낙폭, 노출 및 비용과 함께 별도로 제시한다.

## 우선 원인 분리 실험

동일한 새 엔진 버전, 데이터 revision, 기간, 유니버스, 초기자금, 체결 및 비용을 고정하고 완전한 설정을 저장한다. 각 비교에서 지정한 항목 외 값은 동일하게 유지한다. 비선형 상호작용이 가능하므로 단일 항목 차이를 전체 차이에 단순 합산하지 않는다.

| 우선순위 | 대상 | 비교 | 확인할 결과 |
|---|---|---|---|
| 1 | 저PER·고ROE | 구 설정 계열을 기준으로 새 기본값과 전체 설정 차이를 기록한 뒤, 시장 추세·리스크오프 비중, 완충·리밸런스, 유동성 조건을 각각 바꾼 쌍을 실행 | 수익·낙폭·거래수 외 현금 및 시장 노출, 회전율, 비용, 후보 종목 수 |
| 2 | RSI 되돌림 | 구 설정 계열을 기준으로 추세 기간, 최대 보유 기간, 종목당 비중 상한과 그 밖의 설정 차이를 각각 바꾼 쌍을 실행 | 진입 신호와 실제 체결 수, 보유 기간, 노출, 비용, 낙폭 및 수익 |
| 3 | 두 전략 | 차이가 큰 항목의 조합과 반대 기준점에서도 동일한 비교를 수행 | 항목 간 상호작용과 결과의 기간·유니버스 민감도 |

코드 차이와 설정 차이를 분리하려면 구·신 엔진에 동일한 전체 입력과 데이터 스냅샷을 적용할 수 있는지 먼저 확인한다. 진입 조건이 달라진 RSI는 신호 단계부터 비교하고, 호환되지 않는 설정은 억지로 동등하다고 간주하지 않는다. 비용을 0으로 둔 진단과 실제 비용 기준을 비교하되, 비용 0 결과를 운용 가능 수익으로 해석하지 않는다. 비용 0 재실행은 주문 수량과 이후 거래도 바꿀 수 있으므로 결과 차이를 순수 비용 합계라고 해석하지 않는다.

후보는 위 실험에서 사전에 정한 위험·거래수 조건을 충족하는 범위에서 고르고, 이후 별도로 확보한 미사용 기간에서 고정 설정을 평가한다. 최적화를 사용할 때는 학습 구간에서만 선택하고 평가 구간을 선택에 사용하지 않는다. 폴드별 기간·설정·거래수·노출·비용·MDD·벤치마크 및 미평가 사유를 보존한다. 표본이 적으면 결론을 보류한다.

## 데이터 준비와 재현성

원 요약의 2019Q4 BONDS 충돌 예시(199,953,500,839와 898,561,179,354)는 커밋 `6cab39f5`의 별도 처분·분배예정 집단 검산 사례와 수치가 일치한다. 해당 커밋은 총계로 구간이 입증되는 경우의 분류와 사채 태그 처리를 보강하고, 테스트에서 그 예시와 수집 버전 변경 시 저장 원문의 재해석을 확인한다. `8d2476f4`는 별도 부채와 중복되지 않고 소계가 검증되는 사채 포함 유동 차입금 사례를 다룬다. 이는 원 요약의 다섯 종목 전체 BONDS 및 LONG_TERM_BORROWINGS gap이 운영 데이터에서 해소됐다는 증거는 아니다. 적용된 서버 버전과 수집 버전, 각 종목·기간·필드별 원문 및 재처리 후 coverage와 남은 gap을 확인하고 재무 준비를 다시 점검한다.

달력은 공식 과거자료 확보 상태와 실제 게시 대기를 구분해 점검하고, 워밍업을 포함한 전체 요청 기간의 coverage 및 준비 상태를 확인한다. 완료되지 않은 준비 결과를 성과 계산에 섞지 않는다. 실행마다 정확한 전체 입력, 전략·엔진·수집 버전, dataset/source revision과 스냅샷 checksum, 달력 원문의 연도별 해시·확인일, 시점별 유니버스 구성과 일정의 해시, 비용·체결·무위험금리, 시드, 실행 ID 및 결과와 로그를 보존한다. 과거 결과와 원자료는 삭제하지 않고 새 실행과 구분한다.

실제 서버 재실행과 운영 데이터의 gap 해소 확인은 후속 작업이다. 이 작업에서는 운영 백테스트 API를 호출하거나 실서버 백테스트를 실행하지 않았다. 코드 수정을 위한 공식 달력 공개 원문 조회만 수행했다.

## dots에 전달할 실행 순서

1. 아래 코드 수정이 운영 서버에 배포됐는지 Git SHA와 수집 버전을 확인한다. devel 반영 자체는 운영 배포를 의미하지 않는다. 기존 보고서의 원자료와 실행을 보존하고, 조회 실패한 기록은 새로 만든 결과로 대체하지 말고 누락으로 표시한다.
2. 원 보고서의 `quant/out/daily_candidates.json`, `daily_wf_results.json`, `intraday_results.json`, `intraday_disp.json`, `isearch_results.json`, `iwf_results.json`과 삭제 전 백업을 확보한다. 분봉 48회 원자료와 총 50회 집계에 포함된 추가 2회를 실행 ID로 대조한다.
3. 2016-01-04 시작 요청의 워밍업을 포함한 준비 완료 여부를 다시 확인한다. 과거 날짜의 임의 시세를 만들거나 준비 검사를 우회하지 않는다. 밸류·퀄리티는 기존 실패 종목·공시·필드별 gap이 해소됐는지 확인한다. 추가로 2014년 이전 달력이 필요하면 별도 결손으로 보고한다.
4. 아래 기존 실행의 전체 입력과 결과를 확보한 뒤, 같은 조건의 기준 실행을 먼저 재현한다. 원 보고서의 공통 조건은 일봉 2016-11-14~2026-11-13, 초기자금 1,000만원, 다음 봉 시가 체결, 수수료 1.5bp·매도세 20bp·슬리피지 5bp, 시드 42다. 실제 저장 요청을 우선하며 보고서만으로 누락 설정을 추측하지 않는다.
5. 위 원인 분리 실험을 저PER·고ROE, RSI 순으로 수행한다. 현금 비중 때문에 낮아진 변동성과 매매 신호 자체의 개선을 구분하고, 결과를 본 뒤 평가 구간이나 지표를 유리하게 바꾸지 않는다.
6. 유망 후보만 학습 구간 내 선택을 적용한 워크포워드로 평가한다. 모든 OOS 폴드의 거래수·수익·낙폭과 미평가 사유를 기록한다. 이미 본 전체 기간에서 선택한 설정을 새 미사용 검증 결과라고 쓰지 않는다. 분봉은 별도 표로 제시하고 표본 부족을 유지한다.

| 우선 조회 대상 | 새 기본값 실행 ID | 구 설정 계열 실행 ID |
|---|---|---|
| 저PER·고ROE, KOSPI200 표기 유니버스 | `bt_01M7MH8535VCNBSDTTADVR53JH` | `bt_01M7MMP934YR7FQAA9QQBVYVTB` |
| RSI, KOSDAQ150 표기 유니버스 | `bt_01M7MH8GG5YDNPX5AX0PG95J97` | `bt_01M7MMQ8SK4A23E5K94MN2K78H` |

위 유니버스 이름만으로 과거 지수 구성원을 재현했다고 간주하지 않는다. [명세](../SPEC.md)의 지원 범위에 따라 실제 선정 규칙과 시점별 일정을 비교한다. 후속 결과에는 각 실험의 입력 차이, 코드·데이터 일치 여부, 비용 후 수익, MDD, 노출률, 거래수, 비용, 데이터 누락 및 실행 ID를 함께 제출한다. 측정하지 못한 지표는 추정값 대신 미측정으로 남긴다.

## 코드 변경 및 검증 결과

### 코드 변경

- KRX [공식 휴장일 조회](https://open.krx.co.kr/contents/MKD/01/0110/01100305/MKD01100305.jsp)의 2014년 16개·2015년 13개 휴장일 원문을 추가했다. 응답 원문과 SHA-256, 연도별 확인일 2026-11-17을 보존하며 기존 2016~2026년 원문과 확인일은 유지한다. 토·일요일은 기존 공식 달력 규칙을 따른다.
- 달력이 없는 연도의 빈 응답은 `BLOCKED_SOURCE_REQUIREMENT`와 `KRX_CALENDAR_UNAVAILABLE` 근거로 차단한다. 최초에 받은 빈 원문도 보존하고 달력 결손 때문에 같은 시세를 반복 수집하지 않는다. 개장일의 빈 응답은 기존 게시 대기 정책을 따른다.
- 서버 시작 시 기존 달력 미확보 대기를 재평가한다. 오류의 UNKNOWN 날짜, 저장된 요청 JSON 또는 공급자 원장의 지문, 원 요청 범위, 새 공식 달력의 판정이 일치하는 경우만 재개한다. 실제 개장일 게시 대기, 네트워크 재시도 기한, 원장 없는 지문과 범위 불일치는 그대로 둔다.
- 전략 기본값·진입 규칙·비용·성과 계산 및 DART 파서는 이번 변경에서 수정하지 않았다. DART 관련 수정은 앞 절의 기존 커밋이며 운영 데이터 재검증이 필요하다.

영구 회귀 테스트는 기존 테스트가 보호하지 못한 과거 공식 달력의 빈 원문 재사용, 달력 미확보의 최초·저장 응답 반복 차단, 원장 지문 기반 대기 복구와 다른 대기 보존을 다룬다. 원문 재사용은 기존 공급자 수집 통합 테스트에, 복구 상태 경계는 기존 자동 수집 큐 테스트에 추가했다. 임시 원문 다운로드·검증 자료는 저장소에 별도 추가하지 않았다.

### 검증 기록

검증 기준은 `devel`의 `ff676ff3`에 이번 코드 변경을 적용한 스냅샷이며 Node 24.22.2와 pnpm 11.25.0을 사용했다. 분리 워크트리의 의존성을 격리 복사한 환경에서 pnpm의 자동 재설치만 끄는 `--config.verifyDepsBeforeRun=false`를 사용했다. 잠금파일과 테스트·린트·타입 검사 조건은 변경하지 않았다.

| 검증 | 실제 명령·방법 | 결과 |
|---|---|---|
| 관련 수집 회귀 | `pnpm --config.verifyDepsBeforeRun=false test tests/integration/automatic-provider-collection.test.ts tests/unit/krx-historical-universe-source.test.ts tests/unit/benchmark-service.test.ts` | exit 0, 48개 통과 |
| 전체 일반 회귀 | `pnpm --config.verifyDepsBeforeRun=false test:all` | exit 0, 261개 파일·2,700개 테스트 통과, 257.47초 |
| 서버·웹 타입 검사 | `pnpm --config.verifyDepsBeforeRun=false typecheck` | exit 0 |
| 린트 | `pnpm --config.verifyDepsBeforeRun=false lint` | exit 0 |
| 서버·웹 프로덕션 빌드 | `pnpm --config.verifyDepsBeforeRun=false build` | exit 0, 웹 번들 500kB 초과 경고 있음 |
| 런타임 버전 대조 | 기준·수정 워크트리에서 `node scripts/build-runtime-versions.mjs --print` 후 비교 | agent·execution·schema 유지, collection·preview·validation 변경 |
| 공식 원문 무결성 | 2014·2015년 다운로드 응답과 seed의 SHA-256 비교, 기존 연도 diff 확인 | 일치, 기존 2016~2026년 원문 변경 없음 |
| 독립 정적 리뷰 | 수집 차단·기존 오류 형식·원장 지문·요청 범위·기존 대기 보존 검토 | 중요한 회귀 발견 없음 |

전체 회귀에는 큐 복구 테스트도 포함된다. Agent 패키지와 UI는 변경하지 않아 별도 패키지 검사·브라우저 E2E는 실행하지 않았다. 운영 서버 배포, 실데이터 준비 완료, 백테스트 수익률 재검산은 이 검증에 포함되지 않으며 dots 후속 확인 항목이다.
