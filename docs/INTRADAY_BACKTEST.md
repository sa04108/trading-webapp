# 분봉 수집과 지정 종목 백테스트

데이터 → 분봉에서 수집하고, 백테스트 → 분봉에서 실행한다. 토스 서버 자격 증명을 기존 연결과 공유한다. 분봉 전략은 기존 일봉 전략·실매매와 별도이며 실제 주문을 보내지 않는다.

## 데이터 계약

- 국내 KOSPI·KOSDAQ 보통주 한 종목을 지정한다. 수집 전에 토스 종목 정보로 상품 종류, ISIN, 상장일을 확인한다. 현재 종목의 상장일 이전은 백테스트하지 않는다.
- 토스 `GET /api/v1/candles`, `interval=1m`, `adjusted=false`, 최대 200개와 `nextBefore`를 사용한다. 과거 제공 기간은 실제 응답 범위만 인정한다. 빈 응답·호출 오류·진행하지 않는 커서는 실패로 표시한다.
- `endMs`는 봉 종료 시각이며 구간은 `[endMs - 1분, endMs)`다. 수집 시각보다 1분 이상 지난 봉만 받는다. 과거의 실제 도착 시각을 재현했다고 주장하지 않는다.
- 거래시장 구성이 공식 명세에 확정되어 있지 않아 `TOSS_UNSPECIFIED`로 보존한다. KRX 전용 봉으로 표시하거나 다른 공급자 봉을 섞지 않는다.
- 최대 100종목, 최근 365일 원본을 `$DATA_ROOT/intraday`에 보관한다. 종목·서울시간 월별 Parquet, INT64 여섯 열, Snappy 압축을 사용하며 DuckDB는 필요하지 않다.
- 새 파일을 완성한 뒤 checksum을 담은 manifest를 원자적으로 교체한다. 읽는 동안 정리 작업이 파일을 지우지 않는다. 만료 봉과 이전 버전 파일은 시간별로 정리하며 최초 데이터 화면 조회에서도 정리한다.
- 과거 결과의 재실행을 위해 원본을 추가 보관하지 않는다. 보관 범위를 벗어나면 같은 기간을 재실행할 수 없으며 결과·설정은 남는다. 일부 만료될 수 있는 경계일은 백테스트 시작일에서 제외한다.
- 차트는 요청한 월만 읽고 최대 2,000개 봉을 반환한다. 날짜 범위를 좁혀 탐색하며 이 제한을 전략 계산에는 적용하지 않는다. 5분·15분 집계 시 누락된 분을 채우지 않는다.

## 초기 실행 계약

- 단일 종목 현금 매매다. 기존 `intraday-ema@1.0.0`에 시초가 범위 돌파, VWAP 회복, 볼린저·RSI 되돌림 전략을 추가했다. 세 전략의 첫 버전은 각각 `1.0.0`이다. 신호 주기는 1분·5분·15분이고 체결에는 1분 원본을 사용한다.
- Asia/Seoul 09:00~15:20 구간을 사용한다. 공식 거래일의 전체 380분이 필요하며, 무거래·정지·개장 시각 변경인지 확인되지 않는 빈 분은 날짜와 사유를 표시하고 거부한다. 종가 단일가 구간을 제외한다.
- 지표와 시초 범위는 매일 초기화한다. EMA는 장기 EMA 개수만큼 확정 봉을 준비한다. 준비 시간은 15:10 진입 마감 이전이어야 한다. 전일 가격 단절을 당일 신호로 사용하지 않는다.
- 15:10 이후 신규 매수를 금지하고 15:15부터 당일 청산을 시도한다. 15:20에도 잔여 포지션이 있으면 마지막 가격 평가와 잔량을 남기고 그날에서 계산을 끝낸다. 익일 이월이나 임의 청산을 하지 않는다.
- 신호 종료 시각에 설정한 데이터·계산·전송 지연을 더한 뒤 처음 사용 가능한 1분봉 시가에서 체결한다. 이미 지난 시가에는 체결할 수 없다.
- 주문 수량은 현금과 이미 확정된 봉 거래량으로 결정한다. 체결 봉 거래량은 사후 부분체결 상한으로만 사용한다. 주문 만료와 진입 마감의 미체결 매수 취소를 적용한다.
- 청산 신호 우선순위는 손절, 익절, 선택한 전략의 청산 조건이다. 기존 미체결 매도는 계속 처리하고 후속 신호로 지연·만료 시간을 연장하지 않는다. 만료 후에도 당일 청산 시간이면 다시 청산을 시도한다.
- 손절·익절은 확정 신호 봉 종가 기준이다. 봉 내부 가격 경로나 스톱 주문 체결은 재현하지 않는다. 비용·매도세·슬리피지는 사용자 입력 가정이며 실제 증권사 비용을 보장하지 않는다. 최근 국내 보통주 호가 단위를 적용한다.
- 비용 반영 자산 수익률, KST 거래일말 Sharpe, 장중·일말 최대낙폭을 계산한다. 신호와 모의 체결 시각을 따로 보존한다.

## 전략 선택과 설정

일봉·분봉은 백테스트 제목 바로 오른쪽의 단일 선택기로 전환한다. 두 목록의 제목·선택기·새 실행 버튼 배치를 동일하게 사용하며 모바일에서는 새 실행 버튼을 아이콘으로 표시한다. 편집 도구는 가로 스크롤 행으로 유지한다. 분봉 목록에는 전략 설명과 설정 바로가기를 표시하고, 실행 내역과 복제 화면에는 선택한 전략·파라미터를 보존한다.

세 신규 전략은 수익률 순위가 아니라 서로 다른 장세, OHLCV만으로 확인 가능한 신호, 명확한 청산 조건을 기준으로 선정했다. 지표 파라미터는 제안 기본값이며 종목·기간 밖의 수익성을 검증한 최적값이 아니다.

| 전략 | 진입 | 전략 청산 | 적합한 검증 상황과 한계 |
| --- | --- | --- | --- |
| 시초가 범위 돌파 (`intraday-orb`) | 첫 N분의 고점에 여유 bps를 더한 가격을 종가로 상향 돌파하고, 시초 분당 평균 거래량 × 신호 봉 분수 × 배수 이상인 첫 신호 | 시초 범위 중간값 아래 종가 | 장 초반 추세. 하루 첫 유효 신호만 주문하며, 허용된 개장 후 시간 안에서만 진입. 거짓 돌파·슬리피지에 민감 |
| VWAP 회복 (`intraday-vwap-reclaim`) | 이전 신호 봉이 VWAP 이하이고 현재 봉이 VWAP 및 상승 중인 EMA 위로 회복하며 이전 N개 신호 봉 평균 거래량 조건 충족 | 당일 VWAP 아래 종가 | 장중 추세 회복. VWAP은 1분봉 `(고가+저가+종가)/3 × 거래량`의 당일 누적으로 근사. VWAP 주변 횡보 시 반복 비용 위험 |
| 볼린저·RSI 되돌림 (`intraday-bollinger-rsi`) | 이전 종가가 하단 밴드 이하·RSI 과매도 상태이고, 현재 종가가 하단 위·중심선 아래로 돌아오며 RSI 상승 | 중심선 이상 종가 | 횡보장 과매도 회복. 밴드는 종가의 모집단 표준편차, RSI는 Wilder 평활. 강한 하락 추세에 취약 |

모든 전략은 확정된 봉으로 판단하며 지연·부분체결·비용·손절·익절·당일 청산 규칙을 공유한다. 지표 준비와 회복 확인에 필요한 이전 봉까지 계산해 15:10 전 진입이 불가능한 설정은 거부한다. 기존 EMA 요청 형식과 계산은 유지한다. 이 전략 추가는 분봉 백테스트에 적용되며 실제 자동매매의 일봉 실행기는 별도다.

## 실행과 운영

수집·실행 상태는 운영 SQLite의 `intraday_collections`, `intraday_runs`에 저장한다. 계산은 서버 전용 자식 프로세스에서 한 번에 하나씩 수행하며 고정된 요청·봉·거래일만 전달한다. 공급자 키는 전달하지 않는다. 초기 버전은 원격 에이전트의 일봉 배정 경로에 분봉을 보내지 않는다. 계산 자식 메모리는 384MiB, 제한 시간은 120초다.

인증된 사용자만 제출·조회·취소할 수 있고 작업 이력은 소유자별이다. 수집 실패를 실행 화면에도 전달한다. 취소 뒤 도착한 결과는 저장하지 않으며, 재시작 당시 진행 중이던 작업은 실패로 정리한다. 결과에 요청·전략 버전·실행 코드 버전·데이터 revision·비용·미체결·잔여 포지션을 보존한다. 데이터가 정정되면 결과 차트에 경고하고 당시 신호·체결 마커를 현재 데이터에 겹치지 않는다.

API는 `/api/v1/intraday` 아래 `data`, `symbols`, `chart`, `collections`, `runs`로 분리한다. 일봉 요청은 구분자가 없거나 `mode=daily`인 경우만 받아 기존 요청·복제 흐름을 유지한다.

일봉·분봉 이력은 공통 연필 편집 버튼과 표·카드 스위치를 사용한다. 분봉 이력 삭제는 `DELETE /api/v1/intraday/history/:id`로 소유자의 종료된 기록만 제거하며, 작업 정리가 끝나지 않은 기록과 공유 Parquet 원본은 삭제하지 않는다. 기존 `DELETE /api/v1/intraday/runs/:id`는 실행 취소 기능을 유지한다. 목록의 삭제 범위는 펼친 전략의 현재 페이지이며 실행 중인 기록은 선택할 수 없다.

분봉 실행 화면은 일봉과 공통 진행 카드를 사용하고 초기 조회 중에는 스켈레톤을 표시한다. 대기·데이터 준비·계산 상태를 갱신하며 완료·실패·취소 시 로딩 표시를 종료한다. 현재 분봉 API는 진행 수치를 제공하지 않으므로 퍼센트를 추정해서 표시하지 않는다.

## 검증

기존 일봉 테스트가 보호하지 못하는 분봉 종료 시각·미래 정보·집계 누락·부분체결·만료·최소 호가·청산 실패, Parquet 왕복·정정·보관 경계, 인증·소유권·취소·수집 실패 전파에 작은 회귀 사례를 추가한다. UI E2E는 모바일·데스크톱의 경로, 오류 종료, 신호·체결 표시를 확인한다. 신규 검증은 기존 EMA 사례가 다루지 못하는 세 전략의 인과관계·당일 초기화·준비 경계와 실제 주문 모형 연결, UI 전략 선택·파라미터 제출·복제 보존 및 제목 옆 선택기의 줄바꿈 방지를 보호한다. 실제 토스 과거 제공 기간과 시장 구성은 운영 자격 증명으로 조회해야 확인할 수 있다.
