# 분봉 수집과 지정 종목 백테스트

데이터 → 분봉에서 수집하고, 백테스트 → 분봉에서 실행한다. 토스 서버 자격 증명을 기존 연결과 공유한다. 분봉 전략은 기존 일봉 전략·실매매와 별도이며 실제 주문을 보내지 않는다.

## 데이터 계약

- 국내 KOSPI·KOSDAQ 보통주 한 종목을 지정한다. 수집 전에 토스 종목 정보로 상품 종류, ISIN, 상장일을 확인한다. 현재 종목의 상장일 이전은 백테스트하지 않는다.
- 토스 `GET /api/v1/candles`, `interval=1m`, `adjusted=false`, 최대 200개와 `nextBefore`를 사용한다. 과거 제공 기간은 실제 응답 범위만 인정한다. 호출 오류·진행하지 않는 커서는 실패로 표시하되, HTTP 429는 실패가 아니라 대기 후 같은 페이지를 재조회한다. 캔들 그룹의 초당 20회 한도는 일봉·분봉·종목·수집 작업 전체가 공유한다. 대기 중 사용자 취소는 취소로, 서버 종료는 다음 부팅 때 재개할 대기 상태로 처리한다.
- `endMs`는 봉 종료 시각이며 구간은 `[endMs - 1분, endMs)`다. 수집 시각보다 1분 이상 지난 봉만 받는다. 과거의 실제 도착 시각을 재현했다고 주장하지 않는다.
- 거래시장 구성이 공식 명세에 확정되어 있지 않아 `TOSS_UNSPECIFIED`로 보존한다. KRX 전용 봉으로 표시하거나 다른 공급자 봉을 섞지 않는다.
- 최대 100종목, 최근 365일 원본을 `$DATA_ROOT/intraday`에 보관한다. 종목·서울시간 월별 Parquet, INT64 여섯 열, Snappy 압축을 사용하며 DuckDB는 필요하지 않다.
- 수집과 백테스트 준비는 저장된 봉을 먼저 확인한다. 공식 거래일의 09:00~15:20 구간 중 누락된 분이 있는 서울 날짜만 하루 단위로 다시 받고, 완전한 날짜와 휴장일은 건너뛴다. 오늘은 수집 시각보다 1분 이상 지난 봉만 누락 판정에 포함한다. 상장일·보관 범위 경계는 조회 범위를 제한한다.
- 날짜별 수집을 마칠 때마다 저장하므로 다음 날짜의 실패나 서버 재시작에도 완료한 날짜는 재사용한다. 한 달 중 1분만 누락되어도 해당 날짜만 다시 조회한다.
- 새 파일을 완성한 뒤 checksum을 담은 manifest를 원자적으로 교체한다. 읽는 동안 정리 작업이 파일을 지우지 않는다. 만료 봉과 이전 버전 파일은 시간별로 정리하며 최초 데이터 화면 조회에서도 정리한다.
- 과거 결과의 재실행을 위해 원본을 추가 보관하지 않는다. 보관 범위를 벗어나면 같은 기간을 재실행할 수 없으며 결과·설정은 남는다. 일부 만료될 수 있는 경계일은 백테스트 시작일에서 제외한다.
- 차트는 요청 범위의 저장된 원본을 읽고 1분·5분·10분·15분·30분·1시간·일·주·월로 집계한다. 기존 2,000봉 표시 제한을 없애 최대 365일을 탐색한다. 분·시간봉은 서울 개장 09:00 기준이며 주봉은 월요일, 월봉은 서울 달력 월을 기준으로 한다. OHLCV는 실제 저장된 09:00~15:20 봉만 합치므로 종가 단일가를 포함한 공식 일봉과 다를 수 있다. 누락된 분은 채우지 않고 화면에 누락 구간을 표시한다. 조회 시작·종료 경계와 진행 중인 구간은 부분 집계일 수 있다. 이 표시용 집계는 기존 전략 신호 계산을 변경하지 않는다.
- 서버는 종목·월·파일 해시별로 검증된 원본을 최대 50만 봉·128개 파일까지 메모리에 재사용한다. 파일 읽기와 checksum 검사는 매 요청 유지하므로 캐시가 원본 손상·삭제를 숨기지 않는다. 차트 집계는 종목·데이터 revision·기간·유효 분 경계·표시 주기별로 최대 20만 봉/누락 구간·64개 결과를 재사용한다. 두 캐시는 최근 사용한 항목부터 보존하며 한도 초과 결과는 보관하지 않는다. 정정·추가 수집·시간 경과에 따른 보관/확정 경계 변경은 다시 계산하고, 당일 누락 구간은 매 요청의 현재 시각으로 제한한다. 서버 재시작 또는 캐시 퇴출 후 첫 조회는 원본 해독과 검증을 다시 수행한다.

## 초기 실행 계약

- 단일 종목 현금 매매다. 기존 `intraday-ema@1.0.0`에 시초가 범위 돌파, VWAP 회복, 볼린저·RSI 되돌림 전략을 추가했다. 세 전략의 첫 버전은 각각 `1.0.0`이다. 신호 주기는 1분·5분·15분이고 체결에는 1분 원본을 사용한다.
- Asia/Seoul 09:00~15:20 구간을 사용한다. 공식 거래일의 전체 380분이 필요하며, 무거래·정지·개장 시각 변경인지 확인되지 않는 빈 분은 날짜와 사유를 표시하고 거부한다. 종가 단일가 구간을 제외한다.
- 지표와 시초 범위는 매일 초기화한다. EMA는 장기 EMA 개수만큼 확정 봉을 준비한다. 준비 시간은 15:10 진입 마감 이전이어야 한다. 전일 가격 단절을 당일 신호로 사용하지 않는다.
- 15:10 이후 신규 매수를 금지하고 15:15부터 당일 청산을 시도한다. 15:20에도 잔여 포지션이 있으면 마지막 가격 평가와 잔량을 남기고 그날에서 계산을 끝낸다. 익일 이월이나 임의 청산을 하지 않는다.
- 신호 종료 시각에 설정한 데이터·계산·전송 지연을 더한 뒤 처음 사용 가능한 1분봉 시가에서 체결한다. 이미 지난 시가에는 체결할 수 없다.
- 주문 수량은 현금과 이미 확정된 봉 거래량으로 결정한다. 체결 봉 거래량은 사후 부분체결 상한으로만 사용한다. 주문 만료와 진입 마감의 미체결 매수 취소를 적용한다.
- 청산 신호 우선순위는 손절, 익절, 선택한 전략의 청산 조건이다. 기존 미체결 매도는 계속 처리하고 후속 신호로 지연·만료 시간을 연장하지 않는다. 만료 후에도 당일 청산 시간이면 다시 청산을 시도한다.
- 손절·익절은 확정 신호 봉 종가 기준이다. 봉 내부 가격 경로나 스톱 주문 체결은 재현하지 않는다. 비용·매도세·슬리피지는 사용자 입력 가정이며 실제 증권사 비용을 보장하지 않는다. 최근 국내 보통주 호가 단위를 적용한다.
- 비용 반영 자산 수익률, KST 거래일말 Sharpe, 장중·일말 최대낙폭을 계산한다. 신호와 모의 체결 시각을 따로 보존한다.
- 최대낙폭(MDD)은 일봉과 동일하게 0 이하의 백분율로 기록한다. 고점 대비 10% 하락은 `-10%`이며, 양의 크기로 저장된 기존 결과도 목록·상세 조회에서 음수로 표시한다.

## 전략 선택과 설정

일봉·분봉은 백테스트 제목 바로 오른쪽의 단일 선택기로 전환한다. 두 목록의 제목·선택기·새 실행 버튼 배치를 동일하게 사용하며 모바일에서는 새 실행 버튼을 아이콘으로 표시한다. 편집 도구는 가로 스크롤 행으로 유지한다. 분봉 목록에는 전략 설명과 설정 바로가기를 표시하고, 실행 내역과 복제 화면에는 선택한 전략·파라미터를 보존한다.

세 신규 전략은 수익률 순위가 아니라 서로 다른 장세, OHLCV만으로 확인 가능한 신호, 명확한 청산 조건을 기준으로 선정했다. 지표 파라미터는 제안 기본값이며 종목·기간 밖의 수익성을 검증한 최적값이 아니다.

| 전략 | 진입 | 전략 청산 | 적합한 검증 상황과 한계 |
| --- | --- | --- | --- |
| 시초가 범위 돌파 (`intraday-orb`) | 첫 N분의 고점에 여유 bps를 더한 가격을 종가로 상향 돌파하고, 시초 분당 평균 거래량 × 신호 봉 분수 × 배수 이상인 첫 신호 | 시초 범위 중간값 아래 종가 | 장 초반 추세. 하루 첫 유효 신호만 주문하며, 허용된 개장 후 시간 안에서만 진입. 거짓 돌파·슬리피지에 민감 |
| VWAP 회복 (`intraday-vwap-reclaim`) | 이전 신호 봉이 VWAP 이하이고 현재 봉이 VWAP 및 상승 중인 EMA 위로 회복하며 이전 N개 신호 봉 평균 거래량 조건 충족 | 당일 VWAP 아래 종가 | 장중 추세 회복. VWAP은 1분봉 `(고가+저가+종가)/3 × 거래량`의 당일 누적으로 근사. VWAP 주변 횡보 시 반복 비용 위험 |
| 볼린저·RSI 되돌림 (`intraday-bollinger-rsi`) | 이전 종가가 하단 밴드 이하·RSI 과매도 상태이고, 현재 종가가 하단 위·중심선 아래로 돌아오며 RSI 상승 | 중심선 이상 종가 | 횡보장 과매도 회복. 밴드는 종가의 모집단 표준편차, RSI는 Wilder 평활. 강한 하락 추세에 취약 |

모든 전략은 확정된 봉으로 판단하며 지연·부분체결·비용·손절·익절·당일 청산 규칙을 공유한다. 지표 준비와 회복 확인에 필요한 이전 봉까지 계산해 15:10 전 진입이 불가능한 설정은 거부한다. 기존 EMA 요청 형식과 계산은 유지한다. 완료된 분봉 백테스트의 결과 화면에서 해당 설정을 독립 모의계좌에 가져올 수 있다.

## 모의투자

분봉 결과에서 **이 결과로 모의투자 만들기**을 선택하면 원본 종목, 전략·파라미터, 신호 주기, 초기 자금과 체결 조건으로 계좌를 만들고 매매 페이지를 연다. ON은 그 페이지에서 직접 선택한다. 일봉과 분봉 계좌는 같은 프리셋 목록과 계좌별 실행 권한·주문 이력을 사용한다. 원본 기간은 출처로 보존하고 활성화 이후의 거래일에 운용한다.

백테스트와 모의투자는 확정 1분봉을 같은 순서로 같은 엔진에 입력한다. 장중 ON 전의 봉은 당일 지표 준비에만 사용한다. 공급자 확정 지연 1분을 적용하고 최근 누락 봉은 2분 더 재조회한다. 이후에도 비어 있는 봉에서는 신호와 체결을 만들지 않는다. 공급자가 사후 정정한 분봉으로 다시 실행하면 과거 모의계좌와 결과가 달라질 수 있다.

OFF는 미체결 잔량을 취소하고 보유 수량을 유지한다. 화면의 분봉 평가액은 표시된 마지막 처리 봉의 종가 기준이다. 활성 상태의 서버 재시작은 이미 기록한 체결 다음부터 이어간다. 당일 청산에 실패한 수량은 잔고에 남고 원래 엔진의 당일 보유 규칙에 따라 자동매매가 중지된다.

원본과 현재 실행 버전이 다르면 같은 전략 버전의 원본 기간을 저장된 봉으로 재계산해 신호·체결·비용과 평가 곡선이 일치할 때만 가져온다. 재현이 불가능하면 현재 버전으로 백테스트를 새로 실행해야 한다.

## 실행과 운영

수집·실행 상태는 운영 SQLite의 `intraday_collections`, `intraday_runs`에 저장한다. 계산은 서버 전용 자식 프로세스에서 한 번에 하나씩 수행하며 고정된 요청·봉·거래일만 전달한다. 공급자 키는 전달하지 않는다. 초기 버전은 원격 에이전트의 일봉 배정 경로에 분봉을 보내지 않는다. 계산 자식 메모리는 384MiB, 제한 시간은 120초다.

인증된 사용자만 제출·조회·취소할 수 있고 작업 이력은 소유자별이다. 수집 실패를 실행 화면에도 전달한다. 사용자가 취소한 작업은 재개하지 않고 취소 뒤 도착한 결과도 저장하지 않는다. 서버 종료는 미완료 작업을 대기 상태로 남기고, 비정상 종료로 활성 상태가 남아도 다음 부팅에서 같은 작업 ID와 요청으로 자동 재개한다. 수집은 저장된 날짜를 건너뛰고, 계산 중단은 저장된 요청으로 다시 계산한다. 백테스트에 연결된 내부 수집은 기존 하위 작업을 이어가며 중복 생성하지 않는다. 보관 기간 만료·손상된 요청·연결 오류 등으로 자동 재개에 실패하면 작업 실패 사유와 알림을 남긴다. 결과에 요청·전략 버전·실행 코드 버전·데이터 revision·비용·미체결·잔여 포지션을 보존한다. 데이터가 정정되면 결과 차트에 경고하고 당시 신호·체결 마커를 현재 데이터에 겹치지 않는다.

API는 `/api/v1/intraday` 아래 `data`, `symbols`, `chart`, `collections`, `runs`로 분리한다. 일봉 요청은 구분자가 없거나 `mode=daily`인 경우만 받아 기존 요청·복제 흐름을 유지한다.

최근 시세 화면은 TradingView Lightweight Charts 5.3.0으로 캔들·거래량·OHLCV 툴팁을 표시한다. 최근 1년 데이터를 분·시간·일·주·월 단위로 조회하며, 종목명 오른쪽의 별 버튼으로 관심 종목을 등록·해제한다. 날짜를 직접 지정하거나 기간 버튼으로 바꾸고 드래그·확대로 이동한다. 수집 이력은 이 화면에 중복 표시하지 않고 작업 센터와 알림에서 확인한다. 독립 수집과 백테스트의 성공·실패는 각각 종료 후 알림을 생성한다. 백테스트 내부 수집은 부모 결과로 알리며 사용자 취소와 배포 중 일시 중단을 실패로 알리지 않는다.

수집 중에는 화면 우측 상단에 대기·수집 상태를 표시한다. 수집 현황의 주기적 갱신은 차트와 분리하여 페이지 스크롤과 차트 확대·이동 상태를 유지한다. 차트는 종목·봉 주기·조회 기간을 바꿀 때 저장된 최신 데이터를 읽으며, 수집 진행·완료나 네트워크 재연결만으로 다시 불러오지 않는다.

종목 패널 상단의 관심 종목·최근 조회 종목 탭은 한 목록만 표시하며 접기 아이콘은 패널 내부 우측 상단에 둔다. 관심 등록과 최근 조회는 운영 DB의 사용자별 `symbol_library`에 따로 저장한다(관심 최대 100개, 최근 30개). `GET/PATCH /api/v1/symbols/library[/종목코드]`는 인증된 사용자 본인의 목록만 조회·변경한다. 검색용 `symbol_directory`는 기존 로컬 종목 마스터·등록 종목에서 이름을 가져오고, 미등록 코드를 토스에서 조회해 이름을 얻으면 추가·갱신한다. 이후 한국어 이름이나 코드로 검색할 때 재사용하며 계산용 종목 마스터·과거 버전은 수정하지 않는다.

일봉·분봉 이력의 표·카드 보기 모두 전략별 펼치기·접기 버튼 왼쪽에 알림 화면과 같은 `편집` 텍스트 버튼을 둔다. 편집 중에는 버튼이 `완료`로 바뀌고 그 왼쪽에 `전체 선택`, `삭제 (선택 수)`가 나타난다. 페이지 공통 편집·선택 도구는 두지 않으며 선택과 편집 상태는 전략별로 독립적이다. 분봉 이력 삭제는 `DELETE /api/v1/intraday/history/:id`로 소유자의 종료된 기록만 제거하며, 작업 정리가 끝나지 않은 기록과 공유 Parquet 원본은 삭제하지 않는다. 기존 `DELETE /api/v1/intraday/runs/:id`는 실행 취소 기능을 유지한다. 선택·삭제 범위는 해당 전략의 현재 페이지이며 실행 중인 기록은 선택할 수 없다. 페이지 이동·편집 종료·삭제는 다른 전략의 선택을 지우지 않는다.

분봉 실행 화면은 일봉과 공통 진행 카드를 사용하고 초기 조회 중에는 스켈레톤을 표시한다. 대기·데이터 준비·계산 상태를 갱신하며 완료·실패·취소 시 로딩 표시를 종료한다. 현재 분봉 API는 진행 수치를 제공하지 않으므로 퍼센트를 추정해서 표시하지 않는다.

## 검증

기존 일봉 테스트가 보호하지 못하는 분봉 종료 시각·미래 정보·집계 누락·부분체결·만료·최소 호가·청산 실패, Parquet 왕복·정정·보관 경계, 인증·소유권·취소·수집 실패 전파에 작은 회귀 사례를 추가한다. UI E2E는 모바일·데스크톱의 경로, 오류 종료, 신호·체결 표시를 확인한다. 신규 검증은 기존 EMA 사례가 다루지 못하는 세 전략의 인과관계·당일 초기화·준비 경계와 실제 주문 모형 연결, UI 전략 선택·파라미터 제출·복제 보존 및 제목 옆 선택기의 줄바꿈 방지를 보호한다. 실제 토스 과거 제공 기간과 시장 구성은 운영 자격 증명으로 조회해야 확인할 수 있다.
