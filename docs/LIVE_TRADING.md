# 실매매 운영

매매 화면은 기존 토스증권 서버 자격 증명을 사용한다. 주문·체결 어댑터 기준은 [토스 OpenAPI](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json) 1.2.28이다. API 키는 서버의 `config.env`에서 관리한다.

## 모의투자 프리셋

매매 페이지에서 **새 모의투자**를 선택하고 전략과 초기 모의자금을 저장한다. 이름을 비우면 전략 이름을 사용한다. 각 프리셋은 별도의 모의계좌를 가지며 저장 직후 자동매매는 꺼져 있다. 여러 계좌를 동시에 켤 수 있고, 각 계좌가 자기 현금·보유 수량·체결 이력과 손실 한도를 사용한다. 자동매매 중에도 표시 이름을 바꿀 수 있다.

대시보드의 **모의투자** 목록은 활성, 꺼짐, 문제 순으로 표시하며 같은 상태에서는 먼저 만든 항목이 위에 온다. 항목을 누르면 해당 계좌의 매매 페이지로 이동한다. 전략을 제거한 계좌의 잔고와 이력은 매매 페이지의 계좌 선택에서 다시 확인할 수 있다. 기존 단일 계좌의 데이터는 기본 계좌로 이어진다.

일봉·분봉 백테스트 결과의 **이 설정으로 매매 준비**를 누르면 원본 설정으로 새 모의계좌가 생성되고 매매 설정 창이 열린다. 창을 닫으면 계좌는 OFF 상태로 남는다.

자동매매 켜기·끄기를 확인하면 서버가 전환 작업을 접수한다. 매매 화면을 떠나거나 브라우저를 닫아도 처리하며, 작업 목록에서 해당 계좌의 진행·완료·실패 사유를 확인할 수 있다. 끄기는 신규 주문을 즉시 차단하고 미체결 주문 대조를 마쳐야 완료된다. 켜기에 필요한 데이터 복구가 끝나면 사용자가 다시 활성화를 확인한다.

## 시작과 지원 범위

1. `pnpm build`로 서버·웹·고정 전략 번들을 함께 빌드한다. 일반 서버 이미지 빌드에도 포함된다.
2. 운영 설정의 `TOSS_CLIENT_ID`, `TOSS_CLIENT_SECRET`, 공급자 접근 권한 및 허용 IP를 확인한다. `LIVE_TRADING_ENABLED=true`를 설정하고 서버 설정을 적용한다.
3. 매매 → 계좌 새로고침 → 운용 계좌 선택 → 전략·파라미터·유니버스·운용 한도 저장 순서로 등록한다. 완료 백테스트에서 설정을 가져올 수도 있다.
4. 활성화 검토에서 계좌와 한도를 확인한다. 입력 자료가 부족하면 준비 진행률·원인을 표시한다. 수집 완료 후 다시 시도해 검증을 통과해야 활성화된다. 호환되는 최신 전략은 활성화할 때 적용하고 그 요구사항으로 검증한다.

초기 지원 범위는 국내 원화 주식, 일봉 전략, 정수 주식 수량, 지정가 DAY 주문이다. 해외 보유·주문이 함께 있는 계좌는 대조를 중단하므로 국내 운용 전용 계좌를 사용한다. 건당 주문은 1억원 미만이다. 일일 손실 한도는 신규 주문 중지와 미체결 취소 기준이며 자동 전량 청산 기능이 아니다.

공식 개장일 09:00~09:10 KST에 전일 확정 KRX 봉으로 판단한다. 활성화 시점까지의 봉은 지표 준비에 쓰고 다음 새 봉부터 주문한다. 창을 놓친 신호는 장중에 소급 주문하지 않는다. 백테스트의 다음 봉 시가 체결과 실제 지정가 체결은 가격·수량·부분 체결이 다를 수 있다. 시세 또는 잔고가 30초 이상 오래됐거나 확인되지 않은 입력이 있으면 전송하지 않는다.

일봉 백테스트 엔진 2.14부터 매매와 같은 종목별 진입 자격과 동시 매수 우선순위를 사용한다. 예를 들어 200봉을 요구하는 설정에서 상장 후 172봉만 존재하면 해당 종목의 신규 매수만 보류한다. 다른 종목의 판단과 보유분의 청산은 계속한다. 상장 후 실제 개장일의 가격이 누락됐고 거래정지 근거도 없으면 가격 수집을 요청한다. 준비 결과와 매매 활동에는 보류 종목과 확보한 봉 수가 표시된다.

전략에 배정한 현금에 실현손익과 수수료·세금을 반영하고, 현재 보유분을 평가해 주문 수량을 계산한다. 백테스트에서 가져온 모의매매 설정은 원본의 수수료·슬리피지 모델을 사용한다. 기존 설정에 비용 정보가 없으면 서버 시작 시 원본에서 복원한다. 원본이 삭제됐거나 읽을 수 없으면 기존 모의 비용을 유지하고 활동 기록에 경고를 남긴다. 모의 주문에는 직전 확정 봉 거래량 한도를 적용하고, 주문 직전 시세·증권사 매수 가능 금액·매도 가능 수량·건당 주문 한도와 지정가 조건을 재확인한다. 장 마감 뒤 알려지는 당일 총거래량은 백테스트의 체결 상한으로만 사용한다. 보유 종목의 분할·상장폐지로 실제 수량이나 정산 대금을 대조해야 할 때는 주문을 중지한다.

## 중지·교체

비활성화 요청 직후 신규 주문을 막고 접수된 주문의 잔량을 취소한다. 비동기 취소는 `중지 중`에서 재확인하며, 취소 실패는 15~60초 간격으로 재시도한다. 그 사이 이미 접수된 주문이 체결될 수 있어 최종 대조 전에는 비활성 완료로 표시하지 않는다. 비활성 완료 후에는 매수·매도·자동 손절이 없고 포지션을 그대로 유지한다.

기존 일봉 계좌와 분봉 모의계좌는 호환되는 전략·실행 버전을 활성화할 때와 활성 상태의 다음 실행 전에 자동으로 적용한다. 일봉 계좌는 비활성 상태에서 **전략 버전 업데이트**로 현재 버전과 적용할 버전, 파라미터를 확인하고 수동으로 적용할 수도 있다. 설정과 파라미터의 수동 변경은 비활성 상태에서만 가능하다. 다른 전략을 등록하려면 기존 전략을 먼저 제거한다. 제거는 포지션 청산을 수행하지 않으며, 남은 포지션은 토스에서 직접 관리한다. 기존 수동 보유 종목에는 자동 주문하지 않는다. 관리 중인 종목을 외부에서 거래하거나 분할 등으로 수량이 바뀌면 수량 대조 오류로 중지한다.

버전 전환은 계좌의 현금·보유 수량과 주문 이력을 보존한다. 일봉은 미체결 주문을 대조한 뒤 마지막 판단 봉까지 새 전략을 준비하고, 분봉은 마지막 처리 봉과 부분 체결 잔량을 이어간다. 기존 설정이나 실행 상태를 해석할 수 없으면 활성 상태에서 새 주문을 보류하고 원인을 활동 기록에 남긴 뒤 재시도한다.

## 오류·복구와 기록

활성 모의계좌는 서버 재시작 시 원장을 대조한 뒤 실행을 이어간다. 실계좌의 실행기가 재시작되거나 교체된 경우에는 잔고와 주문을 대조하고 직접 다시 활성화한다. 오류 상태에서도 접수된 미체결의 취소·체결 대조는 계속한다. 계좌 새로고침으로 원인을 확인한 뒤 비활성 완료 → 활성화 검토를 거친다. 중단 구간은 누락 없이 재생하되 과거 신호는 주문하지 않는다. 5년을 넘긴 체크포인트와 거래 봉을 확인할 수 없는 구간은 명시적으로 차단한다.

접수 응답을 잃은 주문은 `접수 미확인`으로 남긴다. 토스 주문 내역의 종목·방향·수량·가격·시각을 대조해 주문 번호를 연결한다. 10분이 지나고 일치 가능 주문이 없을 때만 미접수로 확인할 수 있다. 이 조작은 주문을 재전송하지 않는다. 수동 확인 없이 전략을 제거하거나 교체할 수 없다.

수익은 현재 전략의 실제 확인된 체결과 보유 평가액으로 추정하며 계좌 전체 평가손익과 구분한다. 수수료·세금이 미확인인 체결은 확정하지 않고, 최근 7일 종료 주문의 후속 정산 비용을 5분마다 대조한다. 더 늦은 정정이나 동일 수량의 체결 가격 변경은 증권사 원장과 별도 대조가 필요하다. 예산을 변경한 경우 단일 수익률 기준이 성립하지 않아 수익률을 표시하지 않을 수 있다.

운영 DB의 전략·주문·이벤트와 데이터 볼륨의 `trading-artifacts`를 함께 백업한다. 사용할 전략 번들의 무결성을 확인한다. 이 기능의 자동 테스트는 대체 증권사와 임시 SQLite를 사용하며, 운영 계좌의 주문·체결 검증을 대신하지 않는다.
